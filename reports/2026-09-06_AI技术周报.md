### 1. Comparative performance of contemporary multimodal large language models in retinal imaging question answering

- **日期 / 来源**：PubMed 索引 2026-09-04（电子出版 2026-08-20）；*Frontiers in Medicine*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42694118/ · https://doi.org/10.3389/fmed.2026.1934968
- **相关度**：眼科多模态 LLM（非 Agent；本周最接近「通用模型直接读视网膜图」的对照）
- **摘要**：从 OCTCases 78 个视网膜病例抽出 226 道选择题（151 看图、75 不看图），评 ChatGPT-5.5 Instant / Thinking、Grok 4、Gemini 3、DeepSeek V4、Kimi 2.5；答案与三名视网膜专科医师核对过的题库对照。总体正确率 **59.3–77.4%**，最高为 ChatGPT-5.5 Thinking，其次 Gemini 3 与 Instant；DeepSeek V4 最低。六家都是**不看图明显强于看图**；看图子集上 Gemini 3 最高。多数表决在 182/226 题上给出组答案，正确率 **89.6%**；全错的题全部是看图题。界面延迟与对错无关。作者支持继续做基准，临床与教学须专科监督。
- **单篇小结**：对照 8/30 *Retina* 四家 MLLM 读 800 张眼底（ChatGPT-4o 75%，其余 14–18%）：骨干换代后总分上来了，但失败仍集中在像素。多数表决提高共识题正确率，正好是 Agent 该加的**跨工具/跨骨干一致性门**——六家打架就转人工，而不是再写一段更长的解释。

### 2. Evaluation of a cornea-specialized large language model for diagnostic and management accuracy in complex corneal cases

- **日期 / 来源**：2026-09-02；*International Ophthalmology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42684491/ · https://doi.org/10.1007/s10792-026-04232-2
- **相关度**：眼科专科 RAG（非工具编排 Agent；对照「认病 vs 选下一步」）
- **摘要**：前瞻、随机、掩蔽：3 名角膜进修医师各评 39 例真实复杂角膜病例，条件为独立 / 通用 GPT-4o 辅助 / 角膜专科 GPT-4o（把 200+ 篇公开 Wikipedia 嵌入 RAG），每例最多问 3 次。开放诊断对照专家金标准：独立 48.7% / 20.5% / 38.5%，通用 GPT-4o 升至 69.2% / 46.2% / 59.0%，专科 RAG 再至 **71.8% / 48.7% / 74.4%**（相对独立均 *p*<0.01）。下一步处置（选择题）则不稳定：第 3 名从 59.0% 升到 71.8%，第 1 名维持 82.1%，第 2 名从 87.2% **掉到 64.1%**。作者认为专科 RAG 主要帮低基线诊断，处置任务应改开放题，并怀疑更小、更干净的检索库可能更好。
- **单篇小结**：与 8/17 近视 LLM、8/23 近视专科评测、8/30 青光眼术式评测同一失败模式——「认病」能抬，「选处置」可能被检索噪声拉低。GAO 把 AAO 编成 70 行表再 SFT，比「把整本 Wikipedia 丢进 RAG」更可审计。角膜问询 Agent 应先对规则表，再强制专科签发。

### 3. Vibe coding for ophthalmologists

- **日期 / 来源**：2026-09-03；*Current Opinion in Ophthalmology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42687662/ · https://doi.org/10.1097/ICU.0000000000001250
- **相关度**：眼科相邻（评论「用 LLM agent 写代码」，不是临床诊断 Agent）
- **摘要**：综述「vibe coding」：用自然语言描述功能，与 LLM agent 协作生成含认证与数据库的可运行应用。作者认为眼科医师可用来做流程、科研与教学原型，尤其适合商业厂商不愿做的亚专科小工具；低风险、不直接改临床决策的场景，医师可在一定条件下自行上线，其余须走机构治理。
- **单篇小结**：本窗口唯一在眼科期刊标题语境里写到 **LLM agent** 的条目，对象是写软件而不是看图/分诊。可与本周 Fable 5.1 / Astra 对照：旗舰更会写院内小工具，但生产环境仍要把 Skill、域名白名单和审计日志写成一等公民，不能把「能跑的原型」当成已验证的临床系统。

### 4. Co-Annotator: Expert-Distilled ViT and VLM for Visual and Documentation Guidance in Age-Related Macular Degeneration

- **日期 / 来源**：2026-08-31 提交 arXiv；`cs.AI`
- **链接**：https://arxiv.org/abs/2608.30352
- **相关度**：眼科人机协同工具（非自主 Agent；给 AMD OCT 读图/写标志物提供注视与文档引导）
- **摘要**：临床 AI 常只优化预测，不管医师「看哪里、写什么」。Co-Annotator 把专家注视与口述蒸馏成两块：注视对齐 ViT 产出兴趣区（AOI），本体约束 VLM 预填可编辑的视网膜 OCT 生物标志物摘要。先用专家注视/口述（US1）训练，再在住院医师对照（US2）上部署：各模态单独安全有益；AOI 引导在撤掉后仍有知觉效率残留，VLM 引导使标志物文档量翻倍以上。
- **单篇小结**：这是「工具输出写进证据黑板」的弱 Agent 形态——模型只提议看区和草稿，医师改。接到 AgentEYE / EyeAgent 时，应把 AOI 与标志物预填做成可开关工具，而不是让规划器直接写诊断。也提醒：人机协同增益可以发生在**文档完整性**，而不只是切片准确率。

### 5. Benchmarking Vision Encoders for Image Classification in Ophthalmology

- **日期 / 来源**：PubMed 索引 2026-09-02；*Computational and Structural Biotechnology Journal*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42682772/ · https://doi.org/10.34133/csbj.0178
- **相关度**：眼科视觉编码器选型（非 Agent；给工具槽提供骨干对照）
- **摘要**：34 个预训练编码器 × 39 个分类任务，覆盖眼底照相、OCT、扫描激光检眼镜与超广角；统一比较冻结特征、线性探测与端到端微调。眼科迁移高度任务依赖，没有单一编码器通吃；**视网膜专科预训练并不自动占优**，若干自然图像与跨域医学编码器持平或更好，病理预训练的 Virchow 总体最强。
- **单篇小结**：`2608.07651` 用 SwinV2-Tiny 分类 + SegFormer-B0 分割。复现青光眼/DR 工具编排时，应把「编码器 × 冻结/LoRA/全微调」写进工具卡，而不是默认 RETFound。病理编码器能赢，也说明眼科 Agent 的看图工具可以从邻近专科基础模型里借，而不必等眼科专用再训一版。

### 6. Improving Generalization of Deep Learning for Glaucoma Classification Under Real-World Domain Shift via Unsupervised Domain Adaptation

- **日期 / 来源**：2026-09-01；*Translational Vision Science & Technology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42684106/ · https://doi.org/10.1167/tvst.15.9.3
- **相关度**：眼科专用 CV（可替换进青光眼 Agent 的分类槽；强调域移）
- **摘要**：对抗式无监督域适应：有标签源域适配无标签目标域，同时优化分类与域判别。6906 张眼底图（UIC 711 张全图/盘沿裁剪 + RIMONE-DL / REFUGE / LAG）。极端域移上，相对标准深度学习准确率最高 +40.0%，AUC 最高 +59.8%；显著图显示 UDA 与标准模型用的特征不同。
- **单篇小结**：AgentEYE 作者自己点出外部分布漂移；`2608.07651` 只有 ORIGA / RIM-ONE-v3 各 100 张。分类工具上线前应先报源→目标 UDA 数字，而不是只报域内准确率。盘沿裁剪 vs 全图也接到上周 EVADE：两视图打架就弃权。

### 7. Modular multi-task deep learning framework for prediction of treatment initiation in neovascular AMD（MANTIS）

- **日期 / 来源**：本窗口 PubMed 可见；*British Journal of Ophthalmology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42680556/ · https://doi.org/10.1136/bjo-2025-328327
- **相关度**：眼科专用 CV / 治疗时点（固定流水线，**不是** LLM Agent）
- **摘要**：用连续 ≥3 次访视的 OCT + 视力，自动判断何时启动抗 VEGF。任务一：识别需要治疗；任务二：估计 Bruch 膜到外丛状层的外层视网膜厚度（ORT）。CNN 抽 OCT 特征，两个 LSTM 分数据集训练。122 人 / 207 眼。任务一对齐临床启动决策：AUROC 0.73（95% CI 0.59–0.87），准确率 0.87，特异度 0.92，灵敏度 0.69；任务二 NMAE 0.12。作者定位为帮助更早干预以保住视力。
- **单篇小结**：FOCUS（8/23）证明固定 OCT 流水线已经很强。MANTIS 补的是**时间序列启动治疗**，不是诊断病名。接到 AMD Agent 时应同时暴露 AUROC、灵敏度与「对齐的是本院启动习惯、不是独立金标准」三行，防止规划器把输出写成注射指征。

### 8. Robust retinal biometrics for patient identity verification and retrieval across age and imaging devices

- **日期 / 来源**：2026-08-31；arXiv `cs.CV`
- **链接**：https://arxiv.org/abs/2608.31094
- **相关度**：眼科身份工具（可作纵向随访 Agent 的身份门）
- **摘要**：在 Rotterdam Study 227,004 张图、21,851 个患者–眼身份上训练 512 维度量学习编码器（ConvNeXtV2 + ArcFace + triplet），跨设备、最长随访 32.6 年；外推 UK Biobank 与 AREDS。用模型筛身份不一致后再人工裁决，发现错误分配比例分别为 0.588% / 0.259% / 0.164%。
- **单篇小结**：上周 OCT 反事实编辑已经证明「改完不像同一个人」。纵向青光眼/注射随访 Agent 应在读第二张图之前先过身份门，否则时间 Agent 比较的是另一个人。也可反过来审计公共数据集标签——周报引用 ORIGA / AREDS 数字时，要意识到身份噪声不是零。

### 9. ARCOS: Zero-shot Boundary Localization for Corneal Layer Segmentation Across Optical Coherence Tomography Devices

- **日期 / 来源**：2026-09-03；arXiv `cs.CV`
- **链接**：https://arxiv.org/abs/2609.03668
- **相关度**：眼科专用 CV 工具（可替换进角膜/屈光 Agent 的分层槽）
- **摘要**：角膜 OCT 界面薄、斑点噪声大、设备间差异大。ARCOS 不做常规区域分类，而在原分辨率重叠切片上预测主要界面的边界热图，再拼接成连续、解剖有序的分层。定位为零样本跨设备边界定位，服务于厚度与术后形态定量。
- **单篇小结**：角膜 Agent 缺的往往不是再写一段 KLEx 指南（8/30 PMID 42668902），而是可跨设备的厚度工具。与条目 2 对照：RAG 抬诊断，分层工具抬「下一步能不能算而不是猜」。

### 10. OphthoChat: A HIPAA-Compliant Chatbot for Ophthalmic EMR Querying

- **日期 / 来源**：*Ophthalmology Science* 2026 年 9 月期；电子出版早于本窗口（约 2026-07-06），**本周作为当期可见条目核对**
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42598632/ · https://doi.org/10.1016/j.xops.2026.101315
- **相关度**：眼科 EHR RAG 聊天机器人（有检索，但不是多工具临床 Agent）
- **摘要**：HIPAA 合规的自然语言病历查询。500 例成人（250 湿性 AMD 注射、250 白内障），>50,000 条病历/手术/影像/OCR 扫描向量化；GPT-4o RAG 答 1000 条按复杂度分层的医师查询。总体准确率 **96%**，灵敏度 93%，特异度 97%；中位 35 秒，约比手工翻病历快 11 倍。正确回答中 97% 引用行匹配金标准。作者强调可追溯，下一步是 EMR 嵌入与亚专科扩展。
- **单篇小结**：电子出版早于本窗口，不计入「本周新的眼科 Agent」。价值是把「能聊天」写成**可点开出处的病历工具**。与 AgentEYE「检索换审计」同构：准确率已经高，缺的是影像工具、急症门和人群级监测。

### 11. Agentic AI in Radiology: Fundamentals, Drivers, and Gaps

- **日期 / 来源**：2026-09-03；*Academic Radiology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42692874/ · https://doi.org/10.1016/j.acra.2026.08.055
- **相关度**：方法可迁移（把 Agent 写成多工具 + 纵向数据的编排层；放射是眼科的近邻）
- **摘要**：叙事综述：当前放射 AI 是窄任务算法，Agentic AI 试图用编排层整合多工具、多数据源与工作流，吃多模态与纵向信息，动态协调组件。文章整理编排策略、工具接入、多模态处理与系统形态，并讨论驱动因素与临床落地障碍。
- **单篇小结**：清单可直接对到眼底/OCT：质控、分类、分割、前后片、指南检索、报告对账。不要把「有一个 LLM」写成已经 agentic；缺编排、缺纵向、缺工具注册，就还是上周那类纯 MLLM。同日牙科评论（PMID 42691769）与心血管综述（PMID 42688813）把同一故事写成「辅助→自主」，治理口径接上周「委托 / 相关失败」。

### 12. PlanningCopilot: An agentic framework integrating ESAPI modules for autonomous treatment planning in lung radiotherapy

- **日期 / 来源**：2026-09 期；*Medical Physics*（本窗口索引）
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42682183/ · https://doi.org/10.1002/mp.70665
- **相关度**：方法可迁移（真接到治疗计划系统的多 Agent；不是只出文本建议）
- **摘要**：规则自动化确定、知识计划给统计剂量，但常要手改；LLM 有推理，缺的是在 TPS 里执行。PlanningCopilot 用四个 GPT-4.1 专科 Agent，经已验证的 Eclipse Scripting API 模块 PlanAct（含 KBP 初始化）**真改计划**，在局部晚期 NSCLC 上评临床可接受率，并探索自学习能否再抬。目标是少人工干预地出可接受计划。
- **单篇小结**：这是本周「Agent 必须能调用院内 API」写得最硬的一篇。眼科对标不是让模型写一段「建议抗 VEGF」，而是经 PACS/EMR/治疗设备接口改预约、出结构化医嘱草稿，并且每步可回放。没有 ESAPI 这类门，Agent 就停在聊天框。

### 13. Transforming large language models into medical specialists via knowledge injection

- **日期 / 来源**：2026-09-04；*Cell Reports Medicine*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42697202/ · https://doi.org/10.1016/j.xcrm.2026.103020
- **相关度**：方法可迁移（知识注入框架，并推到 agentic 协作决策；与 AgentEYE 同刊）
- **摘要**：综述把通用 LLM 变成可信医学专科的三条注入：（1）静态嵌入内化生物医学基础；（2）行为对齐强制安全与可核验诊断逻辑；（3）动态注入（如 RAG）做实时证据接地；另加多模态感知作为输入扩展。再讨论如何把这三条编排成**自主、协作的临床决策 Agent**，以及校准、算力、报告规范与安全协议。
- **单篇小结**：AgentEYE 已经示范「工具定正确率、检索定审计」。这篇把「知识怎么进模型」拆成可版本管理的三层，正好接 Claude Skills / Guideline-as-Oracle：规则表走静态+行为对齐，指南 PDF 走动态 RAG，不要把三层糊进同一段系统提示。

### 14. ClinTraceBench: Source-Verifiable Longitudinal Clinical Reasoning over EHR-Derived Dialogues

- **日期 / 来源**：2026-09-01；arXiv `cs.CL`
- **链接**：https://arxiv.org/abs/2609.01111
- **相关度**：方法可迁移（纵向病历 / agentic memory 评测；可对青光眼与注射随访）
- **摘要**：385 段经核实的 MIMIC-IV 对话，事件 ID 可追溯；九类任务，L0–L4 确定性校验 + L5 人工（一致率 98.92%）。八种病史表示（无上下文、仅末次、全文、稠密检索、两种压缩、Mem0 / A-Mem）× 四个骨干，6,271 题、200,672 次预测。关键负结果：在构造前注入归因句后，Mem0 / A-Mem / LLM 摘要对注入阳性的回收仅 **0–5.3%**（关系丢失）；压缩策略在多访视趋势与跨患者比较上交「聚合税」；盲→全文差距 +29.8～+62.7 个百分点。Pareto 上 Haiku 全文（$25.76）压过 Sonnet（$106.21）。
- **单篇小结**：青光眼 RNFL / AMD 注射史最怕「摘要把时间顺序抹平」。不要默认上 agentic memory；随访 Agent 应保存带时间戳的测量事件，检索时按事件 ID 引用，而不是让记忆模块再写一段故事。

### 15. Examining the Vulnerability of Multi-Agent Medical Systems to Human Interventions for Clinical Reasoning

- **日期 / 来源**：2026-09-02；arXiv `cs.AI`
- **链接**：https://arxiv.org/abs/2609.02191
- **相关度**：方法可迁移（多智能体诊断的人机干预点；可对电话分诊/联合读片）
- **摘要**：在多智能体医患对话里定义「故障点」——推理最容易被外部影响的时刻。MedQA 模拟对话中，正确干预最多把基线诊断准确率抬 **40%**，错误或偏置干预最多降 6%，并增加诊断漂移与不确定。行为上出现早闭与被误导线索带偏，与真实临床认知偏倚同构。
- **单篇小结**：GAO 式分诊不该做成全自动。应在急症定级、缺关键变量、工具输出冲突时强制弹出故障点，让护士/医师改一句；同时也要防「带偏的人」把同一错误过程写进全院（上周相关失败评论）。

### 16. Counterfactual Fairness Audits of Multi-Step Clinical LLM Agents Require a Measured Per-Action Instability Floor

- **日期 / 来源**：2026-09-02；arXiv `cs.CL`
- **链接**：https://arxiv.org/abs/2609.03221
- **相关度**：方法可迁移 / 治理（临床 Agent 公平审计的测量地板）
- **摘要**：反事实公平审计常报 flip rate（只改人口学描述符时动作是否变）。作者证明该数字单独不可读：同一叙事、同一描述符重跑 10 次，16 个情景上 **8.7%** 的结果–情景单元动作会变；动作间不稳定相差约 8 倍（ICU 升级 0.022，管制药物提醒 0.179）。第二模型地板 6.7%，六动作排序几乎相同（Spearman 0.94）。5 次多数表决去掉 39% 的地板后变平。FairMedAgent 只统计「已发表规则承认且医师裁决过」的动作翻转；带裁决尚在进行，**本文不声称发现人群差异**。
- **单篇小结**：眼科筛查 Agent 若要报「对某一人群更激进」，必须先报同一患者重跑的动作级 κ / flip 地板。`2608.07651` 已证明纯 LLM 跑间 κ 可到 −0.01；没有地板的公平数字不能当歧视证据，也不能当「已经公平」的免责声明。

### 17. Accountable AI with Grounded, Faithful, Consistent, Actionable Rationales（VERDICT）

- **日期 / 来源**：2026-09-03；arXiv `cs.CL`
- **链接**：https://arxiv.org/abs/2609.03366
- **相关度**：方法可迁移（把临床匹配做成 SMT 可核验决策，而不是流畅理由）
- **摘要**：问责需要：已核实理由、显式假设、政策一致、以及「改哪条会改结论」的枢轴条件。作者用自忠实性测试：改枢轴条件应改决策。LLM 试验匹配准确率尚可，但政策不一致、理由不忠实。VERDICT 把任务、约束与政策译成 SMT，用求解器出决策，从而**政策一致由构造保证**。在 SIGIR 2016 派生集与 TREC 2021 上，决策准确率高于 LLM-only 与神经符号基线，政策一致率完美，理由更受临床偏好，反事实自忠实性更好。
- **单篇小结**：眼科入组/适应证（抗 VEGF、小梁网手术、KLEx）与试验匹配同构：该不该进，应由规则求解器判，LLM 只负责把病历填进槽。这比「让模型写一段符合指南」更接近 GAO 的规则表，也补上周 Quicker 评论要的可核证据包。

### 18. Claude Fable 5.1 / Mythos 5.1：长程 agentic coding 与科研

- **日期 / 来源**：官方博文 / 平台说明 2026-09-01
- **链接**：https://www.anthropic.com/claude-fable-and-mythos-5-1 · https://platform.claude.com/docs/en/release-notes/overview
- **相关度**：方法可迁移（通用 Agent 骨干；科研与计算机使用）
- **摘要**：Fable 5.1 与 Mythos 5.1 为同一模型、不同护栏；Fable 普遍可用，Mythos 仅受信生命科学/网络项目。默认 1M 上下文、128k 最大输出、始终自适应 thinking；标价仍 $10 / $50 per MTok，**cache read 降至 $0.25**，官方称典型工作负载约便宜 25%，高度 agentic 可到约 45%。公开表：Terminal-Bench-Science 0.1 上 Fable 5.1 **52.6%**（Fable 5 为 24.7%）；Terminal-Bench 4.0 为 55.8%（Mythos 60.9%）；OSWorld 2.0 部分 77.9% / 严格 41.7%；AutomationBench 31.4%。Mythos 在蛋白设计上把设计交给外部实验，12 个靶点命中率近 50%。企业前沿护栏（EFS）计划把数据放在客户云上。
- **单篇小结**：对眼科的意义是「长程科研 Agent + 便宜缓存」而不是「让 Claude 看眼底」。BaT 式写实验、指南 PDF 对账、规则表迭代可以换 5.1；临床决策仍走专用工具。生命科学能力被拆到 Mythos，说明院内部署不要默认打开生物学宽松档。

### 20. GPT-6 Astra：计算机使用与科学工作流旗舰

- **日期 / 来源**：2026-09-03；OpenAI
