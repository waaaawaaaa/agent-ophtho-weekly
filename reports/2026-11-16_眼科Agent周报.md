### 1. RetinaGuard: Risk-Controlled Agentic Triage for Multi-Disease Retinal Screening

- **日期 / 来源**：arXiv **2026-11-07**（`2611.10689v1`）。FAST-NUCES（Sohaib Sulman / Muhammad Atif Saeed / Akhtar Jamil）+ Istinye University + Saarland / DFKI（Roland Aydin）
- **链接**：https://arxiv.org/abs/2611.10689 · https://arxiv.org/pdf/2611.10689 · HTML：https://arxiv.org/html/2611.10689v1
- **相关度**：**直接相关（本周主条目；提交 11/07，落在上周期与本周期之间的漏检周）**——多病种眼底筛查上的风险受控 Agentic 分诊；诊断骨干是 RETFound，**不是** LLM 编排器
- **摘要**：筛查项目要决定哪一次自动决策可以不经人工复查。RetinaGuard 用质量、诊断、不确定性、校验和解释 Agent 为每张眼底图收集证据，学得失败预测器估计该决策不安全的概率，辅助工具只在期望信息价值超过其计算成本时调用，接受阈由 conformal risk control 认证。数据：RFMiD 官方划分（训练 1,536 / 校准 384 / 验证 640 / 测试 640；25 个标签），ODIR-5K 只做外验，IDRiD 分割集只验证解释。不安全定义为筛查标签错 **或** 漏掉任一已存在疾病；假阳性不算不安全。RFMiD 测试集上原配方微调的 RETFound macro-AUROC **0.925**（筛查 0.974），保守分阶段微调 **0.896**；无转诊时不安全率分别为 35.8%（229/640）和 43.8%（280/640）。弱模型上校验分歧给失败预测 AUROC 再加 **0.058**（0.790→0.848），20% 预算相对最低置信度 EDR 增益 11.1 个百分点（抓住 119/280 vs 88），名义 α=5% 时接受 37.0% vs 10.3%。强模型上校验增量只有 0.004，20% 预算 EDR 增益 6.1 个百分点且 Holm 后不显著，认证覆盖 37.7% vs 最低置信度 33.1% / 校准不确定性 38.4%。VoI 门控在弱/强模型上分别只调校验器 **24.8% / 7.7%** 的病例，相对全开工具省约 30% 计算（345 ms→246 ms / 图）。质量 Agent 把合成退化下最差不安全率从 60.2%→7.7%（弱）和 53.1%→28.0%（强）。ODIR-5K 不重训：筛查 AUROC 掉到 0.663，策略转诊 87.4%，实现边缘不安全率 6.8% 超过 5% 目标。IDRiD 上 ConvNeXt-B 的 Grad-CAM 指向游戏 0.864，RETFound 的 attention rollout **不定位**（0.123）。
- **单篇小结**：这是对 GAO-Triage / 黄斑裂孔工作流「Agent 层默认有增益」的定量刹车——**校验 Agent 只在主模型弱、且自己还不知道自己错的时候才值钱。** 接到糖网 / 多病种眼底筛查 Agent 时应固定四列：主模型 macro-AUROC、相对最低置信度的 EDR@20%、α=5% 认证覆盖、外验人群上的实现不安全率。不要把「Agentic」写成已经比不确定性转诊赢了——强 RETFound 上 Holm 后对 B2 零个预算显著。报告 Agent 是模板、对动作无权限，这点应抄到黄斑裂孔报告槽：LLM 不得改诊断。Conformal 保证在 ODIR-5K 失效，禁止把 RFMiD 认证覆盖写成可部署安全门。注意力图不得当临床证据。预印本未经同行评议；未见公开代码。

### 2. EyeAgent: An Agentic AI System for Multimodal Clinical Decision Support in Ophthalmology（v3）

- **日期 / 来源**：arXiv `2511.09394v3`，修订 **2026-11-01**（v1 2025-11-12，v2 2026-03-11）。Comments：**Accepted for publication in NEJM AI**。中山眼科 / 港理工 何明光、Danli Shi 等
- **链接**：https://arxiv.org/abs/2511.09394 · https://doi.org/10.48550/arXiv.2511.09394 · 试验：https://clinicaltrials.gov/study/NCT07401459
- **相关度**：**直接相关（上窗口漏检的版本 bump；工具编排眼科 Agent，不是本周新系统）**
- **摘要**：v3 把系统写成三层：54 个任务特异 EyeTools、32 项临床技能、可换骨干的模块化 LLM 推理核。组件级评估在合计 871,862 样本的留出划分上测新模型。系统级包括工作流广度示例、200 例专家评分，以及 11 中心 27 名眼科医师的探索性读片（无辅助 vs EyeAgent 辅助）。示例病例相对 GPT-5.5 在病灶定量、跨模态合成和不确定性报告上有任务特异优势。专家评分：技能选择 F1 **0.84**，六个临床维可接受或更好 82.7–92.0%。读片：诊断准确率 72.8%→**91.9%**（差 19.1 pp，95% CI 13.6–24.7，Holm *P*<0.001），报告完整度 55.8%→75.6%（差 19.8 pp，14.8–24.7）。作者写明更广的真实世界效力与可推广性需要前瞻和跨人群验证。NCT07401459 仍为 Not yet recruiting，last update 2026-02-23，登记主完成日 2026-10-31 已过。
- **单篇小结**：数字比仓库里一直引用的 v1 海报口径（53 工具、总体 80.79%、辅助 +18.51%）更新了一档，**但 RCT 状态没有动。** 接到「已经进 *NEJM AI*」的采购话术时应要求：读片是探索性不是登记试验、技能选择 F1 和诊断准确率分栏、以及 NCT 为何主完成日过后仍未入组。不要把 v3 写成新的直接相关系统——翻转条件由条目 1 完成，本条是漏检补记。

### 3. Auto-GlaKG: Automated Biomarker Reasoning for Explainable Glaucoma Detection

- **日期 / 来源**：arXiv **2026-11-08**（`2611.11258v1`）。Cheng Huang / Zeyu Han / Yian Hu / Yaopeng Ding / Jingxi Qiu / Yadi Liu
- **链接**：https://arxiv.org/abs/2611.11258
- **相关度**：眼科相邻（青光眼眼底 → biomarker → 固定规则知识图谱；**不是** 工具编排或 LLM Agent）
- **摘要**：可解释青光眼检测需要把眼底图、有临床意义的 biomarker 和诊断预测连起来。知识图谱能提供结构，但用**标注** biomarker 测到的性能，不能代表只给图像时的性能。Auto-GlaKG 用 ResNet50 预测杯盘比（CDR）和六个形态学征象，再用固定临床先验规则把带符号的规则贡献聚成青光眼分数。689 张眼底、分层且 group-aware 的五折：合并 AUC **0.951**（95% CI 0.931–0.969），灵敏度 0.970，特异度 0.779。配对的图像分类器 AUC 同样是 0.951，规则阶段每张图只加 0.2 ms。把预测 CDR 换成标注 CDR，折均 AUC 从 0.953 升到 **0.995**。作者把 CDR 估计写成优先用独立测量 biomarker 验证的缺口。
- **单篇小结**：位置正好接在条目 1 之后——**图谱规则能把已经预测对的征象写清楚，并不能把主模型变强。** 接到青光眼眼底 Agent 的「可解释」槽时应要求：图像-only 与标注-CDR 分栏（本条差 0.042 AUC），以及规则是不是固定先验而不是 LLM 现编。不是工具 Agent，不翻转本周口径。提交日 11/08，落在漏检周。

### 4. Implications of Image-Level Duplication in Public Glaucoma Datasets

- **日期 / 来源**：2026-11-12；*JAMA Ophthalmology*。武藏野大学（Endo / Fukuhara / Oka）
- **链接**：https://doi.org/10.1001/jamaophthalmol.2026.5155 · https://pubmed.ncbi.nlm.nih.gov/43018943/
- **相关度**：眼科相邻 / 数据治理（公开青光眼 OCT 集不是独立队列；**不是** Agent，但直接打在青光眼 Agent 的外验栏）
- **摘要**：青光眼 AI 常把少数来自同一实验室的公开集当「独立外验」。作者审计 Harvard-GDP（1,000 眼）、Harvard-GF（3,300 眼）、Harvard-FairVision（10,000 眼）。Harvard-GF 与 FairVision 有 1,302 眼指纹匹配（随机期望 1.9）；直接比图确认 **1,031（79.2%）** 是同一份 3D OCT（余弦 ≥0.9999，88% 体素完全相等），至少占 GF 的 31%。三个 FairVision 划分里重复比例 78.5–80.8%。Harvard-GDP 与 GF 共享 22 眼（52 个总偏差点 + MD 全等），全在 GF 验证划分。105 篇引用里拿到全文的 64 篇**都没报告**这份重叠。五次训练：在「78.5% 测试眼其实是训练数据」的泄漏集上 AUC **0.90**，真正样本外 **0.78**（膨胀 0.12）。每个种族亚组都膨胀，且样本外越差膨胀越大（Spearman ρ=−0.57）。
- **单篇小结**：这是给条目 1 / `2608.07651` / 任何 Harvard 青光眼 OCT 工具槽的硬约束——**互当外验会把 0.78 写成 0.90，公平性缺口会被泄漏掩盖。** 接到青光眼 Agent 外验表时应先问：三个 Harvard 集有没有按体积去重、患者级划分有没有跨库碰撞。不是 Agent，但本周正刊里对眼科 Agent 数字杀伤力最大的一条。

### 5. 眼科基础模型适配框架、视网膜脱离 AI 诊断 meta，以及角膜 / 眼表成像卡

- **日期 / 来源**：2026-11-14 / 11-14 / 11-10 / 11-09；*Acta Ophthalmol* / *Graefes* / *Cornea* / *Prog Retin Eye Res*
- **链接**：https://doi.org/10.1111/aos.70276（PMID 43031527）· https://doi.org/10.1007/s00417-026-07618-1（PMID 43033233）· https://doi.org/10.1097/ICO.0000000000004359（PMID 43008396）· https://doi.org/10.1016/j.preteyeres.2026.101539（PMID 43003180）
- **相关度**：眼科相邻（适配框架 / 诊断 meta / 角膜炎四分类 / 眼表照相标准化；都**不是** Agent）
- **摘要**：**Beyond the foundation model**（11/14）：不问「再做一个眼科基础模型」，问拿到权重之后怎么适配。主张用标注量、疾病稀有度、预训练–任务域匹配、许可、算力和跨设备/人群泛化**一起**决定要不要微调，并必须对照监督基线、按预定用途验证。**RD meta**（11/14）：66 项综述、31 项可合并（118,432 张图）。合并灵敏度 **0.93**、特异度 **0.98**、AUC 0.982、DOR 642；眼底照相最多、深度学习为主。作者强调外验和真实世界验证仍薄。**角膜炎四分类**（11/10）：973 张眼前节图、576 例、7 家日本机构 + JOIR。YOLOv5 五折：卡他性溃疡 / 疱疹基质 / PUK / 疱性角膜炎的 PPV 0.72 / 0.84 / 0.88 / 0.72，AUC 0.81 / 0.90 / 0.94 / 0.91；探索性一折上模型 76.6%，角膜专科 72.5%，住院医 64.5%。**OSP 路线图**（11/09，Ting 等）：裂隙灯眼表照相缺采集协议，这是可部署 AI 的主瓶颈；给出分场景最低采集/数据集规范。
- **单篇小结**：四条分别钉四句话——RETFound / EVLF-FM 的下一步是适配门而不是再预训练；RD 0.93/0.98 不能写成已经可替代散瞳检查（外验薄）；角膜炎头可以进眼前节工具槽，但卡他性溃疡灵敏度只有 0.47，不能当筛查门；眼表 Agent 先缺标准化照片，不缺模型。全部不是编排 Agent。

- **摘要**：**六模型眼科技术写作**（Cureus，epub 10/13，本周索引）：ChatGPT 4.0 / Gemini 2.5 Pro / DeepSeek / Grok 3 / Copilot / OpenEvidence 2.0 对四条眼科亚专科提示。人工对照在医学准确性、全面性、组织上全面压过模型；OpenEvidence 文献支持与对照打平（24/24 完整准确引用）。**屈光手术人选**（*Medicine*，10/30 号）：问 AI 能否匹配屈光外科医师做候选人选择——按既定口径不是工具 Agent，引用前对原文数字，不臆造灵敏度。**欧盟 MDR + AI Act**（*Ophthalmol Sci*，epub 9/11，本周索引）：把眼科 AI 的再分类、合规和临床含义写成监管卡。

### 7. Clinical-SAM: Agentic Test-Time Adaptation of SAM via Physician-in-the-Loop for Clinical Tumor Segmentation

- **日期 / 来源**：2026-11-12；*IEEE Transactions on Medical Imaging*。Bayasi / Fayyad / Yousefirizi / Rahmim
- **链接**：https://doi.org/10.1109/TMI.2026.3753143 · https://pubmed.ncbi.nlm.nih.gov/43019264/
- **相关度**：**方法可迁移（本周正刊主对照）**——医师-在环的测试时 Agent，把「接受/拒绝」当成唯一在线信号；可对 OCT / 眼底分割工具槽
- **摘要**：交互式基础模型（SAM）跨部署点泛化差。现有测试时适应要么拿掉医师、要么把空间标注负担加回来。Clinical-SAM 分两阶段：部署前用强化学习训一个自提示 Agent，推理时不再要逐例空间点；部署后只用医师已经在产生的信号——对每张提议掩膜的二元接受/拒绝——在线改策略。六个肿瘤分割基准（CT：结肠 / 胰腺 / 肝 / 肾；PET：头颈 / 肺），以与参考标准的一致当作医师接受的代理。六个数据集全部达到当时 SOTA，超过微调、交互、TTA 和在线学习基线，平均每例只要 **3.3** 次二元判断。
- **单篇小结**：这是给条目 1「报告 Agent 对动作无权限」的分割版——**人在环可以薄到二元门，不必画轮廓。** 接到黄斑裂孔 / 视盘杯分割工具槽时应同时报：平均点击/判断次数、相对纯 TTA 的增益、以及代理标签是不是真医师。不是眼科，肿瘤终点不能外推到 OCT 层分割。

### 8. 放射科两条对照：文档 Agent 的高严重违规消不掉，FDA 工具目录盖不住全报告

- **日期 / 来源**：arXiv **2026-11-08** / **2026-11-06**
- **链接**：https://arxiv.org/abs/2611.11541 · https://arxiv.org/abs/2611.09836
- **相关度**：方法可迁移（工具使用 LLM Agent 的事前护栏；用已批器械目录做放射编排。后者末作者单位是 Rothschild 眼科基金会放射科，**不是**眼科终点）
- **摘要**：**Safeguarding Agentic AI in Radiology**（Charité，11/08）：48 个合成、放射科审过的基础场景（发现沟通 / 肿瘤委员会 / 随访），43 个另有误导信息变体，共 91 变体。六模型（Claude Sonnet 5.5、GPT-6.1-Sol、GLM-5.3、MiniMax M3、Gemma-4-31B、Qwen3.8-27B）× 三种护栏（只给权限 / 确定性规则 / 规则+本地 LLM 检查器）= 1,638 回合。只给权限时高严重违规 7.3–27.1%（合 **19.4%**）；加规则 16.7%（−2.8 pp）；规则+检查器 **13.2%**（−6.2 pp）。任务成功率没有可检测下降。误导变体里 Agent 在 83% 回合打开被改过的文档，58% 的错误陈述引用了它。挡住的动作里 64–68% 本来不会造成违规，被退回修改。**Can Agentic Systems Close the Gap**（Raidium / Rothschild，11/06）：用 FDA 已批放射 AI 器械整理出的工具目录 vs 无限目录，在虚构多模态报告语料上模拟编排。仅凭适应证 + 已批目录，编排器找回不到三分之一可行动发现；多数漏诊是该模态根本没有已批类别，三分之一是目录里有却没被调用。补最常缺的工具能接近无限目录，换小编排器则把增益全部吐回去。
- **单篇小结**：两条分别对应眼科的两件事——OCT 报告 Agent 必须有**动作前**规则+检查器，且不能指望把高严重违规打到零；眼底/OCT 工具槽不能默认「把已有 CE/FDA 头都挂上就等于全报告」——目录缺口和编排漏召回是两件独立的事。Rothschild 署名不把本条变成眼科直接相关。

### 9. Safe RL for Multi-Turn Clinical Agents、BioMem，以及静默访问 PHI

- **日期 / 来源**：arXiv 2026-11-09 / 11-10 / 11-02（漏检周）
- **链接**：https://arxiv.org/abs/2611.12728 · https://arxiv.org/abs/2611.13426 · https://arxiv.org/abs/2611.02319
- **相关度**：方法可迁移（多轮临床 Agent 的过程奖励、生物医学记忆、HIPAA 最小必要。均非眼科）
- **摘要**：**Safe RL**（Murphy / Saenz，11/09）：用药续方分诊、急性诊断、剂量滴定三个可控环境。只奖最终结局的 GRPO 常提高平均奖励，但会早承诺、压成一问、在罕见高危上崩。诊断任务上，给「降低不确定性的提问」稠密学分，三颗种子上提高留出价值和中等病例支持，且没有结局-only 的高危种子崩。探索/利用解耦在最佳检查点抬高危支持，但低急性病例问得过多。监督已经会仔细问诊之后，RL 靠少问抬平均分、同时伤高危。**BioMem**（11/10）：五套记忆策略 × 四模型，覆盖生物医学知识推理、临床预测、长程对话；在此之上提出训练免费的 Hybrid Memory Retrieval and Utilization（HMRU）。**Silent PHI access**（11/02）：标识符无关的临床任务里，三个模型仍会不必要地调 PHI 工具，Claude Opus 4.8 与 GPT-5.5 没有；最严策略下的残留访问限于用户覆盖策略或声称已批准的帧。执行前闸门几乎消掉这类访问。只看输出验证不了最小必要。
- **单篇小结**：接到青光眼电话分诊 / GAO-Triage 续训时应禁止只报结局准确率——必须分栏早承诺、高危召回、平均问次数。记忆层可抄 HMRU 的「保真 vs 利用」拆法，不要把「有记忆」写成已经会跟抗 VEGF 疗程。PHI 条要求：眼科科研 Agent 的工具日志必须能审计「调了但没写出」的病历号。

### 10. MAGR-TCM 多 Agent 分诊、喉音 Agentic 筛查与病理 / 心衰 agentic 就绪短评

- **日期 / 来源**：2026-11-12 / 11-13 / 11 月号
- **链接**：https://doi.org/10.1186/s13020-026-01485-y（PMID 43015875）· https://doi.org/10.1016/j.jvoice.2026.10.049（PMID 43026113）· https://doi.org/10.1016/j.medj.2026.101333（PMID 43025396）· https://doi.org/10.1016/j.cardfail.2026.06.031（PMID 43009254）
- **相关度**：方法 / 治理可迁移（家用多 Agent 分诊、可解释筛查 Agent、病理基础模型+agentic 就绪、心衰作为 agentic 试验场。均非眼科）
- **摘要**：**MAGR-TCM**（11/12）：741 份病案抽 10,231 实体 / 32,051 关系做成妇科中医知识图谱，四 Agent RAG 重建「病–证–法–方–药」。安全测试集灵敏度与特异度均 **100%**，用来区分可自评与需急诊。**喉音 AVDD-Agent**（11/13）：随机森林 + LIME/SHAP/DiCE + 规则，三类声音（喉气囊肿 / 老年声 / 正常）；作者自称初步框架。**病理 *Med***（11/13）：讨论计算病理里基础模型与 agentic AI 的临床就绪，本身是综述/观点。**心衰 ADVOCATE**（ARPA-H，11 月号）：把心衰写成临床 agentic AI 的理想试验场，无新系统数字。
- **单篇小结**：家用分诊可抄 MAGR 的「安全测试集必须 100% 特异」——眼科预问诊 Agent 若不能把红旗从可自评里分开，就不要上线。喉音条提醒「Agentic」可以只是分类器外包一层规则，按既定口径**不**对照条目 1。病理 / 心衰两条只提供叙事，不提供可搬数字。
