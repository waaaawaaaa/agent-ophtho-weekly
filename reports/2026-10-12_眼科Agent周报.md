### 1. OphthaAgent: Learning Cognitive Prudence for Reliable Fundus Diagnosis via Tool-Augmented Reinforcement Learning

- **日期 / 来源**：OMIA13 口头 / 海报，会议日 **2026-10-01**（Strasbourg）；本窗口会后页放出可核对口头表 + 海报 PDF。东南大学（Wenqing Xie / Ruiqi Wang / Gaole Dai / Yi Zhou）+ 南京理工大学（Tao Zhou）。GitHub 最近推送 **2026-10-01**
- **链接**：http://hdmilab.cn/omia13 · 海报：http://hdmilab.cn/documents/omia13-paper-poster/7.pdf · 代码（部分开源）：https://github.com/rikey123/OphthaAgent
- **相关度**：**直接相关（本周主条目）**——工具使用 / 多轮眼底诊断 Agent，覆盖 DR、AMD、DME、青光眼
- **摘要**：MLLM 单次嵌入容易漏细病灶；朴素工具增强又会「认知卸载」——模型把工具输出当真理，错误沿轨迹级联。OphthaAgent 把诊断写成在线多轮 reason–tool–observe–refine：11 个异构眼底工具做质控/增强、可疑区裁剪、病种级预测（DR 分级、AMD、DME 风险）、病灶分割定量、解剖级分析（血管、视盘/杯、黄斑、ETDRS 映射）。反思在工具低置信、相互打架或临床证据不够时触发，把工具输出当**可错中间证据**，再用内在视觉推理和细粒度工具核验。训练两阶段：先在五类专家轨迹上冷启动 SFT（最少够用、冲突恢复、级联依赖、共病、质量感知拒识/先增强），再 GRPO，复合奖励 = 格式 + 准确 + 行为（含动态 LLM-as-Judge）。轨迹过滤：百分制（结构 10 / 临床逻辑 30 / 工具交互 40 / 答案一致 20），低于 50、致命错、幻觉工具证据直接丢。海报对照 FundusExpert（8B）总体 **73.57% vs 67.05%**（约 2× 少参数）；域内单标签 MCQ 80.33%，域外单标签 73.48%，域外多标签 Jaccard 61.80%、precision 81.08%。疾病维写优于 MedGemma（AMD、DR 严重度、HTR、病理性近视、青光眼等）。RL 后：工具辅助纠正 7.4%→13.9%（+87%），成功纠正 4.6%→14.2%（+210%），纠正占比 24.0%→33.5%。README 工具表写明：质控 EfficientNet 集成（DeepDRiD / DrimDB）、增强 IETK-Ret、DR 分级 DINOv2（EyePACS / APTOS）、病灶 nnU-Net（IDRiD）、解剖 AutoMorph、AMD DeepSeeNet+、盘/凹定位多任务 EfficientNet。仓库只放 `ophthaagent-toolkit/`（agents / generator / `fundus_decision.py` / `run_vqa.py`），大权重与非公开组件未放；徽章写 Under Review。
- **单篇小结**：这是对 `2608.07651`（人写质控/分类/分割 + 一次反思）和 MedRSI（失败后发明工具、慢注册）的第三种写法——**工具集仍然是人预先挂上的，但策略用 RL 学会「何时不信工具」**。可搬的不是 73.57% 这个绝对分（海报未给划分、样本量、金标准定义），而是三张表：11 工具按病种/病灶/解剖三粒度拆；轨迹必须能写失败恢复；纠正率单独报，不要只报最终准确率。接到 AI-TEC / EyeAgent 时，应禁止生产 Agent 把分割/分级分数写成不可质疑的事实；低质量图默认先增强或弃权，而不是硬出 DR 期。局限必须写清：会议海报 + 部分开源，无权重、无外中心、不是 silent trial；GitHub 创建于 2025-10-18，本窗口新增的是可引用口头/海报与工具链 README。不要和 OphthaReason（看图推理、非工具编排）或 QiZishi/OphAgent 混名。

### 2. Retina-RAG: Retrieval-Augmented Vision–Language Modeling for Joint Retinal Diagnosis and Clinical Report Generation

- **日期 / 来源**：OMIA13 同场口头（Foundation Models / Trustworthy Clinical AI）；Friedrich-Alexander-Universität Erlangen-Nürnberg（Abdelrahman Zaian / Sheethal Bhat / Andreas Maier）。预印本 `2605.06173` 早于本窗口，本周按会后海报补录
- **链接**：http://hdmilab.cn/documents/omia13-paper-poster/9.pdf · https://arxiv.org/abs/2605.06173 · https://cris.fau.de/publications/363776945/
- **相关度**：眼科相邻（分类器引导 RAG 写 DR/ME 报告；**不是**工具编排或诊疗 Agent）
- **摘要**：筛查系统多停在图像级分类、没有结构化报告。Retina-RAG 拆三块：(i) 视网膜分类器——FLAIR 出 DR 级、FunSwin 出黄斑水肿及分数；(ii) 分类器引导 RAG——ICDR / AAO / Joslin 知识库，FAISS+BM25 混合检索再重排，只取与预测分级/ME 状态匹配的 top-3；(iii) LoRA（r=64, α=128）适配的 4-bit Qwen2.5-VL-7B，提示先图、分类器输出只是一个数据点、固定报告格式。RDD 测试（3 次均值）：DR F1 **0.731** / AUC 0.774，ME F1 **0.948** / AUC 0.897，超过零样本 Qwen（0.096 / 0.732）和 MMed-RAG（0.541 / 0.641）。报告 ROUGE-L 0.438、SBERT 0.884。消融：分类器 + 微调 VLM 已到 DR F1 0.698 / ME 0.878；再加检索把 ME F1 抬到 0.948。只调 1.23% 参数、单消费级 GPU。下一步写跨数据集与专家事实性。
- **单篇小结**：形态上接近「专用门 + 出处检索 + 小 VLM 填报告」，不是 OphthaAgent 的多轮工具循环。接到筛查 Agent 的报告槽时，应先锁分类器、再只检索与该分级一致的指南片段——不要让通才 VLM 自己检索再改分级。预印本在 5 月，不另计一条「新的直接相关」。

### 3. OphJev: endpoint-aware System One decisions for ophthalmic imaging and clinical text

- **日期 / 来源**：medRxiv 上线 **2026-10-06**（稿号 2026.10.03.26364645）；Zhicheng Du / Zhuo Deng / Lan Ma
- **链接**：https://www.medrxiv.org/content/10.64898/2026.10.03.26364645v1 · https://doi.org/10.64898/2026.10.03.26364645
- **相关度**：眼科相邻（终点感知的校准 / 选择性通才查询；**不是** LLM Agent）
- **摘要**：眼科决策需要「对着具体临床问题、候选集和运行策略」的概率，而不是一张泛用 softmax。OphJev 把冻结的影像/文本表征、候选打分、schema 特异校准和**选择性通才查询**拼成 System One 框架，眼底与 OCT 分开写终点配置。八个外部资源 × 多表征家族 × 三种通才规模 × 三随机种子。schema 感知仿射校准在全部 8 个主影像–文本配置上降低 held-out Brier 与选择性风险。HYGD 上，匹配监督融合把 AUROC **0.772→0.798**；另一条增益路由策略在最多 20% 通才影像调用下把 Brier **0.618→0.599**。作者强调这是互补的决策层能力，不是万能增益；外推和更大专科库仍依赖队列。文本扩展：1,996 份病历 × 91 个眼科问题，校验集校准改善笔记概率，词法对照仍然强。结论：可审计决策框架，前瞻临床获益未验证。
- **单篇小结**：位置正好接在上周 CRC-Router「错接风险」和 EVisionAI「混浊/豹纹弃权」之后——把「何时叫通才」写成可校准预算，而不是默认每张 OCT 都过旗舰 VLM。不要把 System One / 路由写成已经是诊疗 Agent。接到青光眼/糖网门时应同时暴露：校准 Brier、通才调用比例、以及外队列是否还成立。

### 4. Comparison of Two AI Chatbots for Diagnosis and Providing Treatment Suggestions in Retinopathy of Prematurity

- **日期 / 来源**：2026-10-07；*Journal of Medical Internet Research*
- **链接**：https://doi.org/10.2196/86726 · https://pubmed.ncbi.nlm.nih.gov/42842945/
- **相关度**：眼科患教/决策 LLM（70 婴 / 140 眼需治 ROP；**非 Agent**，给分诊 Agent 提供「看图 vs 写处置」拆槽）
- **摘要**：深圳眼科中心等。需治 ROP 70 婴（140 眼），结构化临床文本 + 广角眼底。两阶段提示：先出分区/分期/plus，再给治疗建议；金标准为临床共识。Gemini 2.5 Pro vs ChatGPT o4-mini：分区一致 79.3% vs 85.7%，分期 64.3% vs 70.0%，需治灵敏度 93.6% vs 90.7%（均 *P*>0.05）。Plus：Gemini **77.1% vs 57.1%**（*P*=0.006）。在金标准诊断上的治疗方式指南符合：o4-mini **65.0% vs 39.3%**（*P*=0.01）。ROP 特异 GQS：治疗建议 o4-mini 更好（*P*=0.001），诊断任务相当。
- **单篇小结**：这是把「会看 plus」和「会按指南选激光/抗 VEGF」拆开的对照。接到 ROP / GAO 分诊 Agent 时应分两槽评，不要一个「聊天机器人总分」。70 例需治队列没有特异度分母，不能写成筛查门。

### 8. Deep Learning-Derived Retinal Vascular Morphology and Incident Treatment for Sight-Threatening Diabetic Retinopathy

- **日期 / 来源**：电子出版 2026-08-26；本窗口 *Ophthalmology Science* 可见（2026 Nov 卷）
- **链接**：https://doi.org/10.1016/j.xops.2026.101385 · https://pubmed.ncbi.nlm.nih.gov/42857094/
- **相关度**：眼科预后生物标志（Moorfields / UCL Keane 组；AutoMorph 黄斑血管形态 → 需治 STDR；不是 Agent）
- **摘要**：2000–2022，20,855 人 / 33,861 只可分级、治疗初治、有黄斑中心眼底的眼。AutoMorph 抽动脉/静脉复杂度、密度、管径、迂曲。均访 1.74 年，10.2% 眼接受 STDR 治疗（PDR 1,387；CSME 2,059）。动脉复杂度 / 密度最高四分位相对最低：STDR 治疗 HR **0.52 / 0.47**；更大静脉管径 HR **2.53**；更大动脉管径降低 PDR 治疗风险（HR 0.64）。无/轻度 DR 且无 DME 的敏感分析方向不变。
- **单篇小结**：这是把上周九病种门/阴性筛查从「现在有没有病」改成「以后会不会被治疗」。接到糖网随访 Agent 时应把血管形态写成只读风险层，和当前 ICDR 分级分开报。电子出版早于窗口，仅因本周索引列入。

### 13. KGR-MAS: Knowledge Graph-Enhanced Multi-Agent LLM Framework for Evidence-Based Medical Diagnosis and Clinical Decision Support

- **日期 / 来源**：2026-10-08；*IEEE Journal of Biomedical and Health Informatics*
- **链接**：https://doi.org/10.1109/JBHI.2026.3740738 · https://pubmed.ncbi.nlm.nih.gov/42848569/
- **相关度**：**方法可迁移（本周主对照）**——用知识图谱拆子任务、门控跨 Agent 记忆、在诊断检查点检索
- **摘要**：针对 LLM 推理偏倚、信息瓶颈和适应性差。KGR-MAS 三件套：(1) 从知识图谱导出可执行诊断路径，动态分配 Agent，并用路径初始化共享短时记忆；(2) 语言级 LSTM 风格门控 + Transformer-XL 短时记忆，管跨 Agent 信息流；(3) KG 引导的 RAG-STM：在诊断检查点检索，再写回短时记忆。自建医学 KG embedding Hits@1 32.8%、MRR 0.498。MedQA 准确率 **87.2%**（相对对照 +14.4%），四个开放域均分 77.4%（+29.0%），作者称超过 GPT-o1 的 72.0%。
- **单篇小结**：可直接搬到青光眼/抗 VEGF：先把 AAO / EGS 指南编成可执行路径，再按检查点检索，而不是让通才「读完整份病历再讲故事」。这和上周 ARCagent「冲突写成检索目标」是同一纪律，只是对象从互相打架的指南变成图谱路径。局限：评测是 MedQA 选择题，不是眼底/OCT 轨迹；「超过 o1」取决于对照设定。院内不要把 87.2% 写成已经可替代专科。

### 14. LongCAF: A longitudinal context-constructive agentic framework for LLM-supported hypertension self-management

- **日期 / 来源**：2026-10-08；*Journal of Biomedical Informatics*

- **相关度**：方法可迁移（纵向记忆 + 意图路由 + 安全升级；6 个月真实部署，可对青光眼/nAMD 随访对话）
- **摘要**：浙大 / 解放军总医院海南医院。把碎片化、漏报、意图漂移的慢病对话写成五模块：纵向上下文记忆、意图感知路由、上下文接地的回复合成、主动补问、安全升级到临床医师。6 个月部署：患者级上下文完整度中位 **42.9%→57.1%**，新增 79,290 条临床相关记录，非血压域占 49.3%；69% 的患者可见输出用到了检索到的患者上下文；候选问题采纳 84.4%；意图路由 micro-F1 0.911；端到端安全升级 precision 0.915 / recall 0.977 / F1 **0.945**。

### 17. Claude Haiku 5.5、Sonnet cache 降价与 GPT-6 Intelligent UI
