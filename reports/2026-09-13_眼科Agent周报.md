## 本周总结

检索窗口 **2026-09-07～2026-09-13**。按既定口径（标题/摘要同时出现 Agent / Agentic / multi-agent / tool-using LLM agent，以及 ophthalmology / ophthalmic / fundus / OCT / glaucoma / retina），本周有 **两条直接相关增量**，其中更重的是期刊评论正刊：

1. **AI-TEC**（清华戴琼海 / 王雅星 / 吴嘉敏 / Tien Yin Wong 等，*Nature Medicine* 2026-09-10）：北京清华长庚医院自 **2025 年 11 月** 起把「AI-Agent Augmented Tsinghua Eye Clinic」嵌进真实门诊——预问诊、分诊、多模态精诊、决策支持与随访管理由多个专科 Agent 串起来，而不是再挂一批互不相通的筛查模型。文章是 Comment，**没有给出诊断准确率或 RCT 数字**；核心主张是：算法进院后，评价要从「这个模型准不准」改成「有没有改工作流、转诊、治疗与结局」。
2. **Moorfields nAMD 分析 Agent**（吴伊兰 / Dun Jack Fu / 周宇坤 / Siegfried Wagner / Pearse Keane，*Journal of Medical Internet Research* 2026-09-08）：用 Claude 在 Chat / Code / Cowork 三种模式下，对 Moorfields **7802 眼湿性 AMD 12 年公开队列**做「出题 → 写统计计划 → 跑代码」。Kaplan–Meier 点估计在 17 次完成跑里几乎重合，但 **SAP 质量不能预测代码对不对**，同模式错误会原样复制；17 篇叙事总结里 8 篇完全合格，**2 次出现有临床意义的错误**。作者明确：出题和写计划可以放手，公式、队列边界和一致性指标必须专家核。

连续跟踪的青光眼眼底 Agentic 框架（`2608.07651`）、GAO-Triage（`2608.04772v2`）与 AgentEYE（*Cell Reports Medicine*）本周未见新版本、代码仓或勘误。MICCAI 2026 *Agentic AI for Medicine* Workshop 仍定 **10 月 1 日**，官网录用名单未公开。EyeAgent RCT（NCT07401459）仍为 Not yet recruiting（估计启动日 3 月已过）；AEYE Trial（NCT07096232）仍为 Enrolling by invitation、last update 2025-09-15。

### 1. Initial lessons from real-world implementation of an AI-agent eye clinic in China（AI-TEC）

- **日期 / 来源**：2026-09-10；*Nature Medicine*（Comment）
- **链接**：https://doi.org/10.1038/s41591-026-04631-z · https://pubmed.ncbi.nlm.nih.gov/42722887/ · 清华院系说明：https://media.au.tsinghua.edu.cn/info/1016/1638.htm
- **相关度**：**直接相关**（本周主条目；期刊正刊，关键词即 AI-agent eye clinic / multi-agent ophthalmic workflow）
- **摘要**：清华自动化系、北京视觉科学与转化眼研究所（BERI）、清华医学、北京清华长庚医院等联合发表 Comment。作者认为，基础模型把单任务诊断、风险预测和读图做得越来越准，并不自动等于医疗服务更好——真实诊疗是患者、医师、设备、数据和互锁流程组成的系统。传统「AI-assisted」把模型当外挂：影像分析、检出、风险各跑各的，医师仍要手工拼结果，有时还加重信息负担。文章提出 **AI-native health system**：AI 嵌进路径，持续整理信息、支持决策、协调照护。据此做成 **AI-TEC**（AI-Agent Augmented Tsinghua Eye Clinic）：预问诊 Agent 整理症状与病史，分诊 Agent 做风险分层并分配检查，精诊 Agent 整合多模态眼科数据，决策支持 Agent 提供循证信息，患者支持 Agent 覆盖患教、随访与长期管理；各阶段信息向后传递，强调 Agent 之间的信息流而不是工具堆叠。**2025 年 11 月**原型进入长庚常规流程，先接预问诊和眼底分析。实装经验：专家审过的高质量临床数据能明显抬性能；系统与运营设计决定医师愿不愿意用；持续反馈才能让 Agent 进化。作者同时指出 silent trial 测得出「在真实环境里跑得怎样」，测不出对决策、效率和结局的影响；真实参考标准本身有不确定性；以病为中心的算法任务未必对应患者主诉；筛查若不接到转诊、确诊、治疗和随访，临床价值仍为零。通讯作者含吴嘉敏、王雅星、戴琼海、Tien Yin Wong；共同第一作者严韬、张迪。
- **单篇小结**：这是本仓库首次出现「已经进院的眼科多 Agent 诊所」，位置正好接在 AgentEYE / EyeAgent / `2608.07651` 之后——那三篇还停在内部基准或工具编排，这篇把问题改写成**系统工程**。评测清单应加四栏：工作流嵌入、医师采用、转诊闭环、结局，而不是只报敏感度。局限必须写清：这是 Comment，不是 RCT，也没有公开工具列表或代码。对标 NCT07401459（EyeAgent 多中心 RCT）时，AI-TEC 提供的是「先 silent、再改流程」的部署叙事，不能替代随机对照。

### 2. Performance, Failures, and Oversight of a Large Language Model Agent for Clinical Data Analysis

- **日期 / 来源**：2026-09-08；*Journal of Medical Internet Research* 28:e99597
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42709964/ · https://doi.org/10.2196/99597
- **相关度**：**直接相关**（tool-using LLM agent + 湿性 AMD 真实队列；任务是科研分析而不是看图诊断）
- **摘要**：Moorfields 团队用先前发表的 **7802 眼湿性 AMD 12 年结局**公开数据集和参考 R 脚本，评 Claude Agent 在 Chat / Code / Cowork 三种交互下的五阶段分析流水线。三种提示：A 只看原始数据出研究问题；B 从高层临床目标写 SAP 再执行；C 按研究者写好的 SAP 执行；各 3 次重复，共 27 跑。结果：产出 18 个有临床根基的问题、覆盖 7 个域，只有 Cowork 摸到 3 个需要数据驱动方法的主题；9 份 SAP 都找对了统计框架；Kaplan–Meier 估计在 17 次完成跑里几乎相同。系统失败是：SAP 质量预测不了代码对错，同模式错误在独立重复里原样传播；结果文本几乎都能对上执行日志，但出现过单位传递错误和一次未披露的崩溃后重跑。17 篇叙事总结中 8 篇完全合格，**2 次写出有临床意义的错误**。结论：出题和写计划可靠，公式组成、队列边界逻辑和 concordance 计算必须专家核完才能报数。作者强调眼科队列只是受控试验台，框架可外推到其他专科。作者 Wu / Fu / Zhou / Wagner / Keane。
- **单篇小结**：这是本周第二篇「眼科 × 真会跑工具的 Agent」，对象从门诊改成了科研。对照上周 ClinTraceBench「记忆丢关系」、VERDICT「理由不忠实」：这里的失败更具体——**计划写对了，代码仍会在边界条件上静默错**。AMD 注射随访 / 青光眼纵向分析 Agent 若要自动出 KM 或治疗间隔，必须把「队列定义 / 单位 / 是否重跑」做成独立校验门，不能只看曲线好不好看。Cowork 能问出数据驱动问题，说明交互形态本身就是能力，评测要固定模式。

### 3. Generative artificial intelligence to augment ethical problem solving in ophthalmology: GPT-5.1 versus a human ethicist

- **日期 / 来源**：2026-09-07；*International Ophthalmology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42704533/ · https://doi.org/10.1007/s10792-026-04230-4
- **相关度**：眼科相邻（LLM 伦理推理，不是临床诊断 Agent）
- **摘要**：从 AAO *Ask the Ethicist* 随机抽 10 个真实眼科伦理情景，比较 GPT-5.1 与人类伦理专家。可读性上 GPT 更难读（Flesch 10.9 vs 25.4；Gunning Fog 21.3 vs 19.5）。10 名医师盲评：自己会不会用，人类中位 4.1、GPT **5.0**；感知患者影响 3.6 vs **3.9**。评分者一致性中等（ICC 0.56–0.69）。作者认为值得继续探索 LLM 作常见生命伦理辅助，但输出默认是专家级难读文本。
- **单篇小结**：与 8/30 KLEx 指南对齐同一模式——对齐可以很高，同时完全不适合直接给患者。分诊 / 患教 Agent 若接到伦理或知情同意，应先对规则表、再强制降年级，并保留伦理委员会或主治签发。医师「更愿意用 GPT」不等于患者读得懂，也不能当成已验证的伦理裁决。

### 4. Multimodal AI in retinal disease: from images to decisions and real-world endpoints

- **链接**：https://pubmed.ncbi.nlm.nih.gov/42704550/ · https://doi.org/10.1007/s10792-026-04254-w
- **相关度**：眼科相邻（视网膜多模态 AI 议程，点名决策与真实世界终点，不是具体 Agent）
- **摘要**：卷首把视网膜 AI 的下一问从「分类准不准」改成「能不能撑起患者路径上的决策」。主张把眼底、OCT、OCTA、超广角与临床特征、治疗史、纵向变化拼起来，服务风险分层、监测、治疗反应预测和个体化随访。同时警告：加模态或加参数本身不构成临床效用；必须证明相对单模态和临床基线的增量，处理缺失与域移，并跨机构、设备、人群外验。评价应走出回顾判别，覆盖视功能、转诊适当性、治疗时点、治疗负担、安全、可及与患者体验。

### 5. Large Language Models Approximate Inter-Expert Agreement in Glaucoma Suspect and Glaucoma Classification from Multimodal Data

- **日期 / 来源**：*Ophthalmology Science* 2026 年 10 月期；电子出版 2026-08-04；**本窗口 PubMed 索引**
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42718906/ · https://doi.org/10.1016/j.xops.2026.101352
- **相关度**：眼科多模态 LLM（非工具编排 Agent；本周最接近「通用模型同时吃眼底 + OCT + 视野」的对照）
- **摘要**：美国三级青光眼转诊中心 131 人 / **230 眼**（2016–2022）。输入年龄、性别、种族、视力、眼压、眼底照相、OCT RNFL 报告与视野报告；无任务微调。7 种配置：GPT-5 Pro、GPT-5.2、Gemini 3 Pro（两种提示）、Grok 2.2。金标准是 4 名青光眼专科医师的 leave-one-out 多数共识。专科医师准确率 71.3–83.9%（κ 0.46–0.68）；GPT-5 Pro 长提示 **80.4–85.7%**（κ 0.61–0.71），Gemini 3 Pro 长提示 **80.9–84.3%**（κ 0.62–0.68），各在两套参考上最高；GPT-5.2 中等，Grok 2.2 接近随机。中重度青光眼一致率高，疑似与轻度明显掉。作者 Shean / Mallapu / Xu 等。
- **单篇小结**：对照 8/30 *Retina* 四家 MLLM 只看 800 张眼底（除 ChatGPT-4o 外掉到 14–18%）：把 OCT 报告和视野打印件喂进去后，旗舰可以摸到专科医师之间的一致率。这不是否定 `2608.07651` 的工具编排——疑似/轻度正是 CDR / RNFL 定量工具该上场的地方；Grok 接近随机也再次说明骨干不能互换。Agent 设计应把「中重度可让 MLLM 起草、轻度强制过分割/分类工具」写成路由规则。电子出版早于本窗口，引用时按 8/4 epub 计。

### 8. Autonomous AI-driven point-of-care screening for diabetic retinopathy（AEYE-DS）

- **日期 / 来源**：电子出版 2026-08-25；*Frontiers in Digital Health*；**本窗口 PubMed 索引**
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42712598/ · https://doi.org/10.3389/fdgth.2026.1907804
- **相关度**：眼科自主筛查系统（固定算法，**不是** LLM Agent；本周作为三项前瞻验证的可见条目）
- **摘要**：AEYE-DS 在未散瞳点对点筛查中检出 more-than-mild DR，对照独立阅片中心 ETDRS 多专家。三项目、两种 FDA 相机（手持 Aurora、台式 Topcon NW400），>1200 名既往无 DR 诊断的糖尿病患者。敏感度/特异度：AEYE-1 **93%/91%**，AEYE-2 **92%/94%**，AEYE-3 **93%/89%**；可成像率 >99%；操作者内重复性 >99%；台间/机间再现 95–99%。作者支持规模化 POC 筛查。
- **单篇小结**：FOCUS / AEYE-DS 继续证明「写死的筛查流水线」在 DR 上已经很强。Agent 不该重做这件事，而该做 AI-TEC 指出的后半段：阳性之后谁转诊、谁治疗、谁随访。不要和 NCT07096232（屈光/圆锥角膜多 Agent）或商品名 AEYE 混成同一个系统。

### 9. Deep learning-based retinal risk stratification for 10-year atherosclerotic cardiovascular mortality

- **日期 / 来源**：电子出版 2026-09-01；*Clinical Hypertension*（本窗口可见）
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42707608/ · https://doi.org/10.5646/ch.2026.32.e38
- **相关度**：眼科相邻（眼底生物标志物预测全身结局；可作预问诊/分诊 Agent 的风险工具）
- **摘要**：韩国单中心 7832 名高血压或糖尿病、无既往 CVD 患者。Dr. Noon CVD 眼底评分在校正传统因素和 CKD 后，仍与 10 年 ASCVD 死亡独立相关（HR trend 1.49）；加入临床模型后 ΔC-index 0.030、NRI 0.484。高血压与糖尿病亚组趋势一致，且独立于是否有糖尿病视网膜病变。
- **单篇小结**：预问诊 Agent 很适合接「眼底 → 全身风险」工具，但必须把输出写成风险分层而不是心血管诊断。与视网膜身份门（上周）对照：先确认是同一个人，再谈纵向风险。

### 10. Optical Character Recognition-based Biometry Scanner for Easy and Efficient Biometry Calculations

- **日期 / 来源**：2026-09-01 电子出版；*Journal of Refractive Surgery* 2026 年 9 月期
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42715024/ · https://doi.org/10.3928/1081597X-20260701-02
- **相关度**：眼科工作流工具（OCR + Gemini 2.5 填 ESCRS IOL 计算器；弱 Agent 形态）
- **摘要**：跨平台 App 用 Gemini 2.5 OCR 读任意设备生物测量打印件，自动填 ESCRS IOL 计算器。12 名眼科医师 4 周使用：准确 4.5、易用 4.5、推荐 4.67。10 名医师 × 5 次计算：App 91.7 秒 vs 手工 179.4 秒（−48.9%）。
- **单篇小结**：这是「计算机使用 Agent」最脏、也最刚需的眼科场景——把厂商打印件搬进计算器。对照 8/26 Claude in Chrome：域名白名单 + 动作预审后，屈光术前清单可以先做 OCR→槽位→医师确认，而不是让模型直接选晶体度数。

### 11. Safe to Stop? Risk-Constrained Stopping for Sequential Clinical Diagnosis Agents（Cros）

- **日期 / 来源**：2026-09-09 提交 arXiv；`cs.AI`
- **链接**：https://arxiv.org/abs/2609.09678
- **相关度**：方法可迁移（序贯诊断 Agent 的停时 / 覆盖–误差权衡；可对电话分诊与检查开单）
- **摘要**：现有 Agent 基准多在固定或无约束交互后评准确率，自主停止是否可靠被默认。Cros 把状态误差排序、在隔离开发折上设计策略、再用 LTT 风格精确检验「选择性诊断误差」和「最低自主覆盖」。有限样本保证要求候选族、检验规则和随机化在碰校准标签前冻结。MIMIC 派生腹痛 1834 幕：完整 ranker 的探索性状态–误差 AUROC 0.853，高于最大类概率 0.715 和骨干自带停分 0.552。在已看过的 367 幕评价折上，冻结权重解析平均为选择性误差 16.9%、覆盖 78.8%、代价 5.57、检查 0.68，对照原生停止的 30.8% / 100% / 8.14 / 1.53。强迫继续并不单调：仅 HPI 误差 28.3%，全套检查后升到 34.3%。作者坦陈评价标签在早期开发中被看过，**不能当确证安全证书**；联合准则在 20 次开发重折上只名义满足 6 次。
- **单篇小结**：GAO / AI-TEC 的分诊 Agent 缺的正是「何时停、何时再开一项检查」。Cros 把停时做成带覆盖承诺的层，而不是让模型自己说「我够确定了」。强迫继续会升误差，说明眼科红眼/闪光路径不能默认「再问一句总是更好」。部署前必须冻结规则再校准，并承认本数字是探索性的。

### 12. EmoMed: An Emotionally-Aware Agent for Multimodal Medical Support with Real-Time Information Retrieval

- **日期 / 来源**：2026-09-07 提交 arXiv；`cs.AI`
- **链接**：https://arxiv.org/abs/2609.07194
- **相关度**：方法可迁移（多模态问询 Agent + 情绪适配 + 双检索；可对患教/远程随访）
- **摘要**：EmoMed 同时吃文本和医学影像，从输入检测焦虑、困惑、紧迫，再调语气、结构和细节；事实靠网页核验 + API 连接的更新知识库。在 GPT-4/5、Qwen3、Llama 4、Gemini 2.5、Grok4、Claude3 上用 LLM-as-judge、MedQA 风格准确率、BERTScore、安全/有用和多模态医学基准。作者称情绪自适应在各维优于中性基线且不掉临床准确率；对照用户研究认为共情和清晰度上升、对事实的信任保持。
- **单篇小结**：眼科电话/在线分诊最怕「正确但冷、或共情但胡编」。EmoMed 把语气做成可开关层，检索仍走双通道，比把共情写进同一段系统提示更可审计。必须另做红旗门：紧迫情绪不能自动升级成急症处置。

### 13. AI agents in cancer imaging: Concepts, advances, and clinical perspectives

- **日期 / 来源**：2026-08-30 电子出版；*Chinese Journal of Cancer Research*；本窗口索引
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42712812/ · https://doi.org/10.21147/j.issn.1000-9604.2026.04.05
- **相关度**：方法可迁移（影像 Agent 综述；放射/肿瘤是眼科近邻）
- **摘要**：多数肿瘤影像 AI 仍是预定任务。Agent 用基础模型做推理与编排，按目标组织分析、调用外部工具和数据，并按中间结果改下一步，有望从孤立模型变成连续工作流。综述整理原则、组件、评价，以及读图、决策支持和科研工作流上的代表进展。作者认为 Agent 能把碎片化的影像、临床和知识资源连起来，但临床证据仍少、多在受控环境；落地还受算力、多步误差传播、以及对具体工具/数据/流程的绑定限制。下一步应做系统级验证：能不能可靠组织信息、解释发现、并与医师协作。
- **单篇小结**：清单可直接对到眼底/OCT：质控、分类、分割、前后片、指南、报告对账。与同窗口放射评论（PMID 42728185）一起读：Agent 可以多吃病历和旧片，**信息不等于有权裁决冲突或担责**。AI-TEC 若要「精诊 Agent 整合多模态」，必须先写清谁授权、谁改标准、出错算谁的。

### 14. Local large language model-guided optimization for prostate radiotherapy planning（SAGE）

- **日期 / 来源**：2026-09 期；*Medical Physics*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42717765/ · https://doi.org/10.1002/mp.70688
- **相关度**：方法可迁移（本地 LLM Agent 真接治疗计划系统；对照上周 PlanningCopilot）
- **摘要**：SAGE 用本地 Llama 3.1 8B/70B Agent 经临床 TPS 调 VMAT 优化优先级，17 例前列腺 60 Gy/20 fx。比较 8B / 70B / 加 RAG 记忆四档。靶区 PTV V58.5 Gy 与临床计划无显著差；70B-RAG 阴茎球 V22Gy 优于临床（p=0.014）；记忆有增益，模型规模单独不显著。全部 70B-RAG 计划仍临床可接受。最复杂档 10 次自主迭代中位 45 分钟，对照临床任务周转中位 2700 分钟。
- **单篇小结**：继 PlanningCopilot 之后，又一篇「Agent 必须能调用院内 API」。眼科对标不是让模型写「建议抗 VEGF」，而是经 PACS/EMR 改预约、出结构化医嘱草稿，并且每步可回放。本地 70B + 病例内记忆，也说明不必默认上云旗舰。

### 15. Teaching Model Context Protocol, Retrieval-Augmented Generation, and AI Agents to a Multidisciplinary Hospital Workforce

- **日期 / 来源**：2026-09-11；*JMIR Medical Education*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42727083/ · https://doi.org/10.2196/97822
- **相关度**：方法可迁移 / 治理（医院怎么教 MCP、RAG 和 Agent；决定工具能不能被护士/医师用起来）
- **摘要**：首尔 Asan 医学中心 8 周、56 小时院内生成式 AI 培训，同步直播到两家区域医院。前提是 MCP 与 AI Agent 将成为医疗 AI 使用的底座：现场教学 37% 给 MCP，71% 是动手。从概念到 RAG / MCP 再到组队 capstone，配订阅、内部云和每周 3–6 小时辅导。前后测 n=83 / 64。MCP 自我效能增益最大（d=1.57）；非 IT 的临床、信息、科研和行政人员增益大于 IT；有人第一次靠 vibe coding 写出代码。作者称医院级 Agent 培训不必先假设技术背景。
- **单篇小结**：AI-TEC 把「医师愿不愿意用」写成系统问题。这篇给出可抄的培训配方：少讲模型名字，多练 MCP 工具注册和 RAG 白名单。眼科门诊若要上预问诊/眼底 Agent，应先给护士和住院医开一班「只会调本院工具」的课，而不是发一个 ChatGPT 账号。

### 16. Development and validation of a human-supervised AI-augmented living oncology evidence platform（Living-OEP）

- **日期 / 来源**：2026-09 期；*ESMO Real World Data and Digital Oncology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42729682/ · https://doi.org/10.1016/j.esmorw.2026.100770
- **相关度**：方法可迁移（人监督的 agentic 系统综述；可对指南/试验匹配）
- **摘要**：乳腺癌 Living-OEP：GPT-4.1 / o3 / Claude Sonnet-4 模拟 Cochrane 流程，按人写的标注手册拆任务、自调试、再校验。训练 29236 条试验摘要（乳腺/肺/前列腺），4 个综述变量 + 32 个抽取变量，再链到指南路径。对照 1997 条人工标注：综述准确率 95.1–97.2%，抽取 51.1–99.4%（3 个变量明显弱）。在 8 个乳腺治疗情景、6 项质量标准上优于若干聊天/检索机器人。
- **单篇小结**：眼科指南和抗 VEGF / 青光眼术式证据更新速度，已经适合「人写手册 + Agent 每日扫」而不是季度人工综述。抽取准确率下探到 51% 说明：**不能无人值守写进决策支持**；弱变量必须人工锁。可与 VERDICT 式规则求解器对接——Agent 填槽，求解器判适应证。

### 17. Evaluating Scaffolding-Oriented Multi-Agent Large Language Model System for Clinical Interview Training

- **日期 / 来源**：2026-09-10 提交 arXiv
- **链接**：https://arxiv.org/abs/2609.10939
- **相关度**：方法可迁移（问诊训练多智能体；可对眼科标准化病人 / 远程分诊话术）
- **摘要**：AI 标准化病人平台：患者 Agent 对话，导师 Agent 给苏格拉底提示且不泄诊断，轮次评价 Agent 盯进度但不报总分。100 名医学生 RCT：多智能体脚手架 vs 对照，两轮学习后在「仅患者」环境考试。最终诊断准确率无显著差，但沟通、共情和具体问病史行为更好。作者释放带多专家标注的转录、清单、轮次评价和 OSCE 分。
- **单篇小结**：GAO 式电话分诊缺的往往不是再抬一个急症召回数字，而是**把追问过程练出来**。可先在住院医/护士培训里用眼科红眼/闪光脚本，再决定是否把同一脚手架接到真实预问诊。诊断分不涨、过程质量涨，说明不要用期末诊断准确率当唯一 KPI。
