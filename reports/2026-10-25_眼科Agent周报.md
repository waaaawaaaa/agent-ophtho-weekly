### 1. An Agentic AI Workflow for Automated Macular Hole Diagnosis and Structured Report Generation

- **日期 / 来源**：2026-10-23；*Ophthalmology and Therapy*。Moorfields–UCL（Carla Troyas / Neil Shah / Inès Schumacher / Rodrigo Anguita）+ 伯尔尼 Inselspital（Lorenzo Ferro Desideri / Martin Zinkernagel）+ TUM
- **链接**：https://doi.org/10.1007/s40123-026-01523-w · https://pubmed.ncbi.nlm.nih.gov/42909794/
- **相关度**：**直接相关（本周主条目）**——编排 Agent + RETFound-OCT 工具 + GPT-4 报告槽；终点是黄斑裂孔
- **摘要**：现有 OCT AI 多半只做诊断。作者做成端到端 Agentic 工作流：编排 Agent 先走图像诊断，再走语言生成。RETFound 的 OCT 版被微调成「黄斑裂孔 vs 正常黄斑」二分类；多个公开 OCT 集按患者分层划分，再在两个独立外集验证。每张新图：Agent 调训练好的 RETFound，收下诊断，写入结构化提示，调用 GPT-4 写患者可读临床报告。内测 n=180：准确率 100%（95% CI 97.9–100%），AUC 1.00。外验 n=1014：准确率 98.8%（97.9–99.3%），灵敏度 97.9%（96.3–98.8%），特异度 100%（99.2–100.0%），AUC 0.999（0.998–1.000）。Grad-CAM 指向裂孔及邻层。全部样本都生成了简短、标准化的患教报告；**语言模型不参与、也不改写诊断**。作者把它写成虚拟玻璃体视网膜门诊的可扩展拆法，而不是无人签发手术指征。
- **单篇小结**：这是对上周 FFA-SegGPT「先图后文」和 GUIDE「诊断/推荐不得无人签发」的 OCT 手术版——**分类头出诊断，LLM 只复述**。可搬的不是 98.8% 这个接近饱和的二分类分（正常 vs 裂孔，不是分期/鉴别），而是三张表：编排 Agent 只许调已注册的 RETFound；报告提示必须吃诊断输出；语言槽禁止回写。接到 OphthaAgent 报告槽或抗 VEGF / 黄斑裂孔虚拟门诊时，应禁止 GPT 在没有分类分数时写「全层裂孔」。不要和 OphthaReason（看图推理）或 FOCUS（3D OCT 流水线、非 LLM Agent）混名。外验数字引用前对原文划分与设备表。

### 2. GLLaucoMed: A Secure Large Language Model-Powered Agentic Workflow for Automated Medication Extraction from Free-Text Glaucoma Clinical Notes

- **日期 / 来源**：本窗口 *Ophthalmology Science* / PubMed 可见（电子出版约 2026-08；medRxiv 2026-06-15）。Bascom Palmer（Nicholas Solages / Rafael Scherer / Felipe A. Medeiros / Swarup S. Swaminathan）
- **链接**：https://doi.org/10.1016/j.xops.2026.101366 · https://pubmed.ncbi.nlm.nih.gov/42927148/ · 预印本：https://www.medrxiv.org/content/10.64898/2026.06.12.26355525v1 · 标准化代码：https://github.com/swarupswaminathan/llmnotes（最近推送 **2026-07-27**）
- **相关度**：**直接相关（本周索引）**——青光眼病历上的三阶段 Agentic 抽取；不是阅片 Agent
- **摘要**：结构化 EHR 只能覆盖约 13% 从病历抽出的概念。作者在 1,250 例 Bascom Palmer 青光眼仓库（2014–2024）上，由两名青光眼专科标注、第三人仲裁四槽：当前局部用药（CTM）、局部用药拟变更（ΔTM）、当前口服（COM）、口服拟变更（ΔOM）。按医师分层 10% / 10% / 80%。五模型（Claude Opus 4.6、DeepSeek-V3.2、GPT 5.2、Grok 4.1、Qwen3.6-35B-A3B）走 Microsoft Azure AI Foundry、HIPAA 环境，**不微调**。流水线是初抽 → 引用接地校验 → 条件改写，再经 Drugs@FDA 商品名→通用名，输出结构化 JSON。Gwet AC1：CTM 0.799、ΔTM 0.888、COM 0.985、ΔOM 0.988。CTM F1：Claude **0.985** / DeepSeek 0.971 / GPT 0.978 / Grok 0.968 / Qwen 0.970；ΔTM：0.905 / 0.826 / 0.897 / 0.842 / 0.865（期刊摘要 Qwen 为 0.865，预印本写 0.855，引用以期刊为准）；COM：0.923 / 0.887 / 0.899 / 0.906 / 0.894；ΔOM：0.958 / 0.815 / 0.937 / 0.835 / 0.940。阳性例精确匹配：CTM（n=1354）0.730–0.882，ΔTM（n=404）0.619–0.780；口服两槽样本少（47 / 25）。Claude 与 GPT 最强。
- **单篇小结**：这是对 nAMD Claude 分析 Agent「让模型读轨迹」的病历抽取版，对象从 OCT 序列换成滴眼液变更。可搬的不是 CTM 的 0.985，而是：**当前用药和拟变更必须分槽报**——ΔTM 掉了近 10 个 F1 点，正是抗青光眼方案真正会改计划的地方。院内若抄三阶段，应把 Drugs@FDA（或本院处方集）写成本地表，而不是推理时打外网。电子出版跨窗口，仅因本周索引列入；GitHub 无本窗口 commit。不要把「Agentic」写成已经会开医嘱——它抽的是已写在病历里的药。

### 3. Performance of Frontier Multimodal Large Language Models on Ophthalmology Cases

- **日期 / 来源**：2026-10-22；*JAMA Ophthalmology*。多伦多大学 / St. Michael's（Shayaan Kaleem / Andrew Mihalache / Marko M. Popovic / Rajeev H. Muni）
- **链接**：https://doi.org/10.1001/jamaophthalmol.2026.4512 · https://pubmed.ncbi.nlm.nih.gov/42911566/
- **相关度**：眼科相邻（扩展 OCTCases 上的前沿多模态 LLM；**不是** Agent）
- **摘要**：眼科依赖多模态影像；任务型 AI 在限定影像任务上已较强，但通才 LLM 仍随任务和亚专科波动。2024 年 ChatGPT-4 在 OCTCases 429 道选择题上对 **299（69.7%）**，看图题更低。本横断面研究用**扩展后的 OCTCases** 题库，成对比较 ChatGPT-5.2 Instant、Gemini 3.1 Pro、Claude Opus 5.0，并另比 ChatGPT-5.2 与 ChatGPT-4；覆盖 OCT 看图题与非看图题。公开摘要未给出三模型的新准确率表（付费全文 / 表 2），引用前应对原文数字，不要用 69.7% 冒充 2026 年结果。
- **单篇小结**：位置正好接在条目 1 之后——**通才多模态仍在答题，编排 Agent 已经把诊断锁给 RETFound。** 接到院内「用最新 GPT 直接看 OCT」的采购话术时，应要求：看图 / 非看图分栏、以及和 2024 年同一题库的新旧对照。本条不是工具 Agent，不替代黄斑裂孔工作流。

### 4. Large language models as sources of diabetic retinopathy patient education；以及眼前节四消费级 LLM

- **日期 / 来源**：2026-10-24 / 2026-10-19；*Frontiers in Public Health* / *Ophthalmology Science*
- **链接**：https://doi.org/10.3389/fpubh.2026.1945318（PMID 42920690）· https://doi.org/10.1016/j.xops.2026.101398（PMID 42894879）
- **相关度**：眼科患教 / 专科问答（均**非 Agent**）
- **摘要**：**糖网患教**（10/24）：50 道标准化患者问题，ChatGPT / Gemini / DeepSeek / Doubao / Copilot / Perplexity，五名评分者按指南要素打 Safety / Accuracy / Empathy / DISCERN / EQIP / JAMA / GQS。Safety 组间一致中等（Fleiss κ=0.581），其余 ICC 0.806–0.870。安全回复率 86.0–94.0%，模型间无显著差；准确率普遍高、效应量小；共情差异更大（Copilot 最高，Doubao / Perplexity 较低）；Perplexity 的 DISCERN / JAMA 最高，Copilot 的 EQIP 最好。可读性模型间有差，Gemini 总体更易读。**眼前节**（10/19）：45 道专家级眼前节题、六个亚域，ChatGPT / Gemini / Claude / Grok 零样本、关记忆/浏览/检索（2026-01-19 单次会话）。11 名角膜专科盲评五维 Likert（准确、完整/效用、清晰、总体安全、潜在伤害）；无专家标准答案，指标是专家感知而非核实正确性。9,900 条评分齐全。三个质量维组间差显著（Friedman *P*<0.001；Kendall *W*=0.44–0.54），Claude 与 Grok 均优于 ChatGPT 与 Gemini（校正 *P*<0.001）。平均安全分无显著组间差。
- **单篇小结**：上周青光眼 FAQ 问「会不会在常识上撒谎」；本周补两句——糖网患教六模型的安全率其实差不多，差在共情和可追溯；眼前节专家题上 Claude/Grok 更好看，但没有金标准答案就不能写成已经可签发。接到 AI-TEC / 患教 Agent 时应把安全、引用和可读性分栏，并禁止用「专家觉得写得好」替代核对。

### 5. Error-Controlled Decision Policies for Medical Foundation Models（StratCP）

- **日期 / 来源**：medRxiv，本窗口 PubMed 可见（记录写 2026-10-06 / 另有 2026-02 版本号）。Moon / Jin / Zitnik 等
- **链接**：https://doi.org/10.64898/2026.02.23.26346927 · https://pubmed.ncbi.nlm.nih.gov/42926583/
- **相关度**：眼科相邻 / 方法（评测含眼科基础模型；把「能行动 / 必须延期」写成误差预算，**不是**诊疗 Agent）
- **摘要**：平均准确率不能保证安全决策，因为错误会集中在「预测直接指导处理」的患者上。StratCP 是分层共形预测：对每个患者决定基础模型预测能否直接指导处理，或应延期再查；在用户设定的错误发现率下选择可行动子集，给延期者返回覆盖真状态的预测集。有指南关系时用效用图把预测集成临床上连贯的集合。评测覆盖眼科、神经肿瘤和纵向病历，任务含诊断、生物标志、运营、化验和生存。作者称在入选患者上控制 FDR、在延期患者上达到目标覆盖；标准共形会超误差预算。新队列只需约 50 张带标签切片校准，不必重训。
- **单篇小结**：这是对 OphJev「System One + 选择性通才」的误差预算版。接到糖网/青光眼筛查 Agent 时应同时报：在目标假阳性预算下**有多少人真的能自动放行**，而不是再报一张 AUROC。电子出版跨窗口，仅因本周索引列入。不是工具编排。

### 6. 糖网 AI 综述、公平筛查评论与圣保罗收容所便携相机

- **日期 / 来源**：2026-10-23 / 10-20 / 10-23；*Surv Ophthalmol* / *Front Public Health* / *Rev Assoc Med Bras*
- **链接**：https://doi.org/10.1016/j.survophthal.2026.10.008（PMID 42906863）· https://doi.org/10.3389/fpubh.2026.1976572（PMID 42898801）· https://doi.org/10.1590/1806-9282.20260862（PMID 42912071）
- **相关度**：眼科工作流（筛查翻译与现场可行性；都**不是** Agent）
- **摘要**：**糖网 AI 综述**（检索至 2026-03）：从任务 CNN 走到视网膜基础模型，强调标注负担、域偏移和「过了基准还不等于进了门诊」。**公平筛查评论**：准确率本身不够，漏在够不着的人、不可分级、结果延迟、转诊未完成、治疗容量和数字壁垒。**圣保罗收容所试点**：非眼科人员用 Eyer 便携相机拍 38 人 / 76 眼，远程专科 vs EyerMaps。专科在 70/76 眼看到异常（最多是青光眼可疑、混浊、脉络膜视网膜改变、AMD 征象），**没有检出糖网**。以「任何眼部异常」为金标准，AI 灵敏度 25.7%、特异度 33.3%、准确率 26.3%——任务是糖网门，现场病谱却是白内障/青光眼。
- **单篇小结**：上周坦桑尼亚 RCT 把终点改成到诊；本周收容所试点把另一句话钉死——**相机能拍 ≠ 门对得上病谱**。接到社区筛查 Agent 时应先报「现场实际病种」，再报糖网 AUROC。综述/评论不是新系统。

### 7. NAKO 眼底队列、SCORE2 再分层与 LiDeOCTNet 等工具卡

- **日期 / 来源**：2026-10-19 / 10-25 / 10-24；*Ophthalmol Sci* / *Eur J Prev Cardiol* / *Front Digit Health*
- **链接**：https://doi.org/10.1016/j.xops.2026.101408（PMID 42894708）· https://doi.org/10.1093/eurjpc/zwag558（PMID 42921701）· https://doi.org/10.3389/fdgth.2026.1892323（PMID 42920637）
- **相关度**：眼科相邻工具 / 队列（人群资源、全身风险、轻量分割；都**不是** Agent）
- **摘要**：**NAKO**（10/19）：德国国家队列眼科二级模块 48,460 / 205,053 人，年龄 48.9±12.5 岁；非散瞳彩色眼底 + 视力 + 简史。开源 DL 评质量、C/D、A/V；标准架构预测年龄、性别和血压。这是可引用的人群级眼底 AI 资源卡，不是系统。**SCORE2 再分层**（UKB，40,672 未用他汀、无糖尿病，中位 10.0 年、914 例 ASCVD）：视网膜 AI 风险组在校正 SCORE2 后仍预测事件（极高 vs 低危 HR 2.32）；加入后跨过 ESC/EAS 他汀指征边界的 NRI 仅 **0.012**（*P*<0.001），连续 NRI 0.445，但 C 指数和净获益无增益。**LiDeOCTNet**：可变形卷积的轻量 OCT 分割，约 750× 少参数、推理约 7.4× 快，接近 TransUNet。
- **单篇小结**：NAKO 可当眼底基础模型的外验池，不要写成已经有诊疗 Agent。SCORE2 条接上周 Dr Noon CVD——**能再分层 ≠ 改变处方边界**。LiDeOCTNet 可接到黄斑裂孔 / 青光眼 OCT 工具槽的边缘设备栏。

### 8. Agentic artificial intelligence for code status extraction from clinical notes

- **日期 / 来源**：2026-10-20；*JAMIA*
- **链接**：https://doi.org/10.1093/jamia/ocag179 · https://pubmed.ncbi.nlm.nih.gov/42901486/
- **相关度**：**方法可迁移（本周正刊主对照）**——单 Agent / 自反思 / 抽取–复查多 Agent，直接对照 GLLaucoMed
- **摘要**：在 1,000 份 MIMIC-IV-Note 出院小结上抽 DNR / DNI / CMO。三种架构：单抽取 Agent、带自反思的单 Agent、顺序多 Agent 抽取–复查。四个开源模型：DeepSeek-R1-Distill-LLaMA-8B、GPT-OSS-20B、MedGemma-27B-IT、Qwen3.5-27B。金标准为医师–AI 双评 + 仲裁（Cohen κ=0.98–0.99）。对能打的大模型，单 Agent 在显式代码状态上相当或更好；多 Agent 复查把 token 和延迟加倍，准确率不涨。MedGemma 的自反思反而显著损害 DNI（*P*=0.047）。只有较小的 8B 蒸馏模型从多 Agent 复查得到统计显著纠正（DNR *P*=0.017，CMO *P*<0.001），但整体仍未到临床可接受。作者结论：Agentic 复杂度必须同时匹配**任务**和**模型能力**，不能默认上会诊。
- **单篇小结**：这是给条目 2 的刹车——GLLaucoMed 已经是三阶段，**不要再默认加第四个 reviewer Agent**。复现青光眼用药抽取时应固定：单 Agent 基线、自反思是否伤分、以及 token。弱模型才需要复查；能打的模型上，复查是成本不是安全。不是眼科。

### 9. The anatomy of a personal health agent

- **日期 / 来源**：2026-10-21；*Nature*。Heydari / Gu / Liu / McDuff / Xu 等（消费级健康，开源多 Agent）
- **链接**：https://doi.org/10.1038/s41586-026-11161-8 · https://pubmed.ncbi.nlm.nih.gov/42907512/
- **相关度**：方法可迁移（三个专科子 Agent + 编排器；可穿戴 + 病历，不是眼科）
- **摘要**：通才 LLM 盖不住日常健康的四种旅程：一般知识、个人数据解释、养生建议、症状评估。作者做成三个子 Agent——数据科学（纵向可穿戴/病历 + 人群统计）、领域专家（个人数据 × 健康知识；本研究病历仅限血检）、健康教练（动机访谈、目标与障碍）——再由编排器分配并综合。11 项基准、>7,000 条标注、1,350 小时专家/用户劳动。骨干是 Gemini 2.0 家族。作者强调不替代临床医师。开源。
- **单篇小结**：形态接近「把 Symptio 的问诊约束和骨髓瘤技能库拆成生活侧三个角色」。接到青光眼/nAMD 患教或依从性 Agent 时可抄：数字必须给数据科学槽、建议必须给教练槽，禁止通才一次生成「你的眼压该加药」。不是诊疗、没有眼底工具。

### 10. MMedAgent-Plus: Scaling Multimodal Medical Agents across Modalities, Tasks and Workflows

- **日期 / 来源**：arXiv 提交 **2026-10-19**；`2610.27233`。Duke / Stanford / Yale 等
- **链接**：https://arxiv.org/abs/2610.27233 · https://mmedagent.org
- **相关度**：方法可迁移（工具编排总管；**工具库含眼底分割 IterNet 与视网膜 OCT 报告 SpecialistVLMs**，但不是眼科专科系统）
- **摘要**：专科模型单任务强，通才 VLM 覆盖面宽但落后；二者都不会决定「该做哪一步、按什么顺序、中间结果怎么传」。MMedAgent-Plus 用视觉–语言规划器编排 18 个公开领先专科模型，覆盖 12 任务、8 模态（含眼底/OCT）。统一工具接口。规划器在 32 个公开医学基准的 208,928 条指令上微调。三套对话：单工具多轮工具调用准确率 **91.0%**，多工具多轮 **98.1%**，多工具单轮 **80.7%**。给定正确工具输出时，忠实/完整/简洁 14.4–14.8 / 15（600 例）。端到端 350 例、七任务：正确调用专科 90.6%，最终准确率 **0.98**，对齐领先专科、超过最强基线 0.28。错误集中在配准（UniGradICON 召回 0.36）和「该调工具却直接回答」。
- **单篇小结**：这是对 OphthaAgent「11 个预挂眼底工具」的跨科总管版。接到眼科工具注册表时应抄：规划器和专科头必须分开评；单轮组合最容易塌；「No tool」直答必须单独报。不要把 0.98 写成已经覆盖青光眼/黄斑裂孔临床路径——那是七个单工具任务的最终答案准确率。作者单位不是眼科中心，不计入本周「≥1 篇直接相关」的翻转条件（翻转已由条目 1–2 完成）。

### 11. BT-RADS 双 Agent、临床试验技能加载与肺癌筛查 CT 规划–执行

- **日期 / 来源**：2026-10-21 / 10-20 / 10-25；*Radiol Artif Intell* / *JMIR Form Res* / medRxiv
- **链接**：https://doi.org/10.1148/ryai.260234（PMID 42905016）· https://doi.org/10.2196/100769（PMID 42901481）· https://doi.org/10.64898/2026.10.02.26364620（PMID 42926850）
- **相关度**：方法可迁移（影像评分 Agent、按工作流拓扑加载技能、规划–执行答患者问；都不是眼科）
- **摘要**：**BT-RADS**（10/21）：抽取 Agent（gpt-oss-20B）从病历拉临床变量，评分 Agent 把变量和体积定量送进 BT-RADS 逻辑。492 次胶质瘤治疗后 MRI：系统准确率 **76.0%** vs 初始评估 57.5%（+18.5 个百分点，*P*<0.001），κ=0.71；本地开权推理。**临床试验技能加载**（10/20）：45 节点 / 7 层 DAG 挂 59 个 SKILL.md。拓扑路由在「必须靠图结构才能够着证据」的压力题上优于纯 BM25（差 0.348），低上下文调度器少注入 28.82% 仍保质量；词法已够着时，图不额外加分。**肺癌筛查 CT**：规划–执行多模态 Agent 答模拟患者问题，强调该调影像工具时才调、该交给医师的问题要会弃权（本窗口可见，完整数字见原文）。
- **单篇小结**：三条分别对应眼科的三件事——评分必须吃定量体积而不是再生成一段印象（接黄斑裂孔/青光眼分期）；抗 VEGF / CDISC 报表应按工作流拓扑加载技能，而不是把整本指南塞进提示；患教 Agent 必须有「这个问题该交给医师」的弃权槽。全部不是眼病终点。

### 12. Claude Duet、Agent Skills 捐赠与 Decisions API：本周是产品形态，不是新骨干

- **日期 / 来源**：Anthropic / OpenAI 官方 **2026-10-21～10-23**
- **链接**：https://claude.com/resources/articles/claude-duet · https://claude.com/resources/articles/claude-duet-safety-privacy-and-security · https://www.anthropic.com/news（Agent Skills → Agentic AI Foundation，10/22）· Claude API 版本 `2026-10-21`
- **相关度**：运行时（本周平台层增量；Argon GA / Muse Wonder / Astra 并行 Agent / Flash-1017 不重复）
- **摘要**：**Claude Duet**（10/21）：主动式个人 Agent 研究预览，美国 Pro / Max 候补。每天早报、隔数小时扫已连接应用、后台虚拟机继续干活；发送、付款、签署、删除前必须展示并等待批准；禁止证券交易和账户间转账。共享套餐用量，后台巡检也计费。安全页（10/23）加敏感信息分类器，且 Duet 看不到密码/cookie/登录令牌。**Agent Skills**（10/22）捐给 Linux 基金会下的 Agentic AI Foundation，官方称已有 70+ Agent 平台接入。Claude API 发布 **2026-10-21**（2023-06-01 仍可用）；新版 Messages API 去掉 temperature / top_p / top_k。Google Cloud 上 Anthropic 托管的 Claude Platform（含 Managed Agents）正式开放（10/22）。OpenAI **Decisions API**（GPT-6 Luna）正式开放：对有界问题返回概率/选择/分数，支持文本、图像和结构化输入，单请求最多 400 题，带 GPT-Live、提示缓存和美/欧驻留。Claude Code 增加 MCP Tasks / Elicitations（10/23），给长任务插件用。
- **单篇小结**：眼科科研 Agent 本周不缺新权重，缺的是**许可门和技能包标准**。Duet 不得写入院内 HIS——它是个人生产力预览，默认连的是邮箱和办公应用。Skills 捐赠意味着 GAO / 抗 VEGF / 黄斑裂孔报告槽可以按同一 SKILL.md 格式写，但院内仍须本地审查。Decisions API 更接近 StratCP / OphJev 的「有界决策层」，不要把它写成已经会看 OCT。API 2026-10-21 去掉采样参数，复现实验必须锁版本号。
