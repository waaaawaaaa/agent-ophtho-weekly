## 本周总结

未见新的眼科**诊断/分诊工具编排系统**新稿。连续跟踪的 AgentEYE、青光眼眼底 Agentic 框架 `2608.07651`、电话分诊 GAO-Triage `2608.04772v2` 本周无 v3 / 代码仓 / 期刊勘误。MICCAI 2026 *Agentic AI for Medicine* Workshop（会期 10/1）官网仍未公布录用名单；EyeAgent RCT（NCT07401459）仍为 Not yet recruiting。

结构分四层：

1. **直接相关**：眼科医师 × 编码 Agent（vibe coding 评论）。
2. **眼科相邻**：AMD 注视–口述共标注（Co-Annotator）、视网膜成像 MLLM 问答、角膜专科 RAG、眼底–OCT 对齐（CARE）、眼底推 RNFL 厚度图、眼底生物识别。
3. **方法可迁移的医学 Agent**：忠实度门控检索（MedAgent-R1）、糖尿病指南多智能体（DIASENTINEL）、全科动作空间基准（GPAgentBench-2K）、纵向病历记忆（ClinTraceBench / MedCache）、转诊图推理（MASGR）、影像 Agent 对伪造发现的顺从、多智能体「故障点」可被人带偏。
4. **运行时**：同一周连续发布 **Claude Fable 5.1**（9/1）、**Gemini 3.8 Flash**（9/2）、**GPT-6 Astra**（9/3）——旗舰变贵、Flash 级继续当 Agent 工作马、缓存读价被砍。

启示：眼科×Agent 本周的增量在**「谁来写工具」**而不在**「再做一个看图 Agent」**。对照前几周：专用工具定诊断上限、检索定审计、过程义务定何时停。本周补的是第三条腿——**工具本身可以由专科医生用编码 Agent 快速原型化**，但必须用风险分层把「注射间隔计算器」和「改处置建议」分开。视网膜 MLLM 仍明显弱于读图（全体错题都是看图题），角膜 RAG 抬诊断、不稳处置，正好说明 vibe coding 不该直接生成「下一步术式」。医学 Agent 侧则把「引用必须过硬门」「安全弃权是一等动作」「人在故障点插一嘴会改判」写成可测指标，可直接接到青光眼/分诊复现实验。上周已覆盖的 AgentEYE、GAO-Triage v2、EviDx / CDEG / LUCAID / STRIVE、Claude in Chrome 不再重复展开。

### 1. Vibe coding for ophthalmologists

- **日期 / 来源**：2026-09-03 电子出版；*Current Opinion in Ophthalmology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42687662/ · https://doi.org/10.1097/ICU.0000000000001250
- **相关度**：**直接相关**（本周主条目；眼科专科期刊明确讨论 LLM Agent 写代码）
- **摘要**：大模型催生了 vibe coding：用户用自然语言描述功能，与 **LLM Agent** 协作生成可运行代码。本评论从眼科视角问两件事：它在哪里增值、怎样用才算负责。现有平台已能让非程序员从提示词做出带登录与数据库的完整应用。作者认为最适合的切口是**商业产品看不上的亚专科小问题**——临床工作流、科研与医学教育工具。结论分层：不直接改临床决策的低风险应用，医师在一定条件下可独立部署；高风险应用 vibe coding 不能替代专业开发，但能加速实验、澄清需求、把想法做成可摸的原型。需要护栏才能在加速临床医生创新的同时保住安全与问责。作者 Antaki（Cleveland Clinic Cole Eye Institute）/ Bellanda / Keane / Ong。
- **单篇小结**：这是本窗口唯一「标题即眼科 × Agent」的正刊。它不跟 EyeAgent / AgentEYE 抢「53 个影像工具」，而是承认院内大量痛点（注射间隔、白内障滴药日历、教学病例库）太窄、厂商不做。对仓库的含义是：GAO 规则表、质控–分割–分类工具卡，都可以先用编码 Agent 做出可版本化原型，再决定要不要走正规工程与注册。部署门必须写进同一份评论——**能聊出代码 ≠ 能上临床**。

### 2. Co-Annotator: Expert-Distilled ViT and VLM for Visual and Documentation Guidance in Age-Related Macular Degeneration

- **日期 / 来源**：2026-08-31 提交 arXiv；`cs.CV` / `cs.HC`
- **链接**：https://arxiv.org/abs/2608.30352
- **相关度**：眼科相邻（AMD OCT；专家注视 + 口述蒸馏，**不是**工具编排 Agent）
- **摘要**：临床 AI 常只优化预测分，不管医生「看哪里、写什么」。Co-Annotator 把专家注视与口述蒸馏成两路引导：注视对齐的 ViT 给出注视对齐兴趣区（AOI）；受本体约束的 VLM 预填可编辑的视网膜 OCT 生物标志物摘要。先用专家注视/口述（US1）训练，再在住院医师对照（US2）证明两路各自安全、独立有益：AOI 带来可延续的知觉效率（撤引导后仍在），VLM 使生物标志物记录广度翻倍以上。两家学术机构联合部署（US3）同时给两路时，效率增益明显超过单路：每分钟正确诊断 **+40%**，评论编辑时间 **−67%**，诊断正确率不掉。作者强调：US2 单路引导期内并不省时，US3 组合引导期内就开始省时，说明「看对地方 + 预填可改的记录」必须一起上。
- **单篇小结**：这是本周最接近「人机共看 OCT」的眼科稿，但是**固定两路引导**，没有规划器选工具。接到 Agent 时，AOI 可当质控/定位工具，本体约束的预填可当报告槽；缺的是拒答与跨模态仲裁。对 nAMD 随访：先标 CST / IRF / SRF 再让 LLM 写印象，比开放生成「建议打针」更安全。也给 vibe coding 一个反例——住院医效率来自**专家蒸馏的窄工具**，不是聊天框里现编一个分割网。

### 3. Comparative performance of contemporary multimodal large language models in retinal imaging question answering

- **日期 / 来源**：电子出版 2026-08-20；*Frontiers in Medicine*；**本窗口 PubMed 索引**
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42694118/ · https://doi.org/10.3389/fmed.2026.1934968
- **相关度**：眼科多模态 LLM（非 Agent；本周最硬的「纯 VLM 看视网膜」对照）
- **摘要**：从 OCTCases 抽 78 例、226 道选择题（151 看图、75 纯文本），评 ChatGPT-5.5 Instant / Thinking、Grok 4、Gemini 3、DeepSeek V4、Kimi 2.5；答案键经 3 名视网膜专科复核。总体正确率 **59.3–77.4%**，Thinking 最高，Gemini 3 与 Instant 次之，DeepSeek V4 最低。所有模型都是**纯文本强于看图**；看图子集里 Gemini 3 最好。六家多数表决在 182/226 题上给出确定答案，这部分正确率 **89.6%**；全部六家都错的题**全是看图题**。延迟与对错无稳定关系。作者建议：表决一致可当可靠信号，不一致应升级专科；临床只能在专科监督下谨慎使用。温医大眼视光 / 复旦眼耳鼻喉。
- **单篇小结**：把上周 *Retina*「ChatGPT-4o 眼底 75%、其余 14–18%」推进到更新骨干，结论没变：**认字可以，认图不行**。89.6% 的多数表决不是部署方案，而是「何时升级」的门——六家打架就不要写诊断。对照 `2608.07651`：这些选择题应改成「先调 OCT 分层/病灶工具，再让 LLM 选」。电子出版早于本窗口，本周是索引可见。

### 4. Evaluation of a cornea-specialized large language model for diagnostic and management accuracy in complex corneal cases

- **日期 / 来源**：2026-09-02；*International Ophthalmology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42684491/ · https://doi.org/10.1007/s10792-026-04232-2
- **相关度**：眼科 RAG（非工具编排 Agent；对照「认病 vs 选下一步」）
- **摘要**：前瞻、随机、掩蔽：3 名角膜专科培训医师各评 39 例真实复杂角膜病例，条件为独立 / 通用 GPT-4o / 角膜专科 GPT-4o（把 200+ 篇公开 Wikipedia 嵌入 RAG）。每例最多问 3 次。诊断正确率从独立 48.7% / 20.5% / 38.5% 升到通用 GPT-4o 的 69.2% / 46.2% / 59.0%，专科 RAG 再升到 **71.8% / 48.7% / 74.4%**（相对独立均 p<0.01）。**下一步处置**则不稳定：一人升、一人维持高位、一人从 87.2% 掉到 64.1%。作者认为专科 RAG 主要帮基线弱的医师认病，处置任务还需开放式评测，并怀疑更小、经策展的检索库会更好。
- **单篇小结**：又一次「指南/百科对齐抬诊断、开放处置掉安全」。把整本 Wikipedia 塞进 RAG，不如 GAO 的 70 行规则表可审计。一人处置显著变差，说明 Agent 的处置槽必须是适应证计算器 + 红旗门，不能「再生成一个术式名」。基线弱者受益更大，适合做教学/初筛助手，不适合独立门诊。

### 5. CARE: Multimodal Alignment Learning for Ophthalmic Imaging via Joint Optimal-Transport Soft Matching and Graph Neural ODE Refinement

- **日期 / 来源**：2026-08-31；*Journal of Imaging Informatics in Medicine*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42675274/ · https://doi.org/10.1007/s10278-026-02184-8
- **相关度**：眼科多模态 CV（可作眼底–OCT 对齐工具，而非 Agent）
- **摘要**：单模态眼底或 OCT 都不够：CFP/NIR 有表面形态、缺深层结构；OCT 有分层、缺全眼底概貌。隐式注意力融合缺少双侧边缘约束，噪声下容易被单一模态主导。CARE 用熵正则最优传输建软对应，再用图结构 + 图神经 ODE 迭代对齐，并加模态耦合对比学习。GAMMA 上 ACC/Kappa **0.860 / 0.893**，OLIVES 上 **1.000 / 1.000**（公开划分），噪声与少样本设置下仍稳。
- **单篇小结**：AgentEYE / EyeAgent 缺的往往不是「再接一个分类头」，而是**眼底 token 和 OCT 层对得上**。CARE 可当跨模态对齐工具：先对齐再让规划器决定调分割还是调分期。OLIVES 满分按公开划分，外推前先看跨中心，不要写进注册文件当已验证临床性能。

### 6. Deriving OCT-Equivalent Retinal Nerve Fiber Layer Thickness Maps from Fundus Photographs with Deep Learning Improves Glaucoma Diagnosis

- **日期 / 来源**：电子出版 2026-07-15；*Ophthalmology Science*；**本窗口 PubMed 索引**
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42699245/ · https://doi.org/10.1016/j.xops.2026.101325
- **相关度**：眼科专用 CV 工具（可替换进青光眼 Agent 的「结构槽」）
- **摘要**：麻省眼耳 15,031 对眼底–OCT，U-Net 从彩色眼底预测像素级 RNFLT 图（MAE 15.4 μm，SSIM 0.65）。青光眼（Humphrey 24-2）检测：预测 RNFLT 单独 AUC **0.889**，优于纯眼底 0.883，弱于真 OCT RNFLT 0.903；眼底 + 预测 RNFLT 融合 AUC **0.909**，超过所有单模态。增益主要在早期：轻度准确率 55.3%→64.0%，中度 71.5%→80.4%，重度 90.0%→94.6%。作者强调输出是**整张厚度图**而不是一个平均 RNFL 数。
- **单篇小结**：`2608.07651` 目前用分类头 + 杯盘分割估 CDR。这篇提供「没有 OCT 时的结构代理」，适合筛查 Agent 的第二工具，但必须在工具卡上写：**代理厚度 ≠ 真 OCT**，不能当手术/降眼压依据。早期病例增益最大，正是普查要的那一段。电子出版早于本窗口（*Ophthalmology Science* 2026 年 10 月期，101325），本周是索引可见。

### 7. Robust retinal biometrics for patient identity verification and retrieval across age and imaging devices

- **日期 / 来源**：2026-08-31；arXiv `cs.CV`
- **链接**：https://arxiv.org/abs/2608.31094
- **相关度**：眼科身份工具（可作纵向 Agent 的「是不是同一个人」门）
- **摘要**：患者身份错误会污染纵向病历与下游决策。作者在鹿特丹研究 227,004 张图、21,851 个患眼身份上训练 512 维度量学习编码器（ConvNeXtV2 + ArcFace + triplet），跨设备、最长随访 32.6 年。用模型先筛身份不一致再人工裁决，发现鹿特丹 / UK Biobank / AREDS 分别有 **0.588% / 0.259% / 0.164%** 错挂。去近重复后验证 AUROC 均 ≥0.9997；仅用历史图做检索，Recall@1 为 99.7% / 97.2% / 97.6%（库均 4436–8510 身份），Top-5 至少 98.6%。
- **单篇小结**：上周 OCT 反事实编辑已经证明「改像素会改身份」。这篇把身份核验做成可调用工具：随访 Agent 在写「较前片进展」之前，先过这道门。0.2–0.6% 的公开队列错挂也提醒：评测集金标准本身可能脏，Agent 的外部分要能标「身份存疑」而不是硬对标签。

### 8. MedAgent-R1: Faithfulness-Aware Reinforcement Learning for Evidence-Grounded Medical Reasoning

- **日期 / 来源**：2026-08-31；arXiv
- **链接**：https://arxiv.org/abs/2608.30676
- **相关度**：方法可迁移（检索 Agent 的忠实度门；直接对照 AgentEYE「检索换可审计」）
- **摘要**：只奖正确率的 RL 检索 Agent 会学「先靠参数记忆答题，再补看起来像引用的理由」，作者称为 **confident hallucination**：准确率相对监督基线 +5 个百分点，引用编造率却从 16.5% 升到 **31.8%**。MedAgent-R1 把准确率积分做成**硬门**：证据没接地就不给分，再加检索有效与简洁信号。编造率降到 **4.7%**，证据完整度 58.7→82.6，准确率仍 75.1%；HealthBench Safety +13.2。同一套 agentic 检索下，忠实度维超过 GPT-4o（Factual Support 4.55 vs 4.25）。
- **单篇小结**：这是对 AgentEYE 消融的定量补丁：检索若只优化诊断分，会把幻觉写得更像指南。眼科报告 Agent 的奖励必须拆栏——正确 / 可核引用 / 安全——引用编造单独计，不能被总分淹没。复现 GAO 或指南 RAG 时，先复现这条「关掉忠实度门，编造率会翻倍」的对照。

### 9. DIASENTINEL: An Auditable Multi-Agent System for Guideline-Grounded Diabetes Risk Screening

- **日期 / 来源**：2026-08-31；arXiv
- **链接**：https://arxiv.org/abs/2608.31128
- **相关度**：方法可迁移（指南接地、可审计、本地部署；病种近邻是 DR / 糖尿病眼病）
- **摘要**：面向一年期 2 型糖尿病风险筛查与指南接地报告：校准风险预测、确定性临床信号抽取、对 ADA 指南做 Reciprocal Rank Fusion，再用规则 + LLM 蕴含的混合校验层。全程本地、可看引用、可对原始 EHR。演示含批量筛查仪表盘与带引用/校验/原始记录对照的患者报告。
- **单篇小结**：架构几乎是「GAO 规则表 + AgentEYE 引用审计」的代谢病版，而且强调**院内部署**。眼科筛查（DR 分级、青光眼转诊）可直接抄三件套：确定性信号抽取、指南融合检索、规则/蕴含双校验。不要把糖尿病风险分外推成视网膜病变分期；可复用的是审计界面，不是模型权重。

### 10. GPAgentBench-2K: Benchmarking Large Language Model Agents in Complex Clinical Action Space

- **日期 / 来源**：2026-08-31 提交，2026-09-02 v2；arXiv
- **链接**：https://arxiv.org/abs/2608.30188
- **相关度**：方法可迁移（临床 Agent 基准；动作成一等公民，含安全弃权）
- **摘要**：现有医学基准不是静态预测，就是动作集过粗的无约束 MDP。GPAgentBench-2K 用经专家校验的真实全科就诊，做成**约束 MDP**：六类基础临床动作、动作空间上的拓扑工作流先验，并把**安全知情弃权**写成一等结局。评 16 个前沿 LLM：动作空间变大则表现明显掉。即使诊断准确率最高的旗舰模型，在高风险病例上违反安全约束也超过一半。C-GRPO 相对无约束 RL 有改善，但仍远达不到可接受的临床安全。
- **单篇小结**：眼科电话分诊 / 门诊 Agent 不该再只报「与参考一致率」。应同时报 Emergent 召回、违规处置率、以及「该弃权却给了 Routine」的比例。拓扑先验 = 把 AAO 路径写成「先问红旗再定级」的合法动作顺序，和 GAO 规则表是同一件事的环境版。

### 11. ClinTraceBench: Source-Verifiable Longitudinal Clinical Reasoning over EHR-Derived Dialogues

- **日期 / 来源**：2026-09-01；arXiv
- **链接**：https://arxiv.org/abs/2609.01111
- **相关度**：方法可迁移（纵向病历记忆；青光眼/注射随访同构）
- **摘要**：临床助手要在多次就诊上推理，但检索、时间线、LLM 摘要、agentic 记忆会不会丢掉纵向信号，此前没被测。ClinTraceBench：385 段经核验的 MIMIC-IV 对话、事件 ID 溯源、九任务分类、L0–L5 校验（与人工一致率 98.92%）。八种历史表示 × 四骨干，32 格、200,672 次预测。关键发现：即使归因句在构造前就在原文里，Mem0 / A-Mem / llm-summary 仍会丢掉关系——压缩会吃掉「谁在何时因为什么」。
- **单篇小结**：nAMD「上次打针后 CST 降了没有」、青光眼「这次 RNFL 相对去年」都是关系，不是关键词。Agent 记忆不能只存摘要。应强制事件级溯源：每条印象必须能点回某次 OCT/视野的原始数字。通用 agentic 记忆库（Mem0 等）在临床上先当阴性对照。

### 12. MedCache: Efficient and Temporally Valid Memory for Longitudinal Clinical Agents

- **日期 / 来源**：2026-08-30 提交；本窗口内仍为新稿，既有 reports 未展开
- **链接**：https://arxiv.org/abs/2608.29528
- **相关度**：方法可迁移（纵向临床 Agent 的记忆设计）
- **摘要**：在多就诊、多专科病历基准上系统比较记忆的策展、组织、检索与记忆增强推理。结论：时间有效性比「留得更多」重要；按专科切分能减上下文，但会藏共享证据；多智能体只在专科必须一起推理时才有用，而不是「有多块记忆就克隆多个 Agent」。MedCache 据此做混合框架：构造时间有效的患者记忆，组织成重叠专科视图，按查询路由，并自适应调用单专科或多专科。
- **单篇小结**：眼科「视网膜 + 青光眼 + 角膜」共病很常见。记忆应按时间有效窗口切（停用的滴眼液不要永远占上下文），专科视图要允许重叠（激素性青光眼必须同时出现在葡萄膜炎和青光眼视图）。不要为每个亚专科复制一个会聊天的 Agent。

### 13. Evidence, Logic, and Compliance: Multi-Agent Structured Graph Reasoning with Expert Arbitration for Medical Referral（MASGR）

- **日期 / 来源**：2026-08-31；arXiv
- **链接**：https://arxiv.org/abs/2608.30938
- **相关度**：方法可迁移（转诊/分科多智能体；可对眼科急诊分诊）
- **摘要**：转诊要综合主诉、化验与影像。现有 LLM 容易盯高频病名、漏紧急信号，多智能体闲聊又会语义漂移和确认偏误。MASGR 把转诊写成**结构化图构建**：各模态专科 Agent 抽证据，必须在图上为冲突证据建显式逻辑边，再经专家仲裁，而不是松散对话投票。
- **单篇小结**：眼科急诊（闪光 + 视野缺损 vs 「飞蚊变多」）失败模式就是盯常见词、漏急症。把冲突写成图上的边（「主诉闪光」vs「眼底未见脱离」）再仲裁，比让三个角色各写一段更可审计。可先在红眼/闪光分诊上做规则图，不必上多模态大模型。

### 14. Source-Dependent Deference in Medical Imaging Agents Under Falsified Findings: A Pilot Audit

- **日期 / 来源**：2026-08-30；arXiv
- **链接**：https://arxiv.org/abs/2608.29800
- **相关度**：方法可迁移（医学影像 tool-calling Agent 的顺从审计）
- **摘要**：工具返回错误发现时，Agent 会不会放弃自己已经做对的答案？在 20 道 VQA-RAD 封闭题、四个厂商档位上：Agent 先只看图作答，再分别接收「自己调用的 analyze_image 返回的 JSON 否定发现」或「被写成放射科医师引语的散文否定」。最强档位上，散文归因使 13 例中 10 例改掉正确答案，工具 JSON 仅 1/13（精确 McNemar p=0.0039）。作者承认来源标签与通道绑定，且工具通道只有调用时才看得到，因此不能单独归因「放射科」三个字。
- **单篇小结**：眼科 Agent 一旦把「某专家说是青光眼」写进上下文，模型可能推翻自己已经对的杯盘工具输出。护栏应是：**工具 JSON 与人的口头意见分栏，冲突则升级，禁止用散文覆盖数字**。这也解释了为何 MedAgent-R1 要把忠实度做成硬门——通道本身就会改判。

### 15. Examining the Vulnerability of Multi-Agent Medical Systems to Human Interventions for Clinical Reasoning

- **日期 / 来源**：2026-09-02；arXiv
- **链接**：https://arxiv.org/abs/2609.02191
- **相关度**：方法可迁移（多智能体在「故障点」可被人带偏或纠偏）
- **摘要**：在 MedQA 模拟医患对话里定位 Agent 推理最容易被外部影响的故障点。正确干预最多可把基线诊断准确率抬 **+40%**；错误或带偏干预最多降 6%，并增加诊断漂移与不确定。行为上出现与真实临床类似的过早闭合、被误导线索带走。作者认为识别并引导故障点，可能成为提高多智能体稳健性的机制。
- **单篇小结**：双刃剑：护士/低年资医师在故障点插一句可以救命，也可以把三个 Agent 一起带进沟。眼科联合会诊式 Agent（上周审议委员会稿的近邻）必须把「谁在哪一步插话」写进日志，并单独测「错误提示下是否改判」。不能假设多 Agent 投票就能抗提示注入。

### 16. Claude Fable 5.1、Gemini 3.8 Flash、GPT-6 Astra：一周内的 Agent 运行时换代

- **日期 / 来源**：官方 2026-09-01 / 09-02 / 09-03
- **链接**：https://platform.claude.com/docs/en/release-notes/overview · https://blog.google/innovation-and-ai/models-and-research/gemini-models/3-8-flash-and-3-8-flash-cyber/ · https://openai.com/index/gpt-6-astra/
- **相关度**：方法可迁移（通用 Agent 骨干与成本；决定眼科流水线谁干活）
- **摘要**：Anthropic 于 9/1 发布 Claude Fable 5.1（及受限的 Mythos 5.1）：默认 1M 上下文、强调长程 agentic 编码与知识工作；标价仍约 **$10 / $50 / 1M**，但缓存读降到 **$0.25 / 1M**（官方估计高 Agent 负载最多可省约 45%）。Google 于 9/2 发布 Gemini 3.8 Flash / Flash Cyber：定位继续是工作马，引入价仍约 **$0.75 / $3.75 / 1M**（至 2026-12-31），强调 agentic 与多步推理；Cyber 变体经 Fairwind 给可信防御方。OpenAI 于 9/3 发布 GPT-6 Astra：自称 computer / browser use 与软件工程新高，Agents' Last Exam 等自报分高于 Sol / Fable；API 约 **$10 / $50 / 1M**、上下文约 1.05M；是其准备框架下首个标到 **Critical 网络安全能力** 的广泛部署模型，高级网络能力先走 Trusted Access / Daybreak。Tech 报道同时指出 Astra 使用不透明 recurrence，削弱可审计 CoT。
- **单篇小结**：眼科多工具 Agent 的高频质控/分割/JSON 填槽，应继续默认 Flash 级；旗舰留给疑难终审、指南冲突与安全相关决策。Fable 5.1 的缓存读降价让「整本 AAO PPP 当前缀」变得便宜，但仍应把规则表编成 Skill，而不是每次塞 PDF。Astra 的 computer use 分数上升，**不等于**可以去点真实 PACS；Critical 网络能力反而要求院内部署把域名白名单和动作预审写死。不透明推理对「可审计眼科报告」是减分项——引用与工具日志必须独立于模型内心独白。

### 17. （对照跟踪）既有眼科×Agent 硬核稿与会议/试验

- **日期 / 来源**：2026-08-05 / 08-07 / 08-18；本窗口**无新版本**
- **链接**：https://arxiv.org/abs/2608.04772 · https://arxiv.org/abs/2608.07651 · https://doi.org/10.1016/j.xcrm.2026.102969
- **相关度**：直接相关（连续跟踪，非本周新稿）
- **摘要**：GAO-Triage（`2608.04772v2`）用 AAO 规则表零对话标注训练眼科电话分诊 Agent。青光眼眼底 Agentic 框架（`2608.07651`）用 LLM 初判 + 质控/分类/分割 + 反思。AgentEYE（*Cell Reports Medicine*）路由眼底/B 超工具并检索指南写可审计报告。LUCAID（`2608.23803`）于 8/31 出现 v2，摘要主数字未改（前瞻可操作决策一致率 93.0%），不单独展开。
- **单篇小结**：三篇眼科硬核稿本周仍无代码仓或外部分。本周新出的 RNFLT 代理图、CARE 对齐、Co-Annotator AOI，应视为可替换工具/引导卡。vibe coding 评论则提示：这些工具的「院内胶水代码」可以由眼科医生先原型化，但评测与监管仍走正式路径。
