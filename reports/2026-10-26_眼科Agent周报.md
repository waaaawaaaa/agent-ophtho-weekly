### 1. An Agentic AI Workflow for Automated Macular Hole Diagnosis and Structured Report Generation

- **日期 / 来源**：2026-10-23；*Ophthalmology and Therapy*（开放获取）。Moorfields / UCL / Inselspital Bern / Ophthalmic Surgical Intelligence Lab（Carla Troyas / Lorenzo Ferro Desideri / Neil Shah / Inès Schumacher / Martin Zinkernagel / **Rodrigo Anguita** 通讯）
- **链接**：https://doi.org/10.1007/s40123-026-01523-w · https://pubmed.ncbi.nlm.nih.gov/42909794/
- **相关度**：**直接相关（本周主条目）**——编排 Agent 调 RETFound-OCT 做黄斑裂孔二分类，再调 GPT-4 写结构化患教报告
- **摘要**：现有 OCT AI 多半停在单次诊断，和虚拟门诊要写的患教信断开。作者做了一条由 workflow orchestration agent 串起来的顺序工作流：先把 RETFound-MAE 的 OCT 分支微调成「MH / 正常黄斑」二分类，再把**只含诊断结果**的结构化提示交给 GPT-4（Chat Completions）写含诊断、一般处理和主要手术风险的患教报告。训练/验证/内测用 CHU、OCTDL、OCTID、Kermany 等公开集，**按患者分层**划分（训练 691 MH + 897 正常；验证 150 / 216；内测 130 / 50）；外验用 OIMHS（563 MH）和 Noor Eye Hospital（451 正常）。内测 n=180：准确率 / 灵敏度 / 特异度均为 **100%**（Wilson 95% CI 准确率 97.9–100%），AUC 1.00，无误分。外验 n=1,014：准确率 **98.8%**（97.9–99.3%），灵敏度 97.9%（96.3–98.8%），特异度 **100%**（99.2–100%），AUC **0.999**（0.998–1.000）；12 张 MH 漏诊、0 张正常误报。Grad-CAM 主要落在裂孔及邻层；参数随机化后与训练图相关仅 −0.15，删除高贡献像素后 MH 概率下降。40 份外验报告（20 MH / 20 正常）由两名眼科医师三档评分：双评一致 92.5%，**37/40（92.5%）** 评为准确且充分；不准确的两份把白内障写成黄斑裂孔手术「较少见」并发症，不充分的一份漏了视网膜脱离和眼压升高。提示词参考 Moorfields 标准化文书，但**不含视力、症状时长等个体因素**。代码「合理请求可提供」，未放公开仓。
- **单篇小结**：这是对上周 GUIDE「诊断/证据和终稿分权」的玻璃体视网膜版——**RETFound 只许分类，GPT-4 只许复述分类**。可搬的不是 98.8% 这个绝对分（外验两套数据各自只有一个病种，扫描仪/人群可能混杂；二分类、单张 2D B-scan、未分期、未和板层裂孔/假孔鉴别），而是三张表：编排 Agent 不得让语言模型看图；报告错误必须按「诊断错 / 信息不够 / 风险写错」分栏；外验必须同一套里既有阳又有阴。接到 OphthaAgent / FFA-SegGPT / EyeGraph 的报告槽时，应禁止端到端 VLM 一次出诊断+患教。不要把「虚拟门诊可行」写成已经进了 Moorfields 工作流，更不要和 OphthaAgent（多轮眼底工具）或 OphthaReason（看图推理）混名。

### 2. GLLaucoMed: A Secure Large Language Model-Powered Agentic Workflow for Automated Medication Extraction from Free-Text Glaucoma Clinical Notes

- **日期 / 来源**：电子出版 **2026-08-17**；本窗口 *Ophthalmology Science* 11 月刊 / PubMed 索引（entrez **2026-10-25**）。Bascom Palmer（Nicholas Solages / Rafael Scherer / Felipe A. Medeiros / **Swarup S. Swaminathan**）。medRxiv 曾于 6/15 预印
- **链接**：https://doi.org/10.1016/j.xops.2026.101366 · https://pubmed.ncbi.nlm.nih.gov/42927148/
- **相关度**：直接相关（青光眼病历的 agentic 抽药；**本窗口仅期刊索引，非新投稿**）
- **摘要**：从 Bascom Palmer Ophthalmic Repository 抽 1,250 名青光眼患者 2014–2024 年自由文本病历，两名青光眼专科标注、第三人仲裁：当前局部药（CTM）、拟改局部药（ΔTM）、当前口服药（COM）、拟改口服药（ΔOM）。按医师分层 10/10/80 划分；开发/验证只做提示工程，测试集盲评。五模型走 Microsoft Azure AI Foundry 的 HIPAA 环境：Claude Opus 4.6、DeepSeek-V3.2、GPT 5.2、Grok 4.1、Qwen3.6-35B-A3B。Gwet AC1：CTM 0.799、ΔTM 0.888、COM 0.985、ΔOM 0.988。CTM F1：Claude **0.985** / DeepSeek 0.971 / GPT 0.978 / Grok 0.968 / Qwen 0.970；ΔTM 0.905 / 0.826 / 0.897 / 0.842 / 0.865；COM 0.923 / 0.887 / 0.899 / 0.906 / 0.894；ΔOM 0.958 / 0.815 / 0.937 / 0.835 / 0.940。阳性例精确匹配：CTM 0.730–0.882（JI 0.809–0.918），ΔTM 0.619–0.780。公开叙述还写了抽取 → 引用校验 → 条件改写、再经 Drugs@FDA 商品名转通用名的三阶段管线。Claude 与 GPT 最强。

### 3. Performance of Frontier Multimodal Large Language Models on Ophthalmology Cases

- **日期 / 来源**：2026-10-22；*JAMA Ophthalmology*。University of Toronto / St. Michael's（Kaleem / Mihalache / Popovic / **Rajeev H. Muni**）
- **链接**：https://doi.org/10.1001/jamaophthalmol.2026.4512 · https://pubmed.ncbi.nlm.nih.gov/42911566/
- **相关度**：眼科相邻（通才 MLLM 在扩充 OCTCases 上的病例问答；**不是**工具编排或诊疗 Agent）
- **摘要**：眼科依赖多模态影像；任务型 AI 在限定任务上已较强，但通才 LLM 仍随任务/亚专科波动。2024 年 ChatGPT-4 在 OCTCases 429 题上正确 **299（69.7%）**，图像题更弱。本横断面研究用扩充后的 OCTCases 题库，成对比较 ChatGPT-5.2 Instant、Gemini 3.1 Pro、Claude Opus 5.0，并另比 ChatGPT-5.2 vs ChatGPT-4；覆盖 OCT 图像题与纯文本题。公开摘要未放出分模型准确率；全文数字引用前须对原文表。
- **单篇小结**：位置正好接在本周主条目之后——**通才 MLLM 还在 OCTCases 上追 2024 年的 69.7%，专用 RETFound 已经在 MH 二分类外验到 98.8%。** 接到虚拟门诊时应禁止用 ChatGPT-5.2 / Gemini / Opus 直接读 OCT 出诊断；只许它们在诊断锁定后写患教（和条目 1 同一纪律）。不要把「前沿多模态」写成已经能替阅片。

### 4. RetiJev: Fast and Source-Grounded Ophthalmic Decision Models

- **日期 / 来源**：arXiv 提交 **2026-10-22**；`2610.30947`。Bo Liu / Lianyu Wang / Meng Wang / Ching-Yu Cheng / Huazhu Fu
- **链接**：https://arxiv.org/abs/2610.30947 · 代码：https://github.com/Awenbocc/RetiJev
- **相关度**：眼科相邻（源接地的眼科**决策模型**，不是工具 Agent；接上周 OphJev）
- **摘要**：眼科临床决策要快、准、可本地部署；自回归 LLM 在预定义动作上延迟和算力都高。作者先做 RetiJev-Data：从 PMC 文章和 531 种眼病 MeSH 抽出 78,158 道临床决策/诊断题，加 11 套分级系统的 50,074 道分级题，评测集 24,662 题。再训 0.8B–9B 的 RetiJev，直接给候选答案打分、不做自回归解码。全尺寸在指南分级上比 27B LLM 和商业 Jev 1.13 高 **10.4–23.0** 分；RetiJev-9B 临床决策再高 5.4–6.5 分，诊断打平。单 GPU 一例 **158 ms**，比 LLM 生成快 3.5×、比推理模型快 470×。
- **单篇小结**：上周 OphJev 是「终点感知的 System One / 选择性通才」；本条把同一想法写成可发布的小决策模型。接到 GAO-Triage / 青光眼 FAQ / 糖网患教时应先问「动作空间是不是已经封死」——封死了就不要上自回归 Agent。不是诊疗 Agent，不另计直接相关。

### 5. A Visual Grounding Benchmark for Retinal OCT with Multimodal Large Language Models

- **日期 / 来源**：arXiv 提交 **2026-10-22**；`2610.31205`。Fecso / Morano / Fazekas / Pollreisz 等
- **链接**：https://arxiv.org/abs/2610.31205
- **相关度**：眼科相邻（OCT 生物标志物视觉接地基准；证明通才 MLLM **还不会指回病灶**）
- **摘要**：可信的 OCT MLLM 必须能把报告里的病灶框出来，而不是靠捷径答题。RetinaGroundBench：815 张 B-scan，眼科医师穷尽标注 4,537 框，覆盖 8 病 13 种生物标志物。因模型常把一个病灶拆成多个残框，作者提出 AggIoU（重叠预测并集是否盖住金标准）。27 个开源 MLLM（0.8–38B）：最好通用模型 grounding 宏 F1 仅 **23.7%**，召回持续偏低，但生物标志物「在不在」题平衡准确率可到 **73%**。针对 OCT 微调的 8B RetGrounder 把 grounding F1 抬到 **33.9%**（相对 +43%）。
- **单篇小结**：这是对上周 *BMJ HCI*「发现–部位–变化三元组」和 FFA-SegGPT「先分割后写字」的 OCT 定量页——**会答题 ≠ 会指病灶**。接到条目 1 的报告槽或 EyeGraph 时，应把 grounding F1 写成门槛，而不是再报一张存在性准确率。33.9% 仍然低，不要写成已经可部署。

### 7. Visual alert integration with a time out monitor improves utilisation of an AI safety authentication system in ophthalmic surgery

### 8. The anatomy of a personal health agent

- **日期 / 来源**：2026-10-21；*Nature*（开放获取）。Google 组（Heydari / Gu / Srinivas / Yu / Paruchuri / Xin Liu / Daniel McDuff / Xuhai Orson Xu 等）
- **链接**：https://doi.org/10.1038/s41586-026-11161-8 · https://pubmed.ncbi.nlm.nih.gov/42907512/
- **相关度**：**方法可迁移（本周正刊主对照）**——消费级多 Agent 健康副驾驶；病历目前只接到血检，不是眼科
- **摘要**：用户旅程四条：一般健康知识、个人数据解释、健康建议、症状评估。对应三个子 Agent：数据科学（纵向可穿戴 + 人群统计，数字必须能跑代码）、领域专家（可穿戴 + 知识 + 血检）、健康教练（动机访谈、目标、障碍）。编排器分解问题、分配、反思、写记忆。骨干是 Gemini 2 Flash/Pro，重点是系统而不是新权重。11 项基准、>7,000 条标注、1,350 小时（终端用户 651 + 专家 699）。教练 Agent vs 同骨干基线：流程/动机访谈/反馈处理均显著更好，六主题五胜（61–71%）。整合 PHA vs 单 Agent PHIA vs 三子 Agent 并行：45 名终端用户把 PHA 列为总体第一 **46.7%**（并行 28.9%，PHIA 24.4%）；3 名专家给 PHA 总体质量 **72.8%** vs 并行 64.3% / PHIA 54.4%，并把 PHA 排第一的比例约 2× 并行、5× PHIA。迭代编排的调用次数和延迟反而低于静态并行。作者明确：PHA **不能**替代诊断，症状评估仍须转诊。
- **单篇小结**：这是对「再拆一个角色就会更好」的消费级对照——**编排 + 记忆赢了并行堆砌，而且更便宜。** 接到青光眼/nAMD 随访或 AI-TEC 患教时应抄：数字走数据科学 Agent、建议走教练、诊断不得由通才签发。血检 ≠ EHR；不要把 *Nature* 封面写成已经能接眼底/OCT 轨迹。

### 9. MMedAgent-Plus: Scaling Multimodal Medical Agents across Modalities, Tasks and Workflows

- **日期 / 来源**：arXiv 提交 **2026-10-19**；`2610.27233`。Duke / Stanford / Yale 等（Wang / Pan / Li / Dong / Yixin Wang）
- **链接**：https://arxiv.org/abs/2610.27233 · https://mmedagent.org/
- **相关度**：方法可迁移（通用医学工具 Agent；**工具库含眼底分割 IterNet 与 OCT 报告 SpecialistVLMs**，视网膜模态相对通才基线增量最大）
- **摘要**：专科模型单点强、通才 VLM 覆盖面宽但落后；二者都不会决定「下一步该调谁」。MMedAgent-Plus 用视觉–语言规划器编排 18 个公开领先专科工具、12 任务、8 模态（文本 / CT / MRI / X 线 / 超声 / **眼底 / OCT** / 病理）。规划器在 32 个公开基准的 208,928 条指令上微调。Tool-call：单工具多轮 **91.0%**、多工具多轮 **98.1%**、多工具单轮 80.7%。给定正确工具输出时，忠实/完整/简洁 14.4–14.8 / 15（600 样本）。端到端 350 例、7 任务：必调专科召回 **90.6%**，最终答案准确率 **0.98**（对齐专科、基线最强仅 0.28）。眼底通才基线都 <50%，编排后接近 100%；OCT 报告同样拉开。眼底分割 IterNet 端到端调用准确率 82.0%（69.2–90.2%）。失败模式：重叠模态工具互相抢、用户没明说的中间步被跳过。
- **单篇小结**：形态上接近把 OphthaAgent 的「11 个眼底工具」扩成全科工具箱。可搬的是统一工具接口和「先报 tool-call 再报终答」；不可搬的是把 0.98 写成已经能做黄斑裂孔/青光眼诊断——视网膜槽目前是血管分割和 OCT 报告，不是 MH/DR 分期。接到条目 1 时应把 RETFound-MH 注册成可替换专科，而不是再训一个通才规划器。不计入「≥1 篇眼科专用新 Agent」，因为主评测是跨科编排。

### 10. Agentic artificial intelligence for code status extraction from clinical notes；以及试验数据管线的拓扑技能装载

- **日期 / 来源**：2026-10-20；*JAMIA* / *JMIR Formative Research*
- **链接**：https://doi.org/10.1093/jamia/ocag179（PMID 42901486）· https://doi.org/10.2196/100769（PMID 42901481）
- **相关度**：方法可迁移（再叠 Agent 不加分；技能要按工作流拓扑装，而不是整库灌进上下文）
- **摘要**：**代码状态抽取**：1,000 份 MIMIC-IV-Note 出院小结，抽 DNR / DNI / CMO。三种架构（单抽取、自反思、抽取–审稿多 Agent）× 四开源模型。对 GPT-OSS-20B / MedGemma-27B-IT / Qwen3.5-27B，单 Agent 已够，多 Agent 令牌和延迟约翻倍且不涨点；MedGemma 的自反思反而伤 DNI（*P*=0.047）。只有 8B Distill 被审稿显著纠正，但整体仍不到临床可接受。**试验管线**：45 节点 / 7 层 DAG 挂 59 个 SKILL.md；按拓扑装载的上下文评分 4.63 vs 只写领域提示的 4.20（差 0.43，Holm *P*=0.01），但不优于扁平/随机装载；低上下文调度器少用 **28.82%** 上下文且质量不掉，559 个注入片段全部有源。
- **单篇小结**：上周 MedicalAgentsBench 说「推理骨干和脚手架要叠」；本条补一句——**能干的模型上，再叠审稿 Agent 只烧钱。** 技能条则和本周 Anthropic 把 Agent Skills 捐给 AAIF 对上：眼科指南/抽药/报告技能应写成可路由的 SKILL.md，而不是一次塞进 1M 窗。都不是眼病终点。

### 11. Agentic Automation of BT-RADS Scoring；多 Agent 幻觉对照与医学 AutoML

- **日期 / 来源**：2026-10-19～10-21；*Radiology: Artificial Intelligence* / arXiv
- **链接**：https://doi.org/10.1148/ryai.260234（PMID 42905016）· https://arxiv.org/abs/2610.27027 · https://arxiv.org/abs/2610.28410 · https://arxiv.org/abs/2610.25069
- **相关度**：方法可迁移（影像随访多 Agent；协作不自动更诚实；AutoML Agent 会选架构但校准仍可能崩）
- **摘要**：**BT-RADS**（10/21）：抽取 Agent（gpt-oss 20B）从病程读临床变量，评分 Agent 结合体积做胶质瘤治疗后 MRI 分层。492 例可评，系统准确率 **76.0%** vs 初评 57.5%（+18.5 个百分点，*P*<0.001），κ 0.71；BT-4 PPV 92.9%，BT-3b 灵敏度仅 57.1%。**幻觉**（`2610.27027`，10/19）：四系统 × 四模型 × 三临床任务，在**理由**里按事实性/忠实性打幻觉——36 组可分辨比较里 8 组升、4 组降，方向由模型决定，拓扑几乎不决定；能被协作降幻觉的模型，自纠时也降得最多。**MedicalMLOmni**（`2610.28410`，10/20）：多 Agent AutoML，用已发表结果做证据规划 + 并行超参；20 个基准赢 19。**Auto-MD-bench**（`2610.25069`，10/18 窗口边缘）：15 个真实医学建模任务上，最强自主科研 Agent 的区分度够、**校准不如简单基线**。
- **单篇小结**：BT-RADS 可对 nAMD / 青光眼随访的「分层 + 用药 + 影像趋势」抄结构，但 3b 这种阈值档必须单报。幻觉条禁止再写「多 Agent 更安全」——先换/测骨干。Auto-MD-bench 则接 GUIDE：主指标好看不等于风险校准能进院。

### 12. Anthropic 把 Agent Skills 捐给 AAIF：运行时增量是标准归属，不是新骨干
