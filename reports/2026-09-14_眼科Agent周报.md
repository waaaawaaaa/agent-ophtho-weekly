检索窗口 **2026-09-07～2026-09-13**。按既定口径（标题/摘要同时出现 Agent / Agentic / multi-agent / tool-using LLM agent，以及 ophthalmology / ophthalmic / fundus / OCT / glaucoma / retina），本周有 **两条直接相关增量**，其中更重的是期刊评论正刊：

1. **AI-TEC**（清华戴琼海 / 王雅星 / 吴嘉敏 / Tien Yin Wong 等，*Nature Medicine* 2026-09-10）：北京清华长庚医院自 **2025 年 11 月** 起把「AI-Agent Augmented Tsinghua Eye Clinic」嵌进真实门诊——预问诊、分诊、多模态精诊、决策支持与随访管理由多个专科 Agent 串起来，而不是再挂一批互不相通的筛查模型。文章是 Comment，**没有给出诊断准确率或 RCT 数字**；核心主张是：算法进院后，评价要从「这个模型准不准」改成「有没有改工作流、转诊、治疗与结局」。
2. **Moorfields / UCL 的 Keane 组**在 *Journal of Medical Internet Research* 评了一套 **Claude Agent**（Chat / Code / Cowork 三模式）对公开 **湿性 AMD（nAMD）12 年队列**做临床数据分析：从「只给原始表、自己出题」到「自写统计计划再执行」再到「按研究者写好的 SAP 跑代码」，共 27 次重复。结论写得很硬——**出题和写 SAP 可以交给 Agent，公式、队列边界和一致性计算必须人核**；计划写得好并不保证代码对，同模式错误会原样复制到下一次重复，17 份叙述摘要里 2 次出现有临床意义的错。这不是又一篇「让 LLM 看眼底」，而是本仓库第一次把 **眼科科研 / 真实世界结局分析**写成可复现的 Agent 评测。

其余直接相关的诊断/分诊系统稿（`2608.07651` 青光眼眼底工具编排、`2608.04772v2` 电话分诊、AgentEYE）本周仍无 v3、代码仓或勘误。MICCAI 2026 *Agentic AI for Medicine* Workshop 会议日仍为 **10 月 1 日**，录用名单未公开；EyeAgent RCT（NCT07401459）仍为 Not yet recruiting（估计启动日 3 月已过），AEYE Trial（NCT07096232）仍为 Enrolling by invitation。

### 1. Initial lessons from real-world implementation of an AI-agent eye clinic in China（AI-TEC）

- **日期 / 来源**：2026-09-10；*Nature Medicine*（Comment）
- **链接**：https://doi.org/10.1038/s41591-026-04631-z · https://pubmed.ncbi.nlm.nih.gov/42722887/ · 清华院系说明：https://media.au.tsinghua.edu.cn/info/1016/1638.htm
- **相关度**：**直接相关**（本周主条目；期刊正刊，关键词即 AI-agent eye clinic / multi-agent ophthalmic workflow）
- **摘要**：清华自动化系、北京视觉科学与转化眼研究所（BERI）、清华医学、北京清华长庚医院等联合发表 Comment。作者认为，基础模型把单任务诊断、风险预测和读图做得越来越准，并不自动等于医疗服务更好——真实诊疗是患者、医师、设备、数据和互锁流程组成的系统。传统「AI-assisted」把模型当外挂：影像分析、检出、风险各跑各的，医师仍要手工拼结果，有时还加重信息负担。文章提出 **AI-native health system**：AI 嵌进路径，持续整理信息、支持决策、协调照护。据此做成 **AI-TEC**（AI-Agent Augmented Tsinghua Eye Clinic）：预问诊 Agent 整理症状与病史，分诊 Agent 做风险分层并分配检查，精诊 Agent 整合多模态眼科数据，决策支持 Agent 提供循证信息，患者支持 Agent 覆盖患教、随访与长期管理；各阶段信息向后传递，强调 Agent 之间的信息流而不是工具堆叠。**2025 年 11 月**原型进入长庚常规流程，先接预问诊和眼底分析。实装经验：专家审过的高质量临床数据能明显抬性能；系统与运营设计决定医师愿不愿意用；持续反馈才能让 Agent 进化。作者同时指出 silent trial 测得出「在真实环境里跑得怎样」，测不出对决策、效率和结局的影响；真实参考标准本身有不确定性；以病为中心的算法任务未必对应患者主诉；筛查若不接到转诊、确诊、治疗和随访，临床价值仍为零。通讯作者含吴嘉敏、王雅星、戴琼海、Tien Yin Wong；共同第一作者严韬、张迪。
- **单篇小结**：这是本仓库首次出现「已经进院的眼科多 Agent 诊所」，位置正好接在 AgentEYE / EyeAgent / `2608.07651` 之后——那三篇还停在内部基准或工具编排，这篇把问题改写成**系统工程**。评测清单应加四栏：工作流嵌入、医师采用、转诊闭环、结局，而不是只报敏感度。局限必须写清：这是 Comment，不是 RCT，也没有公开工具列表或代码。对标 NCT07401459（EyeAgent 多中心 RCT）时，AI-TEC 提供的是「先 silent、再改流程」的部署叙事，不能替代随机对照。

### 2. Performance, Failures, and Oversight of a Large Language Model Agent for Clinical Data Analysis

- **日期 / 来源**：PubMed 索引 2026-09-08；*Journal of Medical Internet Research*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42709964/ · https://doi.org/10.2196/99597
- **相关度**：**直接相关**（本周第二条；LLM Agent + 湿性 AMD 真实世界队列；关键词含 ophthalmology）
- **摘要**：能从自然语言生成并执行统计代码的 LLM Agent 可能降低临床数据分析门槛，但哪些阶段可靠、哪些必须专家盯，此前缺少分阶段评测。作者用已发表的 Moorfields Eye Hospital **7802 眼 nAMD 12 年结局**公开数据集与参考 R 脚本，评 Claude Agent 的三种交互（Chat / Code / Cowork）和三档提示：A 只给原始数据、自行出科研问题；B 给高层临床目标、自写 SAP 再执行；C 执行研究者写好的 SAP。每档 × 每模式重复 3 次，共 27 次。结果：Agent 产出 18 个有临床根基的问题、覆盖 7 个主题，**只有 Cowork 摸到 3 个需要数据驱动方法的主题**；9 份 SAP 都找对了统计框架；17 次完成运行的 Kaplan–Meier 估计几乎重合。系统性失败是：SAP 质量**不能**预测代码对错，同模式错误在独立重复间原样传播；结果文本几乎总是忠实于执行日志，但出现了单位传播和一次未披露的崩溃后重跑。17 份叙述摘要中 8 份完全合格，**2 次出现有临床意义的错误**。作者结论：出题和写 SAP 可靠，公式组成、队列边界逻辑和一致性计算必须专家核验后才能往外报。作者 Wu / Fu / Zhou / Wagner / **Keane**（UCL / Moorfields）。
- **单篇小结**：这是本窗口「严格眼科 × 工具使用 LLM Agent」的科研侧正刊，对象不是眼底/OCT 诊断，而是**注射随访结局分析**，与 AI-TEC 的门诊部署形成互补。对照 AgentEYE「工具定正确率、检索定审计」：这里工具是 R / 生存分析，审计对象是队列定义和单位。Cowork 能多想出数据驱动问题，说明「有文件、能跑代码」的 harness 已经改变科研 Agent 的能力边界；同模式错误会复制，正好接到 8/30「相关失败 / 人群级监测」——同一条错公式可以一天内写进全组稿件。复现时不要只报 KM 曲线长得像，而要分栏报：出题覆盖、SAP 完整度、代码对参考值、叙述是否发明数字。

### 3. A Pilot Study of a CustomGPT for the Royal College of Ophthalmologists Curriculum 2024

- **日期 / 来源**：2026-09-13；*Journal of Medical Education and Curricular Development*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42732302/ · https://doi.org/10.1177/23821205261474025
- **相关度**：眼科教育 GPT（知识库封闭的课程问答，**不是**多工具临床 Agent）
- **摘要**：Yorkshire & Humber 眼科专科培训项目用官方 RCOphth OST Curriculum 2024 文档做 CustomGPT（仅上传课程 PDF、关网页），请 ST1–ST7 / Fellow 与顾问、导师、项目主任试用 3 个月（2025-04–06）。28 人完成问卷（学员/培训者各 14，仅 21% 为常规 AI 用户）：相关性 4.21/5、易用 4.38/5、满意 4.10/5，86% 称省时间，75% 推荐意愿 ≥8/10。与培训委员会主席对 10 条真实课程问题对照：总体对齐，GPT 引用更准、解释更死板。作者认为课程专用 GPT 能减少歧义、加快查大纲，适合嵌进培训平台。
- **单篇小结**：形态上接近 OphthoChat / Guideline-as-Oracle 的「只检索指定语料」弱 Agent，任务是培训而不是分诊。可直接借鉴「关网页 + 只喂官方 PDF + 与委员会主席对答案」三件套；不要把它写成已经能做急症定级。刚性解读复杂问题，说明规则表仍比整本课程 PDF 更适合电话分诊。

### 4. Large Language Models Approximate Inter-Expert Agreement in Glaucoma Suspect and Glaucoma Classification from Multimodal Data

- **日期 / 来源**：本窗口 *Ophthalmology Science* 可见；https://doi.org/10.1016/j.xops.2026.101352
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42718906/ · https://doi.org/10.1016/j.xops.2026.101352
- **相关度**：眼科多模态 LLM（非 Agent；本周最硬的「通用模型吃眼底+OCT+视野」对照）
- **摘要**：美国三级青光眼转诊中心 131 人 / 230 眼（2016–2022）。输入年龄、性别、种族、视力、眼压、眼底照相、OCT RNFL 报告与视野报告，零样本评 7 个配置（GPT-5 Pro、GPT-5.2、Gemini 3 Pro 两种提示、Grok 2.2）。金标准是 4 名青光眼专科医师留一多数共识（四套）。专科医师准确率 71.3–83.9%（κ 0.46–0.68）；GPT-5 Pro（长提示）80.4–85.7%（κ 0.61–0.71），Gemini 3 Pro（长提示）80.9–84.3%（κ 0.62–0.68），两家各在两套金标准上最高；GPT-5.2 居中，Grok 2.2 接近随机。中重度青光眼一致率高，**可疑青光眼与轻度明显更差**。作者认为公开多模态 LLM 在该任务上可接近专科医师间一致度。
- **单篇小结**：对照 8/30 *Retina* 纯看眼底（ChatGPT-4o 75%，其余 14–18%）和 9/6 OCTCases 看图题全错：把 OCT/视野**报告**（不是像素体积）喂进去后，旗舰可以摸到专科共识带。失败仍集中在「算不算病」的灰区——正是 `2608.07651` 该调用质控/分割/CDR 的位置。Agent 设计应：中重度可用 LLM 初判，可疑/轻度强制过专用工具，两路打架就弃权。Grok 接近随机再次说明骨干必须写进工具卡。

### 5. Generative artificial intelligence to augment ethical problem solving in ophthalmology: GPT-5.1 versus a human ethicist

- **日期 / 来源**：2026-09-07；*International Ophthalmology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42704533/ · https://doi.org/10.1007/s10792-026-04230-4
- **相关度**：眼科 LLM 伦理推理（非 Agent；给「处置/知情」话术提供对照）
- **摘要**：从 AAO *Ask the Ethicist* 随机抽 10 个真实眼科伦理情景（二诊并发症、实验性手术转诊、境外研究、违背最佳利益的治疗要求、术后共管、知情同意职责、企业讲者利益冲突、指南专家组财务披露、手术错误告知、怀疑同事酒后执业），喂给 ChatGPT 上的 GPT-5.1，对照网站伦理专家原文。10 名医师盲评「自己会不会用」和「对患者影响」。GPT-5.1 更难读（Flesch 10.9 vs 25.4；Gunning Fog 21.3 vs 19.5），但使用意愿（中位 5.0 vs 4.1）和感知患者影响（3.9 vs 3.6）显著更高。评分者一致性中等（ICC 0.56–0.69）。
- **单篇小结**：与 8/30 KLEx 指南评测同构——对齐/好用可以很高，同时完全不适合直接给患者（年级水平专家级）。伦理 Agent 若要上线，应先对 AAO 原文行号，再强制降年级，并保留伦理委员会签发；不能把「医师更想复制 GPT 的段落」当成已经可委托。

### 7. Autonomous AI-driven point-of-care screening for diabetic retinopathy（AEYE-DS）

- **日期 / 来源**：2026-09-09；*Frontiers in Digital Health*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42712598/ · https://doi.org/10.3389/fdgth.2026.1907804
- **相关度**：眼科自主筛查（固定算法，**不是** LLM Agent；给工具槽提供 FDA 路径对照）
- **摘要**：AEYE-DS 在三个前瞻对照研究、>1,200 名既往未诊断 DR 的糖尿病患者上，用手持 Aurora 与台式 Topcon NW400 非散瞳眼底，自主判断是否超过轻度 DR（mtmDR），对照独立阅片中心 ETDRS 多专家分级。三研究灵敏度/特异度分别为 93%/91%、92%/94%、93%/89%；可成像率均 >99%；操作者内重复性 >99%；台间/人间再现性 95–99%。作者支持作为可扩展的点诊筛查。
- **单篇小结**：FOCUS / MANTIS 之后，又一条「写死的流水线已经很强」。接到 Agent 时应同时暴露灵敏度、特异度、可成像率和「只报 mtmDR、不报病种鉴别」四行，防止规划器把阳性写成「增殖期、该注射」。自主筛查解决的是可及，不是跨模态仲裁或出处。

### 8. Artificial Intelligence-Assisted Segmentation and Characterization of Choroidal Melanoma Using Ocular Ultrasound

### 9. Optical Character Recognition-based Biometry Scanner for Easy and Efficient Biometry Calculations

- **日期 / 来源**：2026-09-09；*Journal of Refractive Surgery*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42715024/ · https://doi.org/10.3928/1081597X-20260701-02
- **相关度**：眼科工具（Gemini OCR → ESCRS IOL 计算器；弱 Agent / RPA）
- **摘要**：跨平台 App（Biometry Scanner 1.0）用 Gemini 2.5 识别任意设备生物测量打印件，自动填进 ESCRS IOL 计算器。12 名眼科医师用 4 周：OCR 准确性 4.5、易用 4.5、推荐 4.67（5 分）。10 人 × 5 次计时：App 91.7 秒 vs 手工 179.4 秒（−48.9%）。
- **单篇小结**：这是「计算机使用 / 填表 Agent」在屈光术前的最小可行产品，正好对 9/10 Agents API 与上周 Astra/Fable 的浏览器动作。生产环境要把打印件域名/计算器域名写成白名单，并核 OCR 数字，不能把「快了 50%」当成晶状体度数已经对。

### 10. Safe to Stop? Risk-Constrained Stopping for Sequential Clinical Diagnosis Agents（Cros）

- **日期 / 来源**：2026-09-09 提交 arXiv；`cs.AI`
- **链接**：https://arxiv.org/abs/2609.09678
- **相关度**：方法可迁移（诊断 Agent 的「何时停/何时升级」；可对电话分诊与取证）
- **摘要**：诊断 Agent 不但要决定下一张检查，还要决定何时下结论或转人工。现有基准多在固定轮次后评准确率，自主停止不可靠。Cros 用状态级错误排序 + 在隔离开发折上设计策略 + LTT 风格的有限样本检验，同时约束选择性诊断错误和最低自主覆盖。1,834 段 MIMIC 腹痛：完整排序器状态–错误 AUROC 0.853，高于最大类概率 0.715 和骨干自带停止分 0.552。在已看过的 367 段评估折上，选择性错误 16.9%、覆盖 78.8%、代价 5.57、检查 0.68，对照原生停止的 30.8% 错误 / 100% 覆盖。强迫把检查做完并不单调变好：只靠现病史错误 28.3%，全套检查后 34.3%。作者强调评估标签在开发期被看过，**不是确证安全证书**；20 次开发重切里只有 6 次名义上满足联合标准。
- **单篇小结**：这是 EviDx「何时停」的可检验版。眼科红眼/闪光/突发视力下降最怕模型在缺关键变量时直接给 Routine，也怕把全套 OCT/视野做完才更错。GAO 规则表应加一层：必问变量没齐只允许 Emergent/Urgent 或弃权；停止分不能用 softmax 自信代替。作者自己把「不是安全证书」写进摘要，引用时不要写成已经可上线。

### 11. A multi-agent GraphRAG framework for pharmacotherapy safety verification in clinical decision support systems

- **日期 / 来源**：2026-09-10；*Frontiers in Medicine*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42718584/ · https://doi.org/10.3389/fmed.2026.1898857
- **相关度**：方法可迁移（用药安全多 Agent + 知识图谱；可对青光眼/抗 VEGF 联合用药）
- **摘要**：多病共存与多重用药要求同时看适应证、禁忌、相互作用、肝肾功能、化验与剂量上限。静态规则难更新，单独 LLM 又会无出处。作者做三块：药疗知识图谱模式；Extractor–Critic 把非结构化文本变成带质控的图元素；语义检索 + 图遍历 + 安全导向重排。12 例抽取基准 + 30 道临床安全题。多 Agent 抽取相对零样本严格 F1 +0.156；GraphRAG 在线性混合模型与配对分析上优于常规 RAG，答案更可追溯。作者认为常规采用还需更大图、更多数据集和真实人群。
- **单篇小结**：眼科门诊的「滴眼液 + 全身药 + 抗 VEGF」是同一问题的小图。不要把说明书丢进 RAG，而要把禁忌/相互作用编成可遍历的边，LLM 只负责填槽和写给医师看的句子。这比 9/6 角膜 Wikipedia RAG「诊断升、处置掉」更接近 GAO 的规则表。

### 12. AI agents in cancer imaging: Concepts, advances, and clinical perspectives

- **日期 / 来源**：2026-09-09；*Chinese Journal of Cancer Research*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42712812/ · https://doi.org/10.21147/j.issn.1000-9604.2026.04.05
- **相关度**：方法可迁移（把影像 Agent 写成编排层；肿瘤影像是眼底/OCT 的近邻）
- **摘要**：综述：现有肿瘤影像 AI 仍是预定任务；Agent 用基础模型做推理与编排，按目标组织分析、调用外部工具与数据，并根据中间结果改下一步。作者整理原则、组件与评价，覆盖影像解读、决策支持和科研工作流。认为 Agent 能把碎片化的影像、临床与知识连起来，提高复杂任务的连续性和可追溯；但临床证据仍少、多在受控环境，多步执行有算力与错误传播问题，表现绑在具体工具/数据/流程上。下一步应做系统级验证：能否可靠组织信息、解释所见、与医师协作。
- **单篇小结**：清单可直接对到眼底/OCT：质控、分期、前后片、指南、报告对账。同日 *Academic Radiology*「Radiology Is not a Task」（PMID 42728185）把同一论点写成认识论：多模态/agentic 扩大了参与，**并不自动转移裁决权与责任**。眼科筛查一旦全院部署，责任仍须可指认到人。

### 13. Development and validation of a human-supervised AI-augmented living oncology evidence platform（Living-OEP）

- **日期 / 来源**：2026-09-12；*ESMO Real World Data and Digital Oncology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42729682/ · https://doi.org/10.1016/j.esmorw.2026.100770
- **相关度**：方法可迁移（人监督的 agentic 系统综述；可对 AAO/青光眼指南更新）
- **摘要**：用 GPT-4.1 / o3 / Claude Sonnet-4 模拟 Cochrane 流程，按人工标注手册拆任务、自调试、自校验，做成乳腺癌活证据平台。训练 29,236 条试验摘要（乳腺/肺/前列腺），4 个综述变量 + 32 个抽取变量，再链到基于指南的路径。相对 1,997 条人工标注：综述准确率 95.1–97.2%，抽取 51.1–99.4%（3 个变量仍在迭代）。在 8 个乳腺癌场景、6 条标准上，比 ChatGPT / Perplexity / Consensus / OpenEvidence 更全、更准，且每条链到原文与 FDA 标签。
- **单篇小结**：这是 Quicker 式指南 Agent 的肿瘤落地版，而且把「人写手册、人做 SLR、AI 加速」写成产品。眼科指南更新慢，可先拿抗 VEGF / 小梁网手术做同一套：综述层要 95%+，抽取层必须报变量级下限，不能用一个总分盖住 51% 的槽。

### 14. HS-MIND：消化系统恶性肿瘤围手术期多学科智能决策（多 Agent）

- **日期 / 来源**：2026-09-07；*中华胃肠外科杂志*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42706094/ · https://doi.org/10.3760/cma.j.cn441530-20260529-00214
- **相关度**：方法可迁移（院内部署的推理增强 + 多 Agent；有 25 例真实使用）
- **摘要**：华山医院 HS-MIND 用 ReAG-LLM 与多 Agent，四层架构（数据与知识 / 推理增强与工具 / 多 Agent 协作 / 临床应用），安全治理贯穿。结合 RAG、受控思维链、工具推理与协作，输出带证据的路径排序供医师审。已用于 25 例高龄、多病消化肿瘤围术期：5 例触发心血管/抗栓冲突模块，23 例路径排序进入 MDT，2 例因证据不足或未决冲突交高年资裁决。

### 15. Teaching Model Context Protocol, Retrieval-Augmented Generation, and AI Agents to a Multidisciplinary Hospital Workforce

- **相关度**：方法可迁移 / 治理（医院怎么培训「会用 Agent」而不是会聊天）
- **摘要**：首尔 Asan Medical Center 8 周、56 小时生成式 AI 强化课，同步直播两家分院。课程前提是 MCP 与 AI Agent 将成为医院用 AI 的底座：现场教学 37% 给 MCP、71% 动手。从概念 → RAG → MCP → 组队 capstone，配订阅、内部云和每周 3–6 小时导师。前后测 n=83 / 64。作者称这是首个同时把 MCP、RAG、LangGraph 与 Agent 设计教给 IT 与非 IT 职工的项目；投入最多的技术自我效能提升最大。强调课后若无支撑，知识–实践缺口仍在。

### 16. Evaluating Scaffolding-Oriented Multi-Agent Large Language Model System for Clinical Interview Training

- **日期 / 来源**：2026-09-10 提交 arXiv
- **链接**：https://arxiv.org/abs/2609.10939
- **相关度**：方法可迁移（问诊训练多智能体；可对眼科标准化病人 / 电话分诊教学）
- **摘要**：脚手架式多智能体「AI 标准化病人」：患者 Agent 对话，导师 Agent 只给苏格拉底式提示、不泄诊断，回合级评价 Agent 盯进度、不提前打总分。100 名医学生 RCT：多智能体组 vs 对照，两轮学习后在「仅患者」环境考试。最终诊断准确率无显著差，但考试总分、沟通、共情与特定病史行为更好。作者将发布带多专家标注的转录、清单、回合评价与 OSCE 分数数据集。

### 17. A Voice-Interactive Multi-Agent System for Smart Operating Rooms（SurgicalRoomAgent）

- **日期 / 来源**：2026-09-10 提交 arXiv；`cs.AI`
- **链接**：https://arxiv.org/abs/2609.11231
- **相关度**：方法可迁移（术中语音多 Agent；可对玻璃体/白内障设备控制，不是诊断）
- **摘要**：面向智能手术室的语音多 Agent：唤醒–ASR–轮次检测–推理–TTS，加上技能注册、任务规划与设备管理。三项工程：KV Cache 前缀预热（重算从约 500 ms 降到数十毫秒）、流式部分 JSON + 提前并行（端到端延迟约 −30%）、按角色/已接设备/手术阶段渐进披露技能提示。实现基于 Qwen3-27B、16k/84k 上下文，声称多设备并行控制达到术中实时。
- **单篇小结**：眼科日间手术要的不是再一个诊断模型，而是「灯、显微镜、录音、术后记录」的低延迟技能注册。渐进披露技能直接对照 Claude Skills：上下文里只放当前阶段能用的工具，避免把全院 API 说明书一次塞进提示。部署前必须最小权限，不能默认给真实设备写权限。

### 18. OpenAI Agents API 公测：托管 Codex harness + 沙箱 + 子 Agent

- **日期 / 来源**：官方博文 2026-09-10
- **链接**：https://openai.com/index/introducing-the-agents-api/
- **相关度**：方法可迁移（通用 Agent 运行时；本周最重要的平台增量）
- **摘要**：把支撑 Codex / ChatGPT for Work 的 harness（上下文管理、工具使用、子 Agent 协调）做成公开 API。一次调用指定任务、模型（示例为 `gpt-6-astra`）、工具与环境；OpenAI 维护 harness，计算环境可选托管沙箱、自有基础设施或 Blaxel / Cloudflare / Daytona / E2B / Modal / Vercel 等。新能力包括：会话接近窗口时自动压缩、按需工具搜索、在代码里并行/串联工具调用、MCP / 自定义函数 / 网页搜索、`multi_agent` 子 Agent 并行。按 token 与工具计费，无额外 API 费。客户引言称评测分 0.71→0.85、子 Agent 延迟降 4 倍、个案成本 −60%、失败响应 −86%。
- **单篇小结**：Keane 组若在 9/10 之后重跑「nAMD 数据分析 Agent」，对照臂就不应再只写 Chat/Code/Cowork，而要固定「Agents API × Astra × 是否开子 Agent × 是否允许改队列定义」。眼科生产若要用它拉指南 PDF 或跑 R，必须自带沙箱镜像、禁外网（或域名白名单），并把公式/队列边界写成 Skill 而不是提示词。上周 Astra/Fable 解决的是「谁更会用电脑」，本周解决的是「谁帮你养 harness」。
