### 1. Accelerating Scientific Research with Gemini in the Real-World（Co-Scientist → Agent_H）

- **日期 / 来源**：2026-08-27 提交；arXiv `cs.AI`；Google DeepMind / Duke / Columbia 等
- **链接**：https://arxiv.org/abs/2608.26701 · HTML：https://arxiv.org/html/2608.26701
- **相关度**：方法可迁移（科研多智能体接到医学问答；本周最重的通用/医疗交叉稿）
- **摘要**：把 Gemini 基座的 Co-Scientist 从「纸上假设生成」扩成执行接地的科研伙伴：构思（进化式假设 + 贝叶斯两两比较）→ 实验（脚手架→全量代码进化）→ 写稿（对照执行日志做幻觉裁剪）。材料科学侧对接半自动 CVD，设计更安全的 MXene 前体路线，并用 Gemini 3 Deep Think 在数分钟内按实验室约束一次长出单层 MoS₂ / MoSe₂ / WS₂。生物学侧用稀疏成像预测工程大肠杆菌群体形态，与未发表湿实验大体吻合。计算机科学侧**无人干预**地发现推理时扩展架构 **Agent_H**：八阶段流水线（多轴分诊与对抗风险检测 → 复杂问分解 → 28–48 条多人格候选 → 单淘汰锦标赛 + 三评委多数决 → 最多五轮临床审核 → 引用/剂量核验 → 长度压缩）。每个查询约 40–80 次 LLM 调用。在设计阶段未见过的 HealthBench Hard / Professional 上，Agent_H 的长度校准分超过 GPT-5.6 Sol、Claude Fable 5 / Opus 5、Gemini 3.1 Pro 等六个前沿单模型基线；医师盲评（106 题）相对裸 Gemini 3.1 Pro **伤害可能性显著下降**（*p*=0.0486），其余维度多为平手。双盲 30 名专家、450 份审稿显示，对照执行日志的可靠性模块降低幻觉与抄袭。
- **单篇小结**：对眼科的直接可迁移点不是去开 CVD，而是 Agent_H 的配方：**先按专科/受众/风险分层再花算力**，复杂题才分解；候选用「急诊/安全」等人设扩多样性，用锦标赛而不是一条 CoT。这与上周 GAO「急症召回优先」和 AMR「按复杂度路由」同构。40–80 次调用说明旗舰模型不该扛全部 tool-calling；眼底质控/分割仍应交给小工具，终审与伤害相关决策再升级。作者自己承认：基线是单次推理，Agent_H 是重推理工作流，比的是「架构」不是「同成本公平对打」。

### 2. EviDx: Evidence-Aware Active Diagnosis with Scaffolded LLM Agents

- **日期 / 来源**：2026-08-25；arXiv `cs.AI`
- **链接**：https://arxiv.org/abs/2608.24570
- **相关度**：方法可迁移（主动取证诊断 Agent；可对眼科问诊/远程分诊）
- **摘要**：临床诊断是主动找证据、更新鉴别、判断「够不够下结论」的过程，但多数医学 LLM 仍是静态病例→答案。EviDx 用 ε-Synthesis 从原始病例构造可交互环境，用临床脚手架组织角色 Agent、证据工具与演化中的证据状态，再用观察者驱动的运行时按不确定度和证据覆盖决定何时终止。评测金字塔分三层：执行稳健、推理动态、诊断结局。实验显示诊断表现与过程稳定性同时改善，并暴露出骨干模型相关的能力边界。作者 Zeng / Zhang / Zhang（上海交大等）。
- **单篇小结**：把「该不该再问一句 / 该不该再调一个 OCT 工具」写成一等公民，而不是提示词里的软约束。眼科红眼、闪光、突发视力下降最怕模型在缺发病时间、单双眼、是否术后时直接给处置——EviDx 的终止门可接到 GAO 规则表之上。评测拆成执行/过程/结局三层，也比只报一个诊断准确率更接近可上线审计。

### 3. CDEG: Learning Decision-Critical Evidence for Long-Horizon Diagnostic Agents

- **日期 / 来源**：2026-08-24 提交，2026-08-26 更新 v2；arXiv `cs.AI`
- **链接**：https://arxiv.org/abs/2608.22899
- **相关度**：方法可迁移（从轨迹里蒸馏「真正改判的证据」）
- **摘要**：长程诊断里，医生 Agent 常因关键证据没采到或采到了却没用上而失败。复用历史轨迹/记忆会把噪声和偶然信息一并灌进去。CDEG 对比同一病例的成功 vs 失败轨迹，用反事实干预验证哪些证据真正改判，再做成诊断–证据–动作图；推理时跟踪当前证据状态，检索该补哪条、该重评哪条。多个医生 Agent 骨干、域内与 OOD 上最高可相对 vanilla **+11.5%** 准确率。
- **单篇小结**：眼科随访（青光眼结构–功能不一致、nAMD 停/打针）最需要的不是更长的对话记忆，而是「哪些字段一旦缺失就不能下结论」。可把 CDEG 的反事实检验做成规则表审计：删掉眼压/RNFL/CST 后诊断是否翻盘，翻盘的才配进强制追问清单。

### 4. MediSkill-Evo: Process-Constrained Self-Evolution for Evidence-Grounded Clinical Interaction

- **日期 / 来源**：2026-08-24 提交，2026-08-25 更新 v2；arXiv `cs.AI`
- **链接**：https://arxiv.org/abs/2608.23397
- **相关度**：方法可迁移（过程知识自进化，不微调骨干）
- **摘要**：交互式临床 Agent 部分可观测，可靠诊疗取决于经证据接地的安全交互。MediSkill-Evo **不微调骨干**，把临床/过程/符号/视觉知识写入四类带校验与作用域规则的知识库，再用 Process-Constrained Preference Harness 把通过校验的知识变成动作偏好。评测：300 条 MIMIC-IV FullChain、180 条硬隔离过程义务、100 例 NEJM 图像诊断。Qwen FullChain 上相对最强先验 Agent，诊断准确率 +7.81%，治疗意图覆盖 +70.67%，严重失败 −43.04%；压力测试下过程综合分与必做动作完成率再升；可选 MedSAM 定位的多模态诊断也有提升。
- **单篇小结**：这是「Skill = 可版本化路径」的医学版，对照上周 Claude Skills GA。眼科可把 AAO 分诊表、术前清单、抗 VEGF 停药规则做成带作用域的过程库，而不是写死在系统提示里。治疗意图覆盖大涨、严重失败下降，说明过程约束主要买的是**安全与完整**，不是再抠几个点准确率——与 AgentEYE「检索换可审计」同一逻辑。

### 5. LUCAID: Agentic Multimodal AI for Lung Cancer Precision Pathology

- **日期 / 来源**：2026-08-24；arXiv `cs.CV` / `cs.AI`
- **链接**：https://arxiv.org/abs/2608.23803
- **相关度**：方法可迁移（专科多模态工具编排 + **前瞻临床验证**；病理近邻）
- **摘要**：肺癌组织诊断要把形态、免疫组化与分子特征放在一起，但病理评估仍偏目测、半定量且观察者差异大。LUCAID 用整合 Agent 挂 **9 个模块**：质控、肿瘤检出/分割、组织学亚型、微环境、细胞量、预测性生物标志物（PD-L1 / MET / TROP-2）到结构化报告，并允许交互查询。分析模块相对大规模专家标注 F1 0.82–0.95。前瞻验证中，临床可操作决策与专家组裁决一致率 **93.0%**，五名有经验胸病理医师为 68.3–81.1%。
- **单篇小结**：架构几乎是 EyeAgent / AgentEYE 的病理翻版，但多了**前瞻一致率**这一栏——眼科 RCT（NCT07401459）还没启动时，这是最接近「人机对照可引用数字」的专科 Agent。可直接对照：质控→分割→分型→标志物→报告；缺的是拒答与跨模态仲裁。不要把 93% 外推成「超过病理科」，比较的是可操作决策一致率，不是替代诊断权。

### 6. STRIVE: Multi-Agent Structured Temporal Reasoning with Integrated Verification for Longitudinal Radiology Report Generation

- **日期 / 来源**：2026-08-25；arXiv `cs.AI`
- **链接**：https://arxiv.org/abs/2608.24237
- **相关度**：方法可迁移（纵向影像报告多智能体；可对 OCT/眼底随访）
- **摘要**：纵向放射报告要同时写「这次有什么」和「相对上次变了什么」。现有方法把诊断、属性、时序比较和语言生成挤在隐空间，难以追溯对错，且把进展状态当独立标签，漏变与方向反转同等惩罚。STRIVE 拆成诊断 / 属性 / 时序变化三个 Agent，产出显式中间证据；时序 Agent 用 Progression-Aware GRPO，方向保留的错误给部分分、方向反转最低分。确定性 Consistency Gate 在写报告前对账，Validation Agent 再检查报告是否被聚合证据支撑。Longitudinal-MIMIC 上临床效力领先，Longitudinal Change Concordance 相对最强基线**翻倍以上**。
- **单篇小结**：nAMD 打针随访、青光眼 RNFL/视野进展，失败模式经常是「方向写反」而不是「病名写错」。把「所见 / 属性 / 相对上次」拆开，再加一致性门，比再训一个更大的报告模型更值。可先在 OCT 结构化报告上做规则 + 本地 LLM 双 Agent，不必上云。

### 7. StrokeGuard: A Multi-Agent Guided System for Prehospital Stroke Assessment

- **日期 / 来源**：2026-08-25；arXiv `cs.HC` / `cs.MA`
- **链接**：https://arxiv.org/abs/2608.24555
- **相关度**：方法可迁移（院前指导式多 Agent；与眼科电话/视频分诊同构）
- **摘要**：院前卒中评估要在极窄时间窗按 FAST 指导受试者做指定动作。居家场景里非临床用户常描述不准、观察不全、步骤不会做。StrokeGuard 用双通道：一条走正式评估（面瘫/上肢无力/言语），一条走步骤提示、纠错与实时反馈；状态机 + 阶段局部回退保证流程可恢复。阶段评分交给受约束的预训练视频模块，证据源写入结构化报告。模拟院前场景下，多步 AI 指导任务体验量表 MATES-9 总分高于纸质 FAST。
- **单篇小结**：这是 AMIE（Video）「边看边问」的轻量落地版。眼科远程最缺的也是指导动作（遮盖–去遮盖、Amsler、指测眼压、手电筒 RAPD），而不是再写一段报告。双通道（评估核 vs 引导核）可直接接到 GAO 护士角色：规则表负责定级，引导 Agent 负责把规则变成下一句能被老人执行的话。注意评测主指标是可用性，不是临床灵敏度。

### 8. Beyond Information Seeking: Severity-Aware Question Supervision for Proactive Medical Dialogue

- **日期 / 来源**：2026-08-25；arXiv `cs.CL`
- **链接**：https://arxiv.org/abs/2608.24521
- **相关度**：方法可迁移（按漏诊代价选下一问；与急症召回同目标）
- **摘要**：主动医学对话要在信息不完整时决定问什么。现有信息寻求目标常选「最降不确定度」的问题，但漏掉重症与在轻症之间纠结的代价完全不同。作者提出 Expected-Severity-Risk（ESR）：按对严重度加权终末风险的期望下降来给候选问题打分，用仅训练集的人群统计对未见答案边缘化，再蒸馏成前缀语言模型，部署时不再跑教师。DDxPlus、Qwen3-4B 三随机种子：高严重度漏诊均值 **0.0645→0.0455（−29.5%）**，诊断准确率 0.9123→0.9320，每段对话只多 0.14 问。
- **单篇小结**：把 GAO 的「急症召回优先」写成可训练目标。眼科闪光/幕布/突发无痛视力下降，下一问不该是「最能缩小鉴别清单」的罕见病细节，而该是排除视网膜脱离/动脉阻塞的红旗。固定问数时 ESR 与纯不确定度策略行为仍不同，说明换目标不是多问两句那么简单。

### 9. Previewing the Model Hardware Standard（Anthropic MHS）

- **日期 / 来源**：2026-08-27；Anthropic 官方公告
- **链接**：https://www.anthropic.com/news/model-hardware-standard-research-preview
- **相关度**：方法可迁移（Agent 操作物理仪器的协议层；与 Co-Scientist 同周）
- **摘要**：MHS 是给 AI Agent 安全操作实验室/制造设备的共享规范研究预览，与 HHMI Janelia 合作起步，模型无关，可通过 MCP / CLI / API 访问。驱动用统一 read/write 原语让设备可发现，并用自然语言标签生成含安全限位的设备说明书。早期案例：Genentech 用移液站+机械臂+酶标仪跑 BCA；卡内基梅隆把互不兼容的四台仪器在约 8 小时内串成剂量–反应流程，速度约 3 倍，六种人为故障均在动作前被拦住；Janelia 把原先七套厂商软件的显微镜台架统一编排。计划研究预览后开源；无编程接口的设备暂不支持。Genentech 气泡/泡沫案例说明：模型会把物理失败误判成软件故障并重试把问题做大，仍需专家把关。
- **单篇小结**：对眼科的意义不是让 Claude 去开激光，而是 **「仪器/PACS/视野计」终于有了和工具调用同一层的协议想象**。眼前更现实的一步仍是：OCT/眼底相机的质控与定量工具走软件 API，MHS 留给真正有程控接口的检查设备。安全叙事要写进设计：重试策略必须区分「软件超时」和「样本/光学物理失败」。

### 11. Diagnostic Accuracy of Multimodal Large Language Models in Retinal Fundus Photography

- **日期 / 来源**：2026-08-25；*Retina*
- **链接**：https://doi.org/10.1097/IAE.0000000000004986 · PMID 42640646
- **相关度**：眼科多模态 LLM（**非 Agent**；对照用）
- **摘要**：8 类视网膜病、每类 100 张彩色眼底，共 800 张，比较 ChatGPT-4o、Claude 3.5 Sonnet、Gemini 1.5、Grok-2 的自由文本诊断、1–10 自信与理由类型。ChatGPT 总准确率 **75%（603/800）**，其余约 18% / 18% / 14%。仅 ChatGPT 的理由类型与对错有关联，自信–准确相关虽弱但显著（*r*=0.19）。模型间一致性极低（与 ChatGPT 的 κ 0.11–0.16，其余两两约 0.05）。
- **单篇小结**：又一次「裸 MLLM 看眼底」：最好的通用模型也只到 75%，其余几乎不可用，且互相不同意。这正是 `2608.07651` / AgentEYE 要用专用分类/分割工具的原因。自信校准很弱，不能当拒答门；若做 Agent，escape 应来自工具冲突或视图一致性（上周 EVADE），而不是模型自报分数。

### 12. Evaluation of Large Language Model-Generated Recommendations in Glaucoma Surgical Decision-Making

- **日期 / 来源**：2026-08-29；*Seminars in Ophthalmology*
- **链接**：https://doi.org/10.1080/08820538.2026.2725223 · PMID 42667272
- **相关度**：眼科 LLM 手术建议（非 Agent；复杂病例对照）
- **摘要**：三甲医院真实病历改成标准化情景，分「原发性」与「复杂」青光眼，让 ChatGPT、Copilot、Gemini 各给一个术式及理由。盲态青光眼专科医师按适宜性、理由、特异性、指南符合、可行性、安全风险打 0–100 分。总体中位质量 80.7 / 80.7 / 82.7，组间无显著差。**复杂度显著伤表现**：Gemini 在复杂病例上适宜性与理由下降、安全风险上升（*p*=0.009）；ChatGPT / Copilot 更稳，但复杂病例理由质量仍显著差于原发性。作者结论：简单原发性病例可作辅助，高风险/复杂场景效用有限，必须专家监督，不能当自主决策者。
- **单篇小结**：与近视评测里「认病强、处置弱」同构，而且这次是**真手术选择**。Agent 设计应把术式推荐做成指南/适应证计算器工具，复杂病例强制升级人工；不要让聊天模型直接输出「做小梁切除」。可与 GAO 的急症召回对照：这里缺的是「复杂度路由 + 安全风险栏」，不是更长的理由。

### 13. A decade of artificial intelligence research in ophthalmology: Global trends and transferable insights for medical AI

- **日期 / 来源**：2026-08-25；*PLOS Digital Health*
- **链接**：https://doi.org/10.1371/journal.pdig.0001347 · PMID 42640898
- **相关度**：眼科 AI 计量综述（非 Agent；用来看 Agent 还没进主航道）
- **摘要**：2015–2025 眼科 AI 原创论文 12,911 篇，年复合增长 39.7%（108→3061）。四条转移：研究设计上开发研究占 88.3%，评价研究 7.4% 且 2019 后才出现；架构上经典深度学习 71.8%，基础模型仅 0.6% 但 2024–2025 陡增；病种仍以 DR / 青光眼 / AMD 为主，角膜、白内障、近视 2019 后加速；模态上图像 84.1%（眼底与 OCT 2019 后平台期），文本 5.5% 在 2022 后继续升。作者认为轨迹是从窄任务看图深度学习走向评价研究、基础模型与多模态。
- **单篇小结**：计量上 **Agent / tool-use 还没有自己的柱子**——本周眼科新稿仍是 MLLM 评测和分割，不是编排系统。这对周报策略是提醒：直接相关稿会继续稀疏，备选 AI 技术周报会经常出场；同时「评价研究占比仍低」说明眼科 Agent 若要发表，人机对照与外部分要比再报一个内部准确率更值钱。

### 14. Automated 2D and 3D Segmentation of AMD and DME Lesions in OCT

- **日期 / 来源**：2026-08-27；arXiv `cs.CV`
- **链接**：https://arxiv.org/abs/2608.27095
- **相关度**：眼科专用 CV 工具（可替换进 nAMD/DME Agent 的病灶槽）
- **摘要**：针对 AMD / DME 的 2D 与 3D 病灶分割做系统消融，域内 Dice 0.76–0.82，体积与表面校准 *r*≥0.97。集成组成是最稳的增益来源。外部分 OLIVES 无病灶金标准，改用生物标志物 AUROC、CST 相关与纵向一致性作代理：预测能跟踪临床标志物，但弱于域内。作者强调切片级指标会漏掉全容积校准问题。
- **单篇小结**：FOCUS（上周）已经证明固定 OCT 流水线很强。这篇提供的是可挂进 Agent 的**病灶负荷工具**，外部分用 CST/纵向一致性当代理，比只报 Dice 更接近随访场景。接到 STRIVE 式纵向报告时，病灶体积变化方向应成为 Consistency Gate 的输入，而不是再让 VLM 估「有没有水肿」。

### 15. A Rationale-Conditioned Image-Contrast Audit of OCT Dependence in Vision-Language Models for Anti-VEGF Treatment-Response Prediction

- **日期 / 来源**：电子出版 2026-08-12；*Bioengineering*；本窗口 PubMed 索引
- **链接**：https://doi.org/10.3390/bioengineering13080912 · PMID 42649801
- **相关度**：眼科 VLM 审计（非 Agent；揭示「看图模型其实没看图」）
- **摘要**：任务准确率不能证明 VLM 真的用了 OCT。作者固定已生成理由，把真实 B-scan 换成均匀灰图，比较 continue/stop 分数，得到「理由条件下的直接图像对比」。RetinaVLM / LLaVA-Med / Qwen3.6-27B，APTOS-2021 小队列 + 100 眼跨中心压力测试。22 个内部单元格里 21 个 AUC 置信区间含 0.5，仅一格呈反向对齐；BH 校正后无正向对齐单元格存活。部分骨干的生物标志物头对图像有反应（PED 平衡准确率可达 0.93），五字段表格参考模型决策 AUC 0.731。作者强调：理由未必忠实、灰图 OOD、样本小，**空对比不能证明模型忽略了 OCT**。
- **单篇小结**：这是给眼科 VLM/Agent 的必要审计：终审 LLM 可能只是在复读自己的理由或表格字段。Agent 评测应强制「换图/遮图」对照，而不是只看停药准确率。也解释了为什么专用分割/CST 工具必须在反思之前以结构化字段进黑板，不能只把图和一段 CoT 拼在一起。
