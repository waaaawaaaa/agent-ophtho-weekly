### 1. LogicEye: Agent Driven Multimodal Dataset for Interpretable Ophthalmic Diagnosis

- **日期 / 来源**：arXiv `2611.18669v1`，submitted **2026-11-17**（Tue）。山东建筑大学计算机与人工智能学院（Jiajie Mu / Lu Chen / Xiaoming Xi / Lishan Qiao / Xiushan Nie）+ 山东大学软件学院（Zheyun Qin / Yilong Yin）
- **链接**：https://arxiv.org/abs/2611.18669 · https://arxiv.org/pdf/2611.18669 · 代码仓：https://github.com/Eden35/LogicEye-Agent-Driven-Multimodal-Dataset-for-Interpretable-Ophthalmic-Diagnosis（创建 **2026-10-26**，最近推送 **2026-11-17**；论文写明代码可获取，本窗口未见权重或 80 万图下载说明）
- **相关度**：**直接相关（本周主条目）**——眼底 + OCT 上的双池核验 Agent；**不是**会调 RETFound / 分诊阈值的诊疗工具 Agent
- **摘要**：公开眼科集多为单模态、粗病种标签，生成报告缺少「支持诊断的所见」和「用于鉴别的阴性征」。LogicEye Agent 从覆盖 38 病种的专家知识库取出阳性纳入池与阴性排除池（例如 NPDR：微动脉瘤/硬性渗出为纳入，无新生血管为排除），再用视觉语言模型逐条对照图像：可见征记录解剖位置与描述，判定缺如的写入阴性所见。LogicEye Data 合并 67 个公开源共 **804,461** 张图（眼底 346,649 / OCT 457,812），层次为 9 大类、29 亚型、38 病种、304 细粒度特征。质控用 MLLM 对诊断准确 / 特征完整 / 非幻觉打 1–5 分，加权得到 LogicEye Score；**<2** 转人工，争议再交高年资眼科。LogicEye Bench 以 Qwen3 VL 8B 为骨干，冻结视觉编码器、微调跨模态适配器与 LLM，联合优化报告生成 + 粗分类（K=9）+ 细分类（K=29）；8:1:1 划分，8×A100、10 epoch。测试集：LogicEye Score **2.92** / ACC **0.54** / METEOR 0.47 / ROUGE-L 0.44，对 GPT-4o **2.11 / 0.32**、Gemini 3.0 Flash 2.05 / 0.28、Qwen3 VL Plus 1.80 / 0.25。九大类 ACC：视神经疾病 **0.83**、糖网 **0.71**、近视相关 0.66、ROP 0.65、黄斑 0.56、白内障 0.54、**青光眼 0.49**、视网膜血管病 **0.21**、炎症/感染视网膜 **0.19**。消融：只生成 Score 2.31 / ACC 0.41；粗+细分类损失各取 1 时最高。
- **单篇小结**：这是对上周 RetinaGuard「报告槽是模板、对动作没有权限」的标注版，也是对 HalluciGuard「检索能压幻觉、仍不会写排除征」的数据版。可搬的不是 2.92 这个自研量表，而是三张表：**阳性池和阴性池必须分列**（没有「无新生血管」，NPDR 报告就是不完整的）；**MLLM 打分不能当唯一质控**（Score&lt;2 才转人工，争议还要高年资）；**分类 ACC 0.54、青光眼 0.49 不能写成已经可签发**——作者自己把任务写成可解释视觉语言建模的基础，不是筛查门。接到糖网 / 青光眼 / OCT 报告 Agent 时，应禁止用「再训一个会写报告的 VLM」替代纳入/排除征知识库；合并 AIROGS / ODIR / Harvard G 等公开源时，应先按上周 *JAMA Ophthalmol* 的体积指纹去重。不要把「Agent」写成已经会看图诊断——病种标签是输入，不是输出。预印本未经同行评议；单位是计算机院，测试集划分未给逐病种 n，商业对照停在 GPT-4o / Gemini 3.0 Flash，没有本周的 GPT-6.2 / Gemini 4 Neon。

### 2. Comparative evaluation of GPT 5.2 Pro and Gemini 3 Pro large multimodal models for retinal optical coherence tomography interpretation

- **日期 / 来源**：2026-11-16；*Graefe's Archive for Clinical and Experimental Ophthalmology*。Bellanda / Shin / Chen / Mizuno / Singh 等
- **链接**：https://doi.org/10.1007/s00417-026-07604-7 · https://pubmed.ncbi.nlm.nih.gov/43037730/
- **相关度**：眼科相邻（通才 LMM 零样本看视网膜 OCT；**不是** Agent）
- **摘要**：担心患者已经能把 OCT 丢进消费级多模态模型。330 张公开视网膜 OCT B-scan、12 个诊断类（含正常），零样本评估 GPT 5.2 Pro 与 Gemini 3 Pro：先做 9 个预定 OCT 特征检测，再做自由文本诊断。Gemini 特征检测 macro-F1 **0.558** 对 GPT **0.472**，诊断准确率 **58.8% vs 32.1%**。显眼异常好于细微结构；正常扫描常被判成有病，**GPT 一张正常图都没认对**。两边都出现反复、模型特异的诊断偏见和幻觉诊断。作者结论：能抽出一些临床相关信息，但诊断可靠性不够，尤其不能当患者端工具。
- **单篇小结**：位置正好接在条目 1 之后——**LogicEye 的 0.54 ACC 已经高于这份零样本通才 OCT 诊断，但两边都远不到可签发。** 接到「最新 GPT / Gemini 已经可以看 OCT」的采购话术时，应要求：正常图特异度单独报、特征检测与诊断分栏、以及有没有幻觉诊断清单。本条不是工具编排，不替代条目 1。对照模型是 GPT 5.2 Pro / Gemini 3 Pro，不是本周新出的 6.2 / Neon。

### 3. Beyond Accuracy 与 RetiDual-Select：不确定度和质量漂移，仍不是工具槽

- **日期 / 来源**：arXiv `2611.23344` / `2611.22117`，均 submitted **2026-11-17**
- **链接**：https://arxiv.org/abs/2611.23344 · https://arxiv.org/abs/2611.22117
- **相关度**：眼科相邻（眼底筛查不确定度基准 / OCT 专科–通才路由；都**不是** LLM Agent，但可对 RetinaGuard 的不确定度门与质量门）
- **摘要**：**Beyond Accuracy**（MEE / Harvard：Jebeli / Eslami / Zebardast / Sobrin / Elze）：&gt;242,000 张眼底、32 个数据集，覆盖糖网 / AMD / 青光眼；6 种不确定度策略 × 3 种 ViT。结论是**没有一种策略/模型普遍最优**：提升区分度、校准、选择性预测并不自动对齐；计算更重的方法不一定压过简单置信度；领域基础模型和校准损失也不保证更可靠。Conformal prediction 能在其统计假设下给出接近名义覆盖的预测集。作者放了划分、checkpoint 和评测代码。**RetiDual-Select**（Kent：Han / De Wilde）：把 RETFound 与 MedSigLIP 图像编码器拆成「候选融合 / 路由安全 / 预测复查」。干净数据上静态 product-of-experts 最高或并列最高。清洁 2% 可接受误差目标下，Kermany-4 接受 **94.3%**、选择准确率 99.89%；OCT-C8 接受 **92.4%**、98.65%。两条分支同时正确占 95.0% / 91.8%，恰好一条正确只占 4.4% / 6.2%。15 种预设合成退化里，自适应增益集中在严重对比度下降（路由机会大约放大九倍）；事后验证里冻结 harm guard 把 OCT-C8 最差条件损失从 1.39 压到 0.36 个百分点。作者写明：合成扰动 ≠ 真实采集/扫描仪漂移。
- **单篇小结**：两条分别钉上周 RetinaGuard 的两句话——**不确定度方法不能按 AUROC 选一个就上**（Beyond Accuracy）；**质量一变，专科/通才谁更可信也会变，必须有冻结的 harm guard**（RetiDual-Select）。接到糖网/青光眼社区门时，应禁止把「再加 Monte Carlo」写成已经更安全；对照必须含简单置信度、conformal 覆盖、以及质量门是否单独过。都不是编排 Agent。

### 5. （本周索引 / 上窗口漏检）10-shot 眼科 MLLM、外眼照相公平训练与交叉公平

- **日期 / 来源**：medRxiv DOI `10.64898/2026.10.30.26366929` posted **2026-11-02**、本窗口 PubMed 索引（PMID 43060702，edat 11/20）/ medRxiv DOI `10.64898/2026.11.08.26363489`（PMID 43060039，edat 11/20）/ *npj Digit Med* 电子出版 **2026-08-03**、本窗口索引（PMID 43052422，edat 11/19）
- **链接**：https://doi.org/10.64898/2026.10.30.26366929 · https://doi.org/10.64898/2026.11.08.26363489 · https://doi.org/10.1038/s41746-026-03030-5
- **相关度**：眼科相邻（少样本 MLLM、外眼照相、青光眼眼底公平性；均**非 Agent**。三条电子出版/首发早于或压在上窗口，仅因本周索引或漏检列入）
- **摘要**：**10-shot**（Ramakrishna / Strand 等）：9 个模型、3 个家族——MLLM（Qwen3.8-27B / GLM-5.3-Flash / Gemma-4-31B-it）、VFM（DINOv3 / RETFound / VisionFM）、VLM（CLIP / EyeCLIP / SigLIP2）；4 个公开集 + 3 个私有集（含 OHTS、BPEI-DLS、WashU-OCT）。MLLM 零样本/10-shot 不做额外训练；视觉模型在同一 10-shot 或全量上线性探针/微调。视网膜 OCT 分类：10-shot MLLM macro-F1 **0.94**，对视觉模型 10-shot **0.59**、全量 **0.96**。糖网 / 黄斑水肿分级 QWK：MLLM 0.69 / 0.73，对 0.48 / 0.57（10-shot）和 0.72 / 0.79（全量）。病灶定位 F1：0.75 vs 0.70 / 0.86。OHTS 垂直杯盘比：零样本 MLLM MAE **0.14**，对视觉模型 10-shot 0.21。WashU 全容积 OCT：零样本 MLLM macro-F1 **0.71**，对 0.50 / 0.82。**外眼照相**（MEE，Kostin 等）：40,687 张外眼照、9,878 人，做威胁视力糖网 / 晚期 AMD / 青光眼二分类。LLaVA 对 VTDR 基线 AUC **85.4%**（ViT 82.6%）；晚期 AMD 各架构约 85–86%；青光眼只有 **67–74%**。公平训练把 VTDR / AMD AUC 提到 86.3% / 85.9%，并部分缩小人口学差距。作者写明：外眼照相还不能部署。**交叉公平**（CMAC-MMD）：皮肤 HAM10000 / BCN20000 + **Harvard-FairVLMed** 青光眼 10,000 张。皮肤 ΔTPR 0.50→0.26、AUC 0.94→0.97；青光眼 ΔTPR 0.41→0.31、AUC 0.72 vs 0.71。推理时不需要敏感人口学。
- **单篇小结**：10-shot 条是给条目 1 / RetinaGuard 的数据效率对照——**少样本 MLLM 能接近全量 RETFound，仍不会编排工具**。接到「只要 10 张就能替换院内 RETFound」的话术时，应要求：10-shot vs 全量分栏、OCT 分类 vs 分级 vs 定位分栏、以及私有容积 OCT 的 0.71 不得写成已经可替代 3D 基础模型。外眼照相的青光眼 67–74% 和 FairVLMed 的 ΔTPR 0.31，正好接上周 Harvard-GF / FairVision **至少 31% 体积重复**——公平数字在去重前不能当独立队列。都不是 Agent，不计入翻转。

### 6. An open agentic AI co-scientist for clinical and biomedical discovery（OpenScientist）

- **日期 / 来源**：2026-11-16；*Nature Medicine*。Washington University in St. Louis 病理与免疫（Roberts / Abrams 等）
- **链接**：https://doi.org/10.1038/s41591-026-04808-6 · https://pubmed.ncbi.nlm.nih.gov/43039361/
- **相关度**：**方法可迁移（本周正刊主对照）**——开源、可断网的科研 Agent；不是眼科，但可对 GUIDE / 实验设计槽
- **摘要**：生物医学分析被数据和领域门槛卡住。OpenScientist 按科学家给定的查询做可核验、数据接地的分析。五例专家评估：把原本要数月的分析压到数分钟；量化阿尔茨海默血生物标志物表现；在隐藏评估队列上做出浆蛋白组生存模型；提出 tau 病理与溶酶体酸化的可复现机制；多发性骨髓瘤假说在外队列得到验证、随机对照中信号减弱；在盲法、预先指定的蛋白组比较中与独立人工分析一致。支持敏感临床数据的完全气隙部署、开源模型推理。作者把它写成「检索文献、生成假说、执行分析、从复杂数据出洞见」的共科学家，而不是自动发论文。
- **单篇小结**：这是给眼科科研 Agent 的正刊模板——**能断网、能留代码、能和独立人工分析对得上，才叫共科学家。** 复现青光眼进展 / 抗 VEGF 队列分析时应同时报：是否气隙、是否有隐藏评估队列、以及随机对照里信号会不会消失。不要把「数分钟完成数月分析」写成已经可替代统计师签字。不是眼病终点。

### 7. Recoverability-Centered Trajectory Governance for Long-Horizon Clinical AI Agents

- **日期 / 来源**：2026-11-22；*Journal of Medical Internet Research*。四川大学华西医院信息中心（Liu Jialin / Liu Siru）
- **链接**：https://doi.org/10.2196/110563 · https://pubmed.ncbi.nlm.nih.gov/43066768/
- **相关度**：方法可迁移（长程临床 Agent 的轨迹治理；概念框架，无前瞻数字）
- **摘要**：临床 AI 正在从单次预测走到会反复调工具、通信、规划和改变状态的 Agent，安全评估不能再停在单条输出。Agent 自己参与制造后续决策所依赖的临床状态，于是「每一步都说得通」仍可能合成不安全轨迹。作者提出以可恢复性为中心的轨迹治理：恢复裕度是人类–AI 系统在可接受纠正路径耗尽前改道的剩余机会；再授权边界是必须收回或收窄委托、等待人类判断的条件。可逆性是动作属性，可恢复性是轨迹属性。操作框架包括持续义务追踪、独立监测、显式再授权、权限收缩、优雅降级、独立升级和核实后的人类接管。评价应组合轨迹压力测试、恢复裕度指标、中断–接管试验和人群监测。纠正能力依赖及时监测和人类救援，因此可恢复性也是公平问题。
- **单篇小结**：这是给 RetinaGuard / EyeAgent / 预问诊 RCT 的安全课——**接受阈值锁的是单张图，管不住跨就诊的轨迹。** 接到抗 VEGF 注射室 / 青光眼随访 Agent 时应再加三栏：这一步之后还能不能改道、委托是否过了再授权边界、以及基层点有没有人能接管。本条没有数字，不要写成已经降低了漏诊。

### 8. CASCADE、卒中多 Agent 与 MedKGent：强制门控、影像接地、时间知识图谱

- **日期 / 来源**：*iScience* **2026-11-22**（PMID 43065768）/ *npj Digit Med* 电子出版 **2026-07-29**、本窗口索引（PMID 43045752，edat 11/18）/ *npj Digit Med* 电子出版 **2026-08-04**、本窗口索引（PMID 43058248，edat 11/20）
- **链接**：https://doi.org/10.1016/j.isci.2026.118246 · https://doi.org/10.1038/s41746-026-03066-7 · https://doi.org/10.1038/s41746-026-03058-7
- **相关度**：方法可迁移（分析步骤强制门控、影像接地多 Agent、时序医学 KG Agent；后两条电子出版跨窗口，仅因本周索引列入）
- **摘要**：**CASCADE**（Shaare Zedek / Helmsley）：规范与实现分离——验证什么、过什么标准由协议锁定，怎么做留给 Agent。约 25,000 例临床肿瘤基因组队列导出，未改协议迁移到 13,424 例三场景：能恢复已知信号，数据不够时报告效力不足而不是假阳性，并把一项临床相关伪迹从危害比 **0.84 纠正为 1.25**；两家独立多中心队列复现，三个 AI 系统高保真重复。**卒中多 Agent**：分诊 / 时间窗 / 多模态影像 / 禁忌证 / 最终治疗建议，外加 RAG。两中心连续 1,658 例可疑 AIS。单提示准确率 **0.636** → 多 Agent **0.755** → 再加 RAG **0.785**；Macro-F1 0.562 → 0.732 → 0.768。影像 Agent：非对比 CT 颅内出血灵敏度/特异度 0.490 / 0.999，CTA 大血管闭塞 0.883 / 0.851，CTP 缺损 0.939 / 0.739。**MedKGent**：两个 Agent 从 1975–2023 年超 1,000 万条 PubMed 摘要逐日建时序 KG，156,275 实体 / **2,971,384** 三元组；三元组有效率接近 90%；下游七个医学 QA 上抬了五家 LLM 的 RAG。
- **单篇小结**：三条分别对应眼科的三件事——分析 Agent 必须能把危害比从「保护」改回「有害」并留下代码（CASCADE）；OCT / 眼底工具槽要按任务拆 Agent，影像灵敏度必须单报（卒中条的出血 0.490 就是反例）；眼科知识图谱若要接 HalluciGuard / GUIDE，应写成时序、可冲突消解，而不是一次抽完。卒中 / MedKGent 电子出版早于窗口，只作方法对照。都不是眼病终点。

### 9. 皮肤科 agentic 共执业、医学 AI Agent 伦理综述与 MERIT

- **日期 / 来源**：*Cell Rep Med* 电子出版 **2026-11-01**、本窗口索引（PMID 43044568，edat 11/17）/ *Health Care Sci* **2026-11-17**（PMID 43048115）/ medRxiv DOI `10.64898/2026.11.02.26367125`（PMID 43060673，edat 11/20；首发约 11/2，仅因本周索引列入）
- **链接**：https://doi.org/10.1016/j.xcrm.2026.103171 · https://doi.org/10.1002/hcs2.70111 · https://doi.org/10.64898/2026.11.02.26367125
- **相关度**：方法 / 治理可迁移（共执业框架、伦理治理、基层认知障碍多 Agent；均非眼科）
- **摘要**：**皮肤科框架**：感知基线已有，下一步是临床主体性——推理核编排主动感知、专科工具和纵向记忆，从转诊走到管理计划。作者写明：还没有系统在皮肤科端到端验证；评价必须看完整临床回合，而不是回顾基准。**伦理综述**（清华）：系统检索医学 AI Agent 的伦理风险，给出适配中国医疗语境的治理框架。**MERIT**：基层用 Agentic CDSS 做早期认知下降的 EHR 接地风险识别与个性化护理，维护患者虚拟认知轨迹；本窗口可见摘要未给出前瞻终点数字。
- **单篇小结**：皮肤科文几乎是给 EyeAgent / OphthaAgent 写的下一页——**工具编排还没有端到端验证，就不能写成共执业。** 伦理综述可当院内采购卡。MERIT 形态接近预问诊 / 青光眼随访，但没有数字，只占位。
