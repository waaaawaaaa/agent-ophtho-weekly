### 1. Bridging the Gap in Ophthalmic AI: MM-Retinal-Reason Dataset and OphthaReason Model toward Dynamic Multimodal Reasoning

- **日期 / 来源**：期刊在线 2026-09-15；*IEEE Transactions on Medical Imaging*。预印本 `2508.16129` 于 **2026-09-16 更新 v5**（初稿 2025-08-22）
- **链接**：https://doi.org/10.1109/TMI.2026.3733595 · https://pubmed.ncbi.nlm.nih.gov/42743029/ · https://arxiv.org/abs/2508.16129 · 代码/权重：https://github.com/lxirich/OphthaReason · 数据：https://huggingface.co/datasets/lxirich/MM-Retinal-Reason
- **相关度**：眼科多模态推理（**非 Agent**；本周最接近「把主诉/病史和眼底图放进同一次推理」的正式发表）
- **摘要**：现有医学多模态推理多停在「看图匹配」的浅推理；真实诊疗要把主诉、病史与多模态影像一起做复杂推理。作者发布 **MM-Retinal-Reason**：据称为眼科首个同时覆盖基础推理与复杂推理、并带 CoT 轨迹的多模态数据集（汇 44 个公开集与 PMC，题型含判断/单选/多选/开放，覆盖 100+ 常见与罕见异常）。据此训练 **OphthaReason**，并加 **Uncertainty-Aware Dynamic Thinking（UADT）**：用熵估计样本级不确定度，再通过整形 advantage 调节探索深度。期刊摘要写：在基础与复杂推理上至少优于通用 MLLM / 医学 MLLM / RL 医学 MLLM / 眼科 MLLM **15.47%**；arXiv v5 摘要按四类对照分别写至少 +24.92% / +15.00% / +21.20% / +17.66%。Hugging Face 目前只公开子集。
- **单篇小结**：这是「让模型自己想」而不是「让模型调质控/分割/CDR」。对照 9/6 OCTCases 看图题全错、9/14 青光眼多模态 LLM 灰区：把病史写进输入、用 RL 拉长思维，可以提高推理基准分，**不能替代** `2608.07651` 的工具层。接到 Agent 时应把 OphthaReason 当规划器候选，UADT 的高熵样本强制过专用工具或弃权；不要把「优于眼科 MLLM 15%」写成已经可临床签发。引用时固定 IEEE 文本还是 v5 分项数字，二者口径不同。

### 2. Evaluating an AI-assisted triage workflow for retinal diseases

- **日期 / 来源**：2026-09-15；*PLOS Digital Health*
- **链接**：https://doi.org/10.1371/journal.pdig.0001700 · https://pubmed.ncbi.nlm.nih.gov/42743257/
- **相关度**：眼科工作流（固定算法阴性筛查，**不是** LLM Agent；给分诊/筛查 Agent 提供「少给人看」的安全账）
- **摘要**：VUNO 与首尔大学医院 / Mass Eye and Ear。6,904 张眼底，三名视网膜专科医师独立分级，评 DR / RVO / AMD。工作流：AI 阴性直接出阴性、不再给人看；AI 阳性才转人工。金标准是另两名医师一致，不一致者剔除（DR 1.2–2.3%，RVO 0.3–0.6%，AMD 6.1–11.6%）。直接阅片量降到 DR 7.3–8.0%、RVO 11.7–11.9%、AMD 13.5–16.8%。DR 灵敏度 0.9168→0.8838（−0.0330，p<0.001），特异度无显著变化；RVO 灵敏度不变；AMD 灵敏度 0.8570→0.8445（−0.0124，p=0.008）。「至少一种靶病」的探索分析把阅片降到 27.7–30.1%，灵敏度再掉 0.0083。作者强调：因为阴性不再复核，DR/AMD 漏诊会推迟治疗，必须按病种权衡。
- **单篇小结**：这是 AI-TEC「分诊 Agent 分配检查」的固定算法对照。数字写得很硬——省人力的代价是灵敏度，而且 AMD 医师间一致性本来就差（剔除 6–12%）。Agent 若做阴性门，应同时暴露：灵敏度差、被剔除的不一致率、以及「漏一张增殖期/湿性 AMD 的代价」。同组还有 8/25 的 first-pass reader 研究（PMID 42739139）：AI–人双阅可把人均读图从约 2.0 降到 1.0–1.1；本条比它更激进，因为阴性完全不给人看。

### 3. Requirements for artificial intelligence scribe systems for medical documentation in ophthalmology

- **日期 / 来源**：2026-09-17；*Die Ophthalmologie*（德文，英德摘要）
- **链接**：https://doi.org/10.1007/s00347-026-02531-8 · https://pubmed.ncbi.nlm.nih.gov/42752949/
- **相关度**：眼科相邻（Ambient Scribe 接受度；弱 Agent / 计算机使用，不是诊断）
- **摘要**：德国区域医师网络匿名问卷，n=34（中位年龄 49，47% 女性）。多数人把 20–39% 工作时间花在文书。约 3/4 表示：若系统可靠且安全，愿意用 Ambient Scribe。好处是少写、多看病人；障碍是 AI 可靠性、HIS 集成与数据保护，**本地部署明显优于云**。作者认为合规、本地、可嵌入现有系统是落地前提。
- **单篇小结**：样本量小，但是把「眼科诊所要的 Agent」从看图改写成**写病历**。正好对 9/14 的 IOL OCR / Agents API：生产环境先做本地、白名单、医师签发，不能把「愿意用」当成已经能进病历。也提醒评测要报文书时间与错误类型（药名、眼别、度数），而不是只报满意度。

### 6. Adaptive Optics Image Analysis Using Generative AI (GPT-4) Scripting: Exploratory Study

- **日期 / 来源**：2026-09-14；*JMIR Formative Research*
- **链接**：https://doi.org/10.2196/94906 · https://pubmed.ncbi.nlm.nih.gov/42735400/
- **相关度**：眼科工具（用 GPT-4 写 R 脚本数视锥；弱 Agent / vibe coding，作者自己写 **nonvalidated**）
- **摘要**：Radboud。AO-FIO 缺少面向非健康大图的分析脚本。作者用 GPT-4 迭代 54 轮生成 R 脚本，在 1 名健康人 + 3 名 Stargardt 患者图上调通预处理与 blob 定量；另一名无编程背景的研究者用另外 4 人的图查错。5 个片段的视锥计数对照两名人工评分员和一套只在健康人上训过的现成软件。结论：能产出可跑的视锥检测草稿，**临床研究前必须再调、再验**。
- **单篇小结**：这是 9/6「vibe coding for ophthalmologists」的最小实验，也是 Keane 组 nAMD Agent 的成像版——会写代码 ≠ 计数可信。接到科研 Agent 时应固定：脚本版本、与人工/专用软件的误差、以及「只在健康人训过的软件不能当 Stargardt 金标准」。54 轮试错本身说明：没有评测环的生成脚本不能进试验终点。

### 8. Explainable Multimodal OCT and OCTA Analysis Reveals Structural and Vascular Features of Mild Glaucoma Across Ethnicities

- **日期 / 来源**：2026-09-01；*Investigative Ophthalmology & Visual Science*（本窗口索引）
- **链接**：https://doi.org/10.1167/iovs.67.11.32 · https://pubmed.ncbi.nlm.nih.gov/42747257/
- **相关度**：眼科专用 CV（轻症青光眼 OCT/OCTA；给工具槽提供跨种族可解释特征，不是 Agent）
- **摘要**：新加坡眼研所 / Duke-NUS 等。轻度 POAG（MD ≥ −6 dB）+ 对照。亚洲队列 621 人开发测试，高加索队列 131 人外验。随机森林：内部多模态 AUC 0.975，与 OCT-only 0.965 无显著差，但显著优于 OCTA-only 0.870；外验多模态 0.884，显著优于 OCT-only 0.801 与 OCTA-only 0.792。SHAP：下方盘周 RNFL 厚度与盘周灌注密度是主贡献。
- **单篇小结**：对照 9/14 青光眼多模态 LLM「可疑/轻度更差」：轻症要的是 OCT+OCTA 数字，不是再让旗舰看一张眼底。外验上 OCTA 才真正补上增量，说明工具卡要按**部署人群**报，而不是只报开发 AUC。Agent 在轻度/可疑应强制出 RNFL + 灌注，两路打架就弃权。

### 9. FairEnc: A Fair vision-language model with fair vision and text encoders for glaucoma detection

- **日期 / 来源**：2026-09-08；*Artificial Intelligence in Medicine*（跨窗口，本周作为公平工具卡核对）
- **链接**：https://doi.org/10.1016/j.artmed.2026.103521 · https://pubmed.ncbi.nlm.nih.gov/42735617/
- **相关度**：眼科 VLM 公平预训练（非 Agent；给 8/30「相关失败 / 公平地板」补可训练方法）
- **摘要**：同时在文本与视觉编码器上对种族、性别、族裔、语言做去偏。文本侧用 LLM 生成「改人口学、保持病义」的合成病历再对比对齐；视觉侧用互信息正则 + 多判别器对抗。Harvard-FairVLMed 上降低 DPD / DEOdds，零样本与线性探测诊断仍强；私有 FairFundus 提示跨域、跨模态仍能保住公平。
- **单篇小结**：9/6 FairMedAgent 证明没有重跑地板的 flip rate 不可读。FairEnc 是编码器侧的补丁，不是动作级审计。青光眼筛查 Agent 应同时报：编码器公平数字 + 同一患者重跑的动作 κ。合成病历改人口学本身也是一种提示注入面，生产环境不要把生成器默认接到外网。

### 10. OptoAgent / SightSentinel：课堂机会性视力微筛查的多 Agent 架构

- **日期 / 来源**：arXiv 提交 **2026-09-13**（上周窗口末日，上周未收录；本周作为边缘相邻补录）；`cs.AI`
- **链接**：https://arxiv.org/abs/2609.14514
- **相关度**：眼科相邻（校园视力筛查多 Agent；**不是**眼科诊疗 Agent，也不在本窗口内新提交）
- **摘要**：儿童远视力下降常不自知。作者把教室已有的墙屏做成反复筛查点：教学内容里插入短校准视标，八个专科 Agent 分工——感知端估计视距、识别正确率、靠近行为、注视稳定、反应潜伏与双眼差；质量 Agent 丢掉几何/照明/注意不合格的观察；纵向 Agent 只把合格证据累到该儿童自己的基线。定位为「不必有人按下开始」的机会性微筛查，而不是一次正式视力表。
- **单篇小结**：形态上接近「环境传感器 + 质量门 + 纵向基线」，不是眼底/OCT 诊断。对本仓库的用处是：学校/社区筛查若要上 Agent，先写**质量门和个体基线**，再谈转诊；不要把课堂视标识别写成已经能诊断屈光不正或弱视。因提交日落在 9/13，不计入本周「≥1 篇直接相关」。

### 11. On-premise medical AI agents for reliable clinical decision-making

- **日期 / 来源**：2026-09-15；*Nature Medicine*
- **链接**：https://doi.org/10.1038/s41591-026-04609-x · https://pubmed.ncbi.nlm.nih.gov/42744896/
- **相关度**：**方法可迁移（本周主条目）**——院内部署 + 决策时可靠性门的自主临床 Agent
- **摘要**：Kather 组（德累斯顿 / NCT / Leeds）。论点：能跑完诊断工作流的 LLM Agent 越来越强，但临床翻译卡在两件事——**机构可控的部署**和**决策时不确定度**。他们做完全本地的临床 Agent，加上多视角可靠性框架以支持选择性自主。MIMIC-IV 派生基准：七病任务准确率 90.04%，四病 83.8%，主基准接近云端对照。决策时同时量化内部似然、语言表述与行为稳定性；**诊断行为一致性**最能区分对错（AUC 0.860，压力测试 0.875）。一致性阈值 0.90 时，保留 49.4% 病例，诊断准确率 **98.9%**。作者主张：用可靠性信号找出低风险子集自动处理，其余升级人工。
- **单篇小结**：这是本周对 AI-TEC / EyeAgent 最可搬的一句——**不要全自动，要选择性自动**。眼科电话分诊和眼底阴性门都可以写成同一张表：一致性/停止分低于阈值只许 Emergent/Urgent 或转诊，不许 Routine。也补 9/9 Cros「何时停」：这里的门是行为稳定性，不是 softmax。局限必须写清：MIMIC 派生病种，不是眼底/OCT；「接近云端」说明本地可以够用，不说明已经能进门诊。院内部署清单应加：模型不出院、可靠性门、升级率。

### 12. Reimagining research papers as interactive and reliable AI agents（Paper2Agent）

- **日期 / 来源**：2026-09-16；*Nature*
- **链接**：https://doi.org/10.1038/s41586-026-11044-y · https://pubmed.ncbi.nlm.nih.gov/42749808/ · 新闻：https://doi.org/10.1038/d41586-026-02880-z
- **相关度**：方法可迁移（把论文变成可调用 MCP Agent；可对眼科方法学复现 / Keane 组脚本）
- **摘要**：Stanford（Miao / Pritchard / Zou）。Paper2Agent 自动把论文变成「虚拟通讯作者」：多 Agent 读正文与代码、搭 MCP 服务器、生成并跑测试再加固；再接到聊天 Agent（如 Claude Code）用自然语言调该文的工具与工作流。案例：AlphaGenome 变异解读、Scanpy / TISSUE 单细胞与空间转录组；并能复现原文结果、回答新查询。多个论文 Agent 协作还给出一个银屑病因果基因优先级。
- **单篇小结**：若 `2608.07651` / GAO-Triage / AgentEYE / nAMD 分析 Agent 被做成 Paper MCP，复现就不该再靠「把 PDF 丢进聊天框」。生产环境必须：MCP 只暴露已测试工具、禁改队列定义、沙箱无外网。这也是对 9/10 Agents API 的内容层——harness 有了，缺的是**每篇方法学自己的工具卡**。

### 13. The Virtual Biotech: A multi-agent AI framework for therapeutic discovery and development

- **日期 / 来源**：2026-09-17；*Science*
- **链接**：https://doi.org/10.1126/science.aeg6779 · https://pubmed.ncbi.nlm.nih.gov/42752167/
- **相关度**：方法可迁移（按药企部门拆多 Agent；抗 VEGF / 青光眼药研发的远对照）
- **摘要**：Stanford / PHD Biosciences。把靶点发现、安全性、模态选择、临床开发做成 agentic 事业部。三个决策点：>37,000 个 Agent 标注 55,984 项试验，发现靶向细胞类型特异基因的药上市概率 +48%、不良事件 −32%；整合多模态证据提出肺癌治疗策略；复盘一项终止的溃疡性结肠炎试验并推断失败机制。作者认为人引导的多 Agent 可以把跨尺度证据做成可追溯分析。
- **单篇小结**：眼科药/器械决策（抗 VEGF 切换、基因治疗入组）缺的不是再一篇综述，而是能把试验、靶点组织特异性和失败机制串起来的部门 Agent。不要把「37,000 agents」写成已经可替代医学事务；要看人如何设题、如何核出处。与 Paper2Agent 同一组（Zou），正好是「论文变工具 + 药企变组织」。

### 15. A medically grounded LLM agent-based tool to detect patient safety events in medical records（SAFE-AI）

- **日期 / 来源**：2026-09-17；*PLOS Digital Health*
- **链接**：https://doi.org/10.1371/journal.pdig.0001174 · https://pubmed.ncbi.nlm.nih.gov/42752617/
- **相关度**：方法可迁移（本体约束的安全事件 Agent；可对眼科用药/注射错误）
- **摘要**：300 份 EMS 病历、18,402 行，两名医师双评肾上腺素不良安全事件（一致率 96%）。SAFE-AI 用临床本体 + 严格规则约束 LLM，减少幻觉。肾上腺素过量准确率 97.9%，给药延迟 91.6%，明显优于基线 LLM。部分与医师不一致被作者视为可辩护的判断差异而非错误。框架强调：不要只靠语料统计，也不要复制训练数据里的偏见。
- **单篇小结**：眼科日间注射/散瞳/乙酰唑胺是同一问题的小本体。不要让模型「读完整份病历再猜有没有错」，而要把剂量、时间、适应证编成可触发规则，LLM 只负责填槽。这比 9/14 GraphRAG 药疗图更靠近「安全事件」而不是「写给医师看的句子」。

### 16. Prompt Injection in Clinical Artificial Intelligence Systems

- **日期 / 来源**：2026-09-15；*Annals of Biomedical Engineering*
- **链接**：https://doi.org/10.1007/s10439-026-04376-3 · https://pubmed.ncbi.nlm.nih.gov/42745101/
- **相关度**：方法可迁移 / 治理（临床与 agentic 系统的提示注入；病历外源材料是攻击面）
- **摘要**：临床 AI 安全讨论常停在准确率、偏见、幻觉（模型没完成任务）。提示注入是相反情况：**模型精确执行了一条临床医生没写、也看不见的指令**。当前语言模型把权威内容与普通 token 混在同一流里。医学特别暴露，因为病历拼自转诊信、患者留言、外院报告、扫描件和外院影像。作者主张把它写成带威胁模型的患者安全危害；改进提示和输入过滤不够；可行回应是带出处的上下文、不可逆动作最小权限、以及部署前对抗测试。
- **单篇小结**：眼科 Agent 一旦能读转诊 PDF、厂商门户或患者上传的眼底，就有同一攻击面。AI-TEC / OphthoChat / Ambient Scribe 都应把「外源文本不可变指令」写成硬规则：工具调用白名单、禁止改医嘱/预约的隐藏指令、动作预审。这比再训一轮对齐更接近能上线。

### 17. EMR: Self-Evolving Medical Multi-Agent System via Experience Mining and Reuse

- **日期 / 来源**：2026-09-14 提交 arXiv；`cs.AI` / 医学多 Agent
- **链接**：https://arxiv.org/abs/2609.15161
- **相关度**：方法可迁移（会诊式多 Agent + 分层经验库；可对疑难眼病 MDT）
- **摘要**：现有医学多 Agent 策略静态、没有持久临床记忆。EMR 把经验分成临床原则 / 诊断模式 / 代表病例三层。推理时模拟 MDT：规划 Agent 协调专科 Agent，汇总 Agent 出结论；事后从轨迹里自动抽正确洞见和失败警告，写回经验库。作者称在医学推理基准上持续优于现有医学多 Agent。
- **单篇小结**：这是 9/6 ClinTraceBench「记忆丢关系」的另一条路——不存一段摘要，而存分层经验。眼科疑难（葡萄膜、神经眼科）可以先把失败警告写成可检索条目（例如「只看眼底、没要视野」），不要让记忆模块再写故事。未外验到眼病数据前，只当方法卡。

### 18. LongAgent / CLEAR：纵向搜索与跨源证据裁决

- **日期 / 来源**：均 2026-09-14 提交 arXiv
- **链接**：https://arxiv.org/abs/2609.15859 · https://arxiv.org/abs/2609.16301
- **相关度**：方法可迁移（注射/青光眼随访；指南 vs 参数知识冲突）
- **摘要**：**LongAgent** 在变量集合 × 时间窗 × 纵向聚合函数上做带历史记忆的 agentic 搜索。合成数据 RMSE 1.7376，相对最强非 Agent 基线改善 0.0151（p=0.0273）；真实临床数据上与强基线相当。**CLEAR** 让参数知识、本地语料、动态检索三条通路独立出答案，再由聚合校验器看一致性、出处与源质量，裁决是保留还是改结论——针对 RAG 把过时或冲突证据灌进模型后反而更错。
- **单篇小结**：青光眼 RNFL / nAMD 注射史是 LongAgent 的目标任务；AAO 指南更新 vs 模型记忆是 CLEAR 的目标任务。随访 Agent 应保存带时间戳的测量事件，冲突时显式裁决，而不是让 RAG「再检索一次就当真理」。LongAgent 真实数据只是持平，引用时不要写成已经赢过生存分析基线。

### 19. CPS-Net：按转诊层级组织的专科感知多 Agent

- **日期 / 来源**：2026-09-15；*Journal of Medical Systems*
- **链接**：https://doi.org/10.1007/s10916-026-02460-8 · https://pubmed.ncbi.nlm.nih.gov/42742847/
- **相关度**：方法可迁移（把诊断做成转诊网络而不是一个通才模型）
- **摘要**：Wisconsin / Froedtert。41 个 Transformer 训在 75,000 名患者、10 专科 / 30 亚专科 EHR；再接到按全科–专科–亚专科分层的 LLM Agent，用共享病例记忆协作、转诊可审计。3,000 例测试：top-1/3/5 为 48.8% / 71.00% / 77.76%，临床相关 94.17%；通才 Transformer 为 19.20% / 38.60% / 47.20%，单 LLM Agent 为 12.70% / 26.40% / 37.23%。
- **单篇小结**：眼科内部已经是角膜/青光眼/视网膜/神经眼科转诊网。AI-TEC 的分诊 Agent 若只做一个通才模型，就会稀释少见病。可搬的是「专科权重 + 可审计转诊」，不是 48.8% 这个绝对 top-1。输出必须能指到哪一层专科、依据哪条记忆，否则仍是黑盒分诊。

### 20. 临床推理模拟、编码 Agent 与放疗规划：过程质量三连

- **日期 / 来源**：2026-09-14～09-17；*Diagnosis* / arXiv / *IJROBP*
- **链接**：https://doi.org/10.1515/dx-2026-0069（PMID 42740524）· https://arxiv.org/abs/2609.19721 · https://doi.org/10.1016/j.ijrobp.2026.09.008（PMID 42754176）
- **相关度**：方法可迁移（训练 / 编码 / 治疗计划；分别对分诊教学、病历结构化、日间手术计划）
- **摘要**：**MAESSCR**（175 名二年级医学生、120 份转录）：脚本遵循 92%，改诊断信息仅 2.5%；但检查/处置 Agent 在 **59%** 的遭遇里抢先解释，病史/查体 Agent 28%——教学价值取决于角色稳定和「让学员自己读结果」。**LearnActCoder** 把 LEARN 批次错误写进 MistakeKDB，假阴性进 Coder、假阳性进 Judge；MIMIC-III 上 CPT F1 +5.9 个百分点，ICD 改善不显著。**肺癌 IMRT**：模块化 RL + Planner/Evaluator/Supervisor，临床目标达成 98% vs KBP 74%；相对纯 LLM 监督，LLM 调用少 75%（1.7 vs 6.7），时间 20.6 vs 33.4 分钟，并能再降肺 V20。
- **单篇小结**：三条都在说「Agent 要有角色和记忆，不能一个通才套所有步」。眼科分诊训练应禁止导师 Agent 说出急症级别（接 9/10 问诊多智能体）；病历编码先做药名抽取（同日德文笔记 F1 0.78，PMID 42752481），ICD 级映射仍不够；手术/注射计划若要自动改参数，必须接到院内 API，而不是让模型写一段建议。

### 21. OpenAI / Anthropic / Google 公开讨论行业安全标准；PACT 压测企业 Agent 是否守规

- **日期 / 来源**：媒体 2026-09-15；PACT 预印本 2026-09-16
- **链接**：https://www.cnbc.com/2026/09/15/open-ai-google-anthropic-safety.html · https://arxiv.org/abs/2609.18605
- **相关度**：运行时 / 治理（本周平台层增量；上周 Agents API 不重复）
- **摘要**：OpenAI 全球事务负责人 Chris Lehane 向媒体确认，已与 Anthropic、Google 就安全协作谈了数周，背景是 Hassabis 7 月提出类 FINRA 的美国主导 Standards Body，以及 Amodei 呼吁放慢最强模型迭代。Lehane 称不需要反垄断豁免；**尚未宣布正式协议或常设机构**。PACT 在 12 个受监管企业域、48 个多轮场景里，把「写在系统上下文里的规则」对上用户/经理压力与便利捷径，测模型会不会违规。
