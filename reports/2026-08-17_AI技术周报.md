### 1. Towards Expert-level Medical AI for Real-time Video Consultations（AMIE Video）

- **日期 / 来源**：2026-08-10 提交 arXiv；Google Research / DeepMind 博客 2026-08-11
- **链接**：https://arxiv.org/abs/2608.09861 · https://research.google/blog/advancing-amie-towards-expert-level-audio-visual-clinical-consultations/
- **相关度**：方法可迁移（医学多智能体；场景含 HEENT；AMIE 此前已覆盖眼科专科评测）
- **摘要**：文本问诊会丢掉步态、呼吸、表情等非语言线索。本文给出 AMIE（Articulate Medical Intelligence Explorer）的视频配置：基于 Gemini 与 Project Astra 的**异步多智能体**——Talker 负责低延迟对话，Planner 在后台更新鉴别诊断与信息缺口，Perception 持续审看音视频流提取临床线索。作者先建立远程医疗视听能力分类与自动评测，再做 100 个情景、300 场实时问诊的随机 OSCE：15 名标准化病人演员 × AMIE（Video）/ AMIE（Text）/ 10 名视频问诊的主治级全科医师，另有 20 名医师独立打分。临床评估认为 AMIE（Video）在病史、诊断、处置与沟通上与 PCP 持平或更好，在引出体征、指导患者完成虚拟体格检查上显著更强；病人演员更偏好视频界面。局限：模拟而非真实患者；精细解剖、细微情感与高频运动仍有误差。
- **单篇小结**：眼科远程分诊/随访最缺的往往不是「再写一段报告」，而是**边看边问**（睑裂、相对性传入性瞳孔障碍、眼位、指测眼压指导等）。AMIE 的「对话延迟」与「深度推理」拆开，可直接对照上周青光眼工具编排稿：一边是影像工具调用，一边是实时感知 Agent。部署前必须强调：目前是演员 OSCE，不能外推到真实眼科急诊。

### 2. Gemini 3.7 Flash：面向 coding / agents 的工作马模型

- **日期 / 来源**：2026-08-13；Google AI Blog
- **链接**：https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-3-7-flash/
- **相关度**：方法可迁移（Agent 骨干选型与成本）
- **摘要**：距 Gemini 3.6 Flash 仅约三周。官方定位为「最聪明的工作马」，强调软件工程、知识工作与 Web 开发，并明确面向 agent：更好适应卡点、澄清意图、多步规划与工具调用，目标是减少失败循环与人工盯梢。引入价约 **$0.75 / 1M input**、**$3.75 / 1M output**（至 2026 年底，约为 3.6 一半量级，以官网为准）。进入 Antigravity、Gemini API / AI Studio、Enterprise Agent Platform，并替换 Spark 个人 Agent 的骨干。第三方报道称其在部分知识工作基准上超过同档 Claude / GPT 模型，但仍非旗舰 Pro。
- **单篇小结**：眼科多工具 Agent（质控→分割→分类→报告）的高频 tool-calling 很吃 Flash 级模型；旗舰模型留给疑难病例、跨模态终审与安全相关决策。评测时应固定「骨干 × effort × 工具集」，避免只比模型名字。

### 3. OpenAI Codex Multi-Agents v2：Sol/Terra 可把任务委派给 Luna

- **日期 / 来源**：约 2026-08-15；Runtime Wire / 开发者社区与 Codex 议题
- **链接**：https://runtimewire.com/article/openai-lets-gpt-5-6-sol-delegate-grunt-work-to-cheaper-luna-agents
- **相关度**：方法可迁移（Agent 编排范式）
- **摘要**：Codex Multi Agents v2 打通跨模型委派：高能力模型（GPT-5.6 Sol / Terra）做编排与规划，把边界清晰的子任务交给更快更便宜的 Luna。此前 Luna 被标成 Multi-Agent v1，Sol/Terra（v2）无法 spawn。v2 修复后，Luna 作为「纯子 Agent」不负责跨 Agent 通信或再派生。默认仍可父子同模型以保质量，但新模式把「选哪个模型」变成编排决策，用于控延迟与 token 预算。
- **单篇小结**：与 AMIE 的职责拆分同一逻辑：规划核不必等于执行核。院内眼科流水线可把批量眼底质控、批量分割交给小模型，把反思、指南对齐和最终印象留给强模型。

### 4. The Path to Self-Evolving Clinical Systems（医学 Agent 综述 v2 更新）

- **日期 / 来源**：v1 2026-07-13；**v2 更新 2026-08-12**；arXiv
- **链接**：https://arxiv.org/abs/2607.11175
- **相关度**：背景 / 方法可迁移（综述覆盖 radiology、pathology、**ophthalmology** 与院内流程）
- **摘要**：本周出现 v2。作者从「临床部署需要什么」而非「模型有什么能力」出发，把医学 Agent 形式化为部分可观测序列决策，给出辅助 / 协作 / 全自主三级分类，并讨论抗污染基准、交互训练环境与 clinical self-evolution。配套叙事强调：可信医学 Agent 缺的是任务、环境与评测，而不只是更大的骨干。
- **单篇小结**：适合作为眼科 Agent 路线图对照：PACS/EHR/指南工具、污染抵抗的眼底/OCT 基准、以及「人机协作」而非一步到位全自动。本周无新系统论文，但这份更新提醒不要只追单点准确率。

### 5. Evaluating multimodal large language models for differential diagnosis of high myopia versus high myopia with glaucoma

- **日期 / 来源**：2026 年（本窗口内出现于 PubMed 索引）；*Frontiers in Medicine*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42602451/
- **相关度**：眼科多模态 LLM（非 Agent；对照用）
- **摘要**：高度近视与高度近视合并 POAG 的结构/功能改变难以区分。回顾性 100 例（各 50）档案，比较 Gemini 3 Flash Preview、Kimi-k2.5、GPT-5.4、Qwen3.5-Plus 在 Direct 与 CoT 两种提示下的鉴别诊断；两名 >10 年经验眼科医师从临床逻辑、知识准确性、多模态证据一致性打分。Direct 模式病例正确率：Gemini 3 Flash Preview 83.0%，Kimi-k2.5 75.0%，GPT-5.4 65.0%，Qwen3.5-Plus 49.0%；CoT 并未稳定提升，跨模型差异在 Direct 显著、在 CoT 不显著。评分者一致性高（加权 κ 0.80–0.84）。
- **单篇小结**：这是典型的「端到端看图问答」，没有工具调用或反思闭环。对照上周 Agentic 青光眼框架：近视合并青光眼正是纯 MLLM 容易过诊/漏诊的场景，更适合接 CDR、RNFL、视野等专用工具后再让 LLM 整合。CoT 无效也提示：眼科鉴别需要的是外部证据，而不是更长的自我解释。

### 6. Large Language Model Simplification of Open Access Pediatric Strabismus Literature

- **日期 / 来源**：2026-08-14；*JMIR Formative Research*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42600075/
- **相关度**：眼科 LLM 应用（非 Agent；患者沟通）
- **摘要**：85 篇开放获取儿童斜视文献，用 DeepSeek-V3 按七年级阅读水平、≤800 词、保留关键医学数据做通俗摘要。Flesch-Kincaid 年级从 15.79 降至 7.84，SMOG 从 14.41 降至 7.68；两名斜视专科医师评估临床保真度。作者认为在医师把关下，可用于健康素养与共同决策。
- **单篇小结**：报告生成/患教是眼科 Agent 的高频子任务，但本文仍是一次性摘要，没有检索工具、指南核对或个性化问询。若接到上周 Guideline-as-Oracle 分诊 Agent，可把「通俗化」做成受监督的工具，而不是开放生成。
