### 1. Large Language Model-Generated Patient Education Materials in Pediatric Ophthalmology: A Scoping Review

- **日期 / 来源**：电子出版 **2026-09-30**；本窗口 PubMed 可见；*Clinical Ophthalmology*
- **链接**：https://doi.org/10.2147/OPTH.S635998 · https://pubmed.ncbi.nlm.nih.gov/42830931/
- **相关度**：眼科相邻（儿科患教 LLM；**不是**工具编排或诊疗 Agent；本周最接近「把 LLM 交给眼科」的新索引）
- **摘要**：Alberta / Toronto。PRISMA-ScR，检索 2015-01～2025-07。20 项研究（2023–2025）评了 3,286 份 AI 生成材料、14 个 LLM。17 项报可读性：研究级 LLM 评价里 59%（37/63）超过推荐的 8 年级；ChatGPT-4o 可接受率 52%，ChatGPT-3.5 仅 18%（非头对头）。中位可理解性（PEMAT-U）过了 ≥70% 门槛。学会材料更准、质量更高，但显著更难读。没有一项按所用框架把输出明确标成幻觉，治疗相关内容不完整很常见。只有 2 项评了患者/照护者视角。作者主张：LLM 适合规模化生成，但必须放进医师监督工作流，并补共设计、多模态教育。
- **单篇小结**：这是 9/14 RCOphth CustomGPT 和上周眼整形 GPT-4o mini 的儿科版——**看起来好懂，不等于照护者读得完、做得了**。接到 AI-TEC / 患教 Agent 时应同时暴露：年级、可执行步骤、以及有没有患者实测。不要把 PEMAT-U ≥70% 写成已经可以无人签发进门诊。电子出版早于窗口起始日，仅因本周索引列入，不计入「≥1 篇直接相关」。

### 2. Comparison of Two AI Chatbots for Diagnosis and Providing Treatment Suggestions in Retinopathy of Prematurity

- **日期 / 来源**：2026-10-07；*Journal of Medical Internet Research*
- **链接**：https://doi.org/10.2196/86726 · https://pubmed.ncbi.nlm.nih.gov/42842945/
- **相关度**：眼科工作流（ROP 诊断 + 治疗建议的聊天机器人对照；**不是** Agent）
- **摘要**：深圳眼科医院 / 南医大 / 同仁。70 名需治 ROP 婴儿、140 眼；结构化临床文本 + 广角眼底。两阶段提示：先出 zone / stage / plus，再给治疗建议；金标准是临床共识。Gemini 2.5 Pro vs ChatGPT o4-mini：分区 79.3% vs 85.7%，分期 64.3% vs 70.0%，需治灵敏度 93.6% vs 90.7%（均 *P*>0.05）。Plus 识别 Gemini 显著更好（77.1% vs 57.1%，*P*=0.006）；按金标准诊断写治疗方式时 o4-mini 更贴指南（65.0% vs 39.3%，*P*=0.01）。两位专科用 5 分 ROP-GQS：治疗建议 o4-mini 更好（*P*=0.001），诊断分相当。
- **单篇小结**：上周 ROP 经济学问「值不值得铺」；本条问「聊天机器人到底会认 plus 还是会开激光」。可直接搬到筛查 Agent：**看图槽和处置槽必须分开评**，不要用一个「需治灵敏度」把 plus 漏诊和治疗偏离藏起来。70 例、全是需治，阴性门和过度治疗都测不到。

### 8. When the Algorithm Speaks First: Trust, Reliance and the Reconstruction of Clinical Metacognition

- **日期 / 来源**：2026-10-06；*Journal of Evaluation in Clinical Practice*。Shaare Zedek / Hebrew University **眼科**组
- **链接**：https://doi.org/10.1111/jep.70652 · https://pubmed.ncbi.nlm.nih.gov/42836783/
- **相关度**：眼科治理（以视网膜影像为最强案例，讨论「算法先开口」之后医师该持什么认识态度）
- **摘要**：概念分析。诊断 AI 越来越在医师形成判断之前给出结论；现有「批判性评价算法输出」课程建立在两条不稳的地基上——泛化元认知训练并不提高诊断准确率，以及它要求医师养成「放松核验」的态度。作者区分 trust 与 reliance：信任=依赖且撤回对可靠性条件的监视。监管批准、机构采用和发表性能可以支持信任「生产该系统的装置」，但**不能**单独或合起来担保对**这一位患者**输出的依赖。算法与人类认识依赖有三个不对称：不可追问/问责、错误落在整类患者、保证属于人群而决定属于个人。因此临床元认知必须改成三种可教、可考的能力：校准过的依赖、对分布式认识劳动的觉察、以及对「被信心掩盖的不确定度」的警觉。机构若不提供追问手段和追问时间，教育改革与治理改革是同一件事。
- **单篇小结**：这是本窗口眼科期刊里对 AgentEYE / MedRSI / AI-TEC 最可搬的一句——**评的不是医师「信不信 AI」，而是有没有手段和时间为这一眼撤回依赖**。院内清单应加：输出能否被追问、弃权是否可见、以及「先出结论」是否被禁止在培训场景默认打开。同窗口 *Ophthalmology*（PMID 42831844，10/5）Stanford 的「机器 vs 人垂直杯盘比」几乎没有可供核对的摘要，仅记题、不展开数字。

### 9. LongCAF: A longitudinal context-constructive agentic framework for LLM-supported hypertension self-management

- **日期 / 来源**：2026-10-08；*Journal of Biomedical Informatics*
- **链接**：https://doi.org/10.1016/j.jbi.2026.105108 · https://pubmed.ncbi.nlm.nih.gov/42849682/
- **相关度**：**方法可迁移（本周正刊主条目）**——6 个月真实世界部署的纵向记忆 + 意图路由 + 安全升级 Agent
- **摘要**：浙大 / 解放军总医院海南医院。长期高血压自我管理要求患者天天做决定、并知道何时就医。常规问答在表达碎片、上下文不全、意图漂移时不够用。LongCAF 五模块：纵向上下文记忆、意图感知路由、交互综合、主动补问、安全升级到医师。6 个月真实部署：患者级上下文完整度 42.9%→57.1%，新增 79,290 条临床相关条目，非血压域占 49.3%；69% 的面向患者输出有患者特异检索支撑；候选问题采纳率 84.4%；意图路由 micro-F1 0.911；端到端安全升级 precision 0.915、recall 0.977、F1 0.945。医师和患者评价认为回复临床相关、合上下文、对继续自我管理有用。
- **单篇小结**：这是对 TeleGlaukos「先写症状分支和升级规则」的 LLM 版，而且是**真随访**不是模拟对话。青光眼/抗 VEGF 随访 Agent 应抄这五槽：记忆、意图、综合、补问、升级——尤其是升级召回必须单独报。不要把「完整度从 43% 到 57%」写成已经可以替代门诊。病种不是眼病；安全门的金标准未在摘要展开，引用前对原文表。

### 10. KGR-MAS: Knowledge Graph-Enhanced Multi-Agent LLM Framework for Evidence-Based Medical Diagnosis and Clinical Decision Support

- **日期 / 来源**：2026-10-08；*IEEE Journal of Biomedical and Health Informatics*
- **链接**：https://doi.org/10.1109/JBHI.2026.3740738 · https://pubmed.ncbi.nlm.nih.gov/42848569/
- **相关度**：方法可迁移（KG 路径拆任务 + 多 Agent 短记忆 + 检查点 RAG）
- **摘要**：KGR-MAS 三件套：用知识图谱诊断路径做可执行子任务分解并动态分配 Agent，同时用路径初始化共享短时记忆；语言级 LSTM 式门控 + Transformer-XL 管跨 Agent 信息流；KG 引导的 RAG-STM 在诊断检查点检索并把证据写回短时记忆。自建医学 KG embedding Hits@1 32.8%、MRR 0.498。MedQA 准确率 **87.2%**（+14.4%），四个开放域集平均 77.4%（+29.0%），作者称超过 GPT-o1 的 72.0%。
- **单篇小结**：形态上接近「指南路径变成工具注册表」，不是让通才模型自由讨论。接到 GAO / 青光眼指南冲突时应先有可执行路径，再谈多 Agent。数字是选择题基准，不是门诊轨迹；「超过 o1」必须对同一划分和同一提示重跑后再引用。

### 11. MedZERO: Self-Evolving Agents for Open-Ended Medical Reasoning Through Controlled Knowledge Accumulation

- **日期 / 来源**：arXiv 提交 **2026-10-06**；评论栏写 accepted by NIPS 2026
- **链接**：https://arxiv.org/abs/2610.08327
- **相关度**：**方法可迁移（本周预印本主条目）**——开放医学推理上的自进化，把探索知识和持久知识拆开
- **摘要**：现有自进化方法最强的地方是数学/代码——答案可精确核对或可执行。医学推理开放、知识密集、往往只能部分核实。MedZERO 让 Examiner 在能力前沿出题、Reasoner 用知识图谱检索和可选网页搜索多轮作答；训练时把临时探索三元组与过滤后才进检索库的持久知识分开，并禁止当前步用自己刚生成的证据。骨干 Qwen3-4B / 8B。开放评测（PubMedQA、MMLU-Pro health、MedBullets op4/op5、MedBrowseComp、MedXpertQA）上，4B 平均 12.9%→**34.9%**，8B 34.9%→**53.5%**；相对最强自进化基线最多 +13.7。消融：前沿课程、受控知识准入、Reasoner 优化必须同时在；默认准入带 [0.30, 0.80]。三轮后 MedBullets op4 仍从 35.2% 到 38.7%。训练不使用人工标注题。
- **单篇小结**：这是对 MedRSI「发现快 / 注册慢」最可搬的非眼科版——**自生成知识不得立刻进稳定库**。眼科若用自进化补指南问答或检查理解，应先设持久知识准入带和「不得检索本步自己的产物」，而不是把每一轮反思写进生产 RAG。局限必须写清：评的是开放题准确率，不是门诊轨迹；网页搜索本身就是污染面。

### 12. MedPrune / MedicalHarness / OA-MAP / PsyCIDRA：剪拓扑、评 harness、人在环、问诊双 Agent

- **日期 / 来源**：arXiv 提交 **2026-10-05～10-08**
- **链接**：https://arxiv.org/abs/2610.06695 · https://arxiv.org/abs/2610.05778 · https://github.com/REAL-Lab-NU/MedicalHarness · https://arxiv.org/abs/2610.12134 · https://arxiv.org/abs/2610.07473
- **相关度**：方法可迁移（多 Agent 通信剪枝；分数属于「模型 × harness」；膝骨关节炎多模态 Agent；精神科问诊 Agent）
- **摘要**：**MedPrune**（10/5）把会诊写成异构通信图，用强化学习剪掉无关科室节点，再按「任务分 − 拓扑复杂度」剪边。MIMIC-CXR / IU-Xray / OmniMedVQA 上平均 +3.65%，token 效率 +37.86%；对抗下平均只掉 3.1%。**MedicalHarness**（10/5）在 4 域 107 个任务上，5 个开源权重 × 5 套 harness 只改 harness；harness 及其与模型的交互大约解释 **1/4** 的结局方差，**没有一套 harness 在所有模型/任务上最好**。MH-Lab 可单独关掉上下文管理、规划或工具暴露。**OA-MAP**（10/8）为膝骨关节炎结构/疼痛进展招募 MRI / X 线 / 临床 Agent + 协调者，可按请求选工具、检索文献；不确定度触发人在环。FNIH 600 人，测试 100 人融合模型 AUROC 结构 0.80 / 疼痛 0.68。**PsyCIDRA**（10/5）把自由问诊和诊断推理拆成双 Agent：问诊侧用工作笔记、专家技能和 ICD-11；推理侧列出支持/冲突/缺失证据，证据不够就拒给终假设。101 名真人、盲法分臂：是否提出诊断假设与心理学家一致率 79.6% vs 直接提示 65.4%。
- **单篇小结**：上周体检多 Agent 证明拆 Agent 不自动更安全；本周补三句——**先剪无关科室、分数必须绑 harness、问诊 Agent 可以拒写诊断**。眼科多专科会诊（青光眼 + 视网膜 + 神经眼科）不要默认全员发言。复现 MedRSI / nAMD 分析数字时，必须固定规划器、工具暴露和上下文管理，否则「换骨干」和「换脚手架」分不清。OA-MAP 的人在环可对结构–功能不一致青光眼；PsyCIDRA 的「证据不够就弃权」可对 GAO 必问变量。

### 13. An open vision-language model for diverse medical applications（MedGemma）

- **日期 / 来源**：2026-10-06；*Nature Medicine*
- **链接**：https://doi.org/10.1038/s41591-026-04626-w · https://pubmed.ncbi.nlm.nih.gov/42839104/
- **相关度**：方法可迁移 / 基础模型（开源医学 VLM；摘要写到 **agentic evaluations +10.8%**）
- **摘要**：Google。MedGemma 基于 Gemma 3 的医学视觉–语言基础模型集合；同期发布医学调过的视觉编码器 MedSigLIP。相对同尺寸生成式模型和 Gemma 基座，保持通用能力的同时提高医学图文理解。分布外：医学图像问答 +2.6–10%，胸片发现分类 +15.5–18.1%，**agentic 评测 +10.8%**。数据少时，微调 MedGemma 比微调 Gemma 3 更有效。作者（除两名合约作者外）均为 Google/Alphabet 雇员或前雇员，可能持有股票。
- **单篇小结**：这是本周最重的开源医学骨干，但「agentic +10.8%」在摘要里没有任务表。接到眼底/OCT 工具编排时应把它当**可微调编码器 + 对话核**，不要当成已经有眼科 Agent 外部分。院内若用 MedSigLIP 换分割/分类槽，仍要按 FOCUS 四轴报外域、校准、质量门和亚组。

### 14. Real-World Effectiveness of AI-Enabled Clinical Decision Support in Primary Care

- **日期 / 来源**：2026-10-08；*Journal of Medical Internet Research*
- **链接**：https://doi.org/10.2196/98630 · https://pubmed.ncbi.nlm.nih.gov/42849036/
- **相关度**：治理 / 对照（基层真实世界 AI-CDSS；其中青光眼判别只到中等）
- **摘要**：清华长庚。PRISMA 2020，2011–2025。24 项达评，10 项是学习/病例式 AI、14 项确定性规则仅作对照。检出不一致：AI 心电图提高新发低射血分数诊断（OR 1.32），EHR 痴呆标记单独用则否（aOR 0.84）。诊断：黑色素瘤 AUROC 0.960，**青光眼 AUROC 0.80、灵敏度 65%**。非随机前后对照报 UTI 治疗成功 75%→80%，4 名全科里 3 人改了糖网筛查标准。评估患者重要结局的两项试验都未显示 AI-CDSS 获益，一项肌骨功能结局甚至偏向常规护理。GRADE 后作者结论：到 2025-12 的证据是杂的；部分研究改善检出或流程，**患者重要获益未被证明**。
- **单篇小结**：这是对「再报一张内部 AUROC」的基层版刹车。眼科筛查 Agent 进社区/全科时，必须同时报：改了没有转诊、改了没有治疗、以及患者结局——本综述里青光眼门只有 65% 灵敏度。不要把「AI 进了基层」写成已经有效。

### 15. Claude Haiku 5.5 与 GPT-6 Intelligent UI：便宜子 Agent vs 聊天界面，不是新骨干

- **日期 / 来源**：Anthropic 官方 **2026-10-07**；OpenAI 官方同日
- **链接**：https://www.anthropic.com/claude-haiku-5-5 · https://platform.claude.com/docs/en/models/haiku-5-5/overview.md · https://openai.com/index/gpt-6-for-everyone/
- **相关度**：运行时（本周平台层增量；Sonnet 5.5 / GPT-6.1 Sol / Luna / Argon 不重复展开）
- **摘要**：**Haiku 5.5** 是 Claude 5.5 家族小模型，定位高通量、低时延的分类 / 路由 / 抽取 / 子 Agent，以及浏览器使用。短提示（≤100k，官方称覆盖旧 Haiku 约 90% 请求）输入/输出 **$0.10 / $0.50**，cache read $0.01；>100k 则 $0.50 / $2.50。官方表：Terminal-Bench 4.0 **39.2%**（Haiku 4.5 为 0.0%，Sonnet 5.5 70.6%，GPT-6 Luna 16.4%），OSWorld 2.1 离线子集 72.4%，HLE 带工具 57.4%，GDPval-AA v2.1 1620。第一款带 effort 旋钮的 Haiku。同日 Sonnet 5.5 **cache read 从 $0.20 降到 $0.10**，官方称多数 agentic 任务再便宜约 20%。网络护栏严于 Haiku 4.5、宽于 Sonnet 5.5（允许更广防御任务，仍拦渗透测试）；生物学护栏与 Sonnet 5 / 5.5 / Opus 5 相同。**GPT-6 + Intelligent UI**：ChatGPT 用原生可流式组件生成按钮、表单、图表和交互界面，并可在继续思考的同时开始作答；联网题 Instant 平均早 44% 开口。付费档 10/7 用 GPT-6 Sol，Free/Go 10/8 用 GPT-6 Luna，都调成日常对话。**Work / Codex 骨干未改**。安全叙述写：在 Astra 经验上加强多轮越狱抵抗，并更清楚说出能力边界。
- **单篇小结**：眼科科研 Agent 缺的是「更便宜的抽表/子 Agent」，不是再换旗舰——Haiku 5.5 适合从视野/OCT PDF 抽字段、跑路由；复杂改脚本仍应留 Sonnet 5.5 / 6.1 Sol。Intelligent UI **不能**写成院内报告生成器：它是 Chat 体验，不是 HIS 组件，也没有眼科控件库。评测须固定「骨干 × effort × 是否 Chat 包装」。一律不得默认给 HIS/PACS 写权限。独立三方尚未同 harness 重跑 Haiku 5.5 vs Luna vs Sonnet 5.5。
