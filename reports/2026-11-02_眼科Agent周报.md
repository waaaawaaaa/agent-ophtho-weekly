### 1. Beyond Billing Codes: An Agentic Large Language Model Pipeline for Extracting Glaucoma Procedural Data from Free-Text Clinical Notes

- **日期 / 来源**：medRxiv **2026-10-30**（DOI `10.64898/2026.10.29.26366154`）。Bascom Palmer（Janet Kang / Nicholas Solages / Rafael Scherer / Felipe A. Medeiros / Swarup S. Swaminathan）+ 圣保罗联邦大学 / UCLA
- **链接**：https://doi.org/10.64898/2026.10.29.26366154 · https://www.medrxiv.org/content/10.64898/2026.10.29.26366154v1 · 代码：https://github.com/swarupswaminathan/llm_procedures（创建 / 最近推送 **2026-10-12**，本窗口无新 commit）
- **相关度**：**直接相关（本周主条目）**——青光眼病历上的三阶段 Agentic 手术史抽取；不是阅片 Agent
- **摘要**：结构化计费码盖不住青光眼真实手术负担。作者在 1,250 例 Bascom Palmer 青光眼仓库（2014–2024）上随机抽样病历，由两名青光眼专科标注、必要时第三人仲裁两槽：既往相关手术（名称 / 日期 / 细节）和拟施行手术（名称 / 细节）。10% / 10% / 80% 划分。五模型（Claude Opus 4.6、DeepSeek-V4 Pro、GPT-5.5、Grok 4.1、Qwen3.6-35B-A3B）走 Microsoft Foundry HIPAA 容器，**不微调**。流水线是抽取 → 校验 → 条件改写，再文本标准化。测试集 1,984 条标签（992 份 × 2 眼）：既往手术 1,057 眼（53.3%），拟手术 152 眼（7.7%）。检出准确率：既往 Grok 0.965–Claude **0.996**，拟手术 DeepSeek/Qwen 0.969–Claude **0.978**。阳性例精确匹配：既往 0.681–**0.890**，拟手术 0.704–**0.849**；Jaccard：既往 0.827–**0.956**，拟手术 0.734–**0.883**。金标准 1,760 条既往手术里，EHR 的青光眼相关 CPT 只抓住 **441（25.1%）**。作者把它写成可扩展的手术负担刻画，而不是自动开手术医嘱。
- **单篇小结**：这是对上周 GLLaucoMed「当前用药 / 拟变更分槽」的手术版，对象从滴眼液换成小梁切除 / 引流管 / SLT / 白内障联合。可搬的不是 Claude 的 0.996，而是两张表：**计费码不是金标准**（CPT 漏了约 3/4，外院手术 + 粒度不够），以及**拟手术必须单独报精确匹配**——阳性只有 7.7%，正是真正会改计划的地方。接到抗青光眼 / 抗 VEGF 队列入组 Agent 时，应禁止只用 CPT 当「做过哪些手术」；三阶段仍须对照单 Agent 基线（见上周 *JAMIA* 代码状态条）。GitHub 早于窗口 18 天，本周新的是可引用预印本，不是新权重。不要把「Agentic」写成已经会排台。

### 2. A clinical multimodal vision language foundation model with fine-grain explainability（EVLF-FM）

- **日期 / 来源**：2026-10-29；*Nature Medicine*。A*STAR / 新加坡眼科研究所 / Duke-NUS（Bai / Cheng / Zhou / Daniel S. W. Ting 等）
- **链接**：https://doi.org/10.1038/s41591-026-04655-5 · https://pubmed.ncbi.nlm.nih.gov/42957777/ · 预印本：https://arxiv.org/abs/2509.24231
- **相关度**：眼科相邻 / 多专科基础模型（训练与外验含 **CFP + OCT**；**不是** 工具编排或诊疗 Agent）
- **摘要**：现有医学基础模型多为单模态、推理不透明。EVLF-FM 用监督微调 + 视觉强化微调，覆盖皮肤 / 肝病 / **眼科** / 病理 / 呼吸 / 放射共 10 种模态（含眼底照相与 OCT）。开发测试 >130 万样本、18 个全球数据集；外验 13,443 例、17 个独立集。任务是诊断、VQA 和像素级视觉接地，并给出与图像证据对齐的解释（事后解释，另测忠实度）。内测诊断均准 **0.895**，压过通才 VLM 和多数专科头；OAEFD-OCT 准确率 0.990 / F1 0.977。接地九模态 Acc@0.5 **0.842**、mIoU 0.741。零样本外验：Glaucoma fundus 0.746/0.743，RetinalOCT 0.503/0.379（64-shot 提到 0.797），DRCR-OCT 0.861/0.861，DRCR-CFP 0.952/0.770，SEED 0.912/0.823。12 名医师按 S.C.O.R.E. 评推理，总分 4.25/5，**OCT 最高（4.73）**。作者写明当前准确率「尚未达到通常要求的约 90% 部署门槛」，只要静态 2D，需要前瞻验证。Ting 披露视网膜病 DL 专利及 EyRIS / aISIGHT 股权。
- **单篇小结**：位置正好接在条目 1 之后——**病历侧已经在抽手术史，影像侧本周最重的正刊仍是会解释的通才 VLM，不是会调 RETFound 的编排 Agent。** 接到「最新多模态已经可以看 OCT」的采购话术时，应要求：眼科外验分栏（青光眼眼底 / RetinalOCT 零样本并不饱和）、接地 IoU、以及有没有超过作者自己写的 90% 门槛。解释是事后生成，约三分之一的 AI 写 CoT 在训练时被丢掉——不要写成模型内部真的按那条推理。不是工具 Agent，不翻转本周口径。

### 3. Evaluating an LLM-assisted workflow for clinical documentation: A pilot randomized controlled trial on time and quality

- **日期 / 来源**：2026-10-26；*PLOS Digital Health*。京都大学眼科（Takayama / Miyake / Tsujikawa 等）。ClinicalTrials.gov NCT07187050（事后登记 2025-09-18）
- **链接**：https://doi.org/10.1371/journal.pdig.0001799 · https://pubmed.ncbi.nlm.nih.gov/42932273/
- **相关度**：眼科工作流（眼科病房的医师-在环文书 RCT；**不是** 诊疗 Agent）
- **摘要**：担心幻觉，所以「医师必须改 LLM 草稿」几乎成了默认，但这个工作流到底省不省时间、质量好不好，此前没有对照。21 名医师随机，17 人完成；6 份模拟病历，各写出院小结和转诊信。医师-在环组改 Gemini 草稿，医师-only 组按同一模板手写；未改稿的 LLM 草稿另成 LLM-only。医师-在环：小结 48 份、转诊 48 份；医师-only 各 54 份。小结创建时间有缩短趋势（β = −59.4 秒，95% CI −150.6 至 31.7，*P*=0.18），转诊信反而更长（β = +52.9 秒，−7.0 至 112.9，*P*=0.08），**两端都没过统计门**。多数专家评分域上，医师-在环优于手写；LLM-only 最快、质量最低。Fitting Cloud 付了 Gemini API 费，未参与设计/分析。
- **单篇小结**：这是给条目 1 / GLLaucoMed「三阶段会自动变好」的眼科文书刹车——**人在环不是免费的安全层**。接到出院小结 / 手术史抽取 Agent 时应同时报：哪一类文书真的省时、哪一类只是把核对时间从「写」挪到「改」。不要把「必须有医师改稿」写成已经证明又快又好。不是工具编排。

### 4. Talking Eyes、OpenEvidence 屈光题，以及 AMD OCT「诊断器 + 评分器」

- **日期 / 来源**：2026-10-31 / 10-26；*Ophthalmic Epidemiol* / *J Cataract Refract Surg*。AMD 条为 *Ophthalmol Sci* 2026 年 11 月号（电子出版 2026-08-26，仅因本周索引列入）
- **链接**：https://doi.org/10.1080/09286586.2026.2715736（PMID 42965292）· https://doi.org/10.1097/j.jcrs.0000000000002088（PMID 42929207）· https://doi.org/10.1016/j.xops.2026.101372（PMID 42935864）
- **相关度**：眼科患教 / 专科问答 / LLM-as-judge（均**非 Agent**）
- **摘要**：**Talking Eyes**（10/31）：叙事综述 31 项公开 LLM 眼科患教研究。模型能简化术语、改读写读级，但偶发误导、语境误解和西方中心偏差；提示工程 + 眼科医师改稿后更好看。**OpenEvidence vs 六模型**（10/26）：AAO BCSC 屈光手术 225 道选择题。OpenEvidence 准确率 **76%**，显著低于 ChatGPT-4o / 5、Claude、Copilot、Gemini、Grok（86.2–**92%**，Claude 最高）；用户均分 77%。全部模型 95% CI 下限仍过 60% 及格线。作者写明：这不是开放临床问答上的全局知识对照。**AMD OCT 评分器**（本周索引）：140 张 OCT（CNV 70 / 玻璃膜疣 70），6 个诊断器（GPT-4.1 / 4o / o4-mini / Gemini-2.5-Flash / GPT-5-mini / GPT-5.5）写自然语言诊断，4 个评分器按量表打准确 / 影像特征 / 鉴别 / 清晰。Gemini-2.5-Flash 与两位视网膜专科的 ICC **0.897**（专科之间 0.806），均差 0.123 分可视为等价。大样本上 GPT-5.5 诊断器均分最高（6.3/8）。
- **单篇小结**：三条分别钉三句话——患教综述不再增加新系统；**策展检索不等于会答题**（OpenEvidence 在这份屈光 MCQ 上反而最低，不要写成「医学 RAG 已经赢了」）；LLM-as-judge 可以盯诊断质量，但诊断器本身仍是通才看图，不是 RETFound 工具槽。AMD 条电子出版跨窗口，仅因本周索引列入。

### 5. Global RETFound 协议、CAICC 白内障证据图与 DAIRET 糖网分诊

- **日期 / 来源**：*Ophthalmol Sci* 11 月号（电子出版 2026-08-26，本周可见）/ 2026-10-27 / 2026-10-21（本周索引）
- **链接**：https://doi.org/10.1016/j.xops.2026.101384（PMID 42953713）· https://doi.org/10.1186/s12886-026-05483-4（PMID 42958114）· https://doi.org/10.3390/diagnostics16203422（PMID 42938261）
- **相关度**：眼科基础模型协议 / 路径证据图 / 现场分诊（都**不是** Agent）
- **摘要**：**Global RETFound**（Moorfields–UCL / 港中文 / NUS；Keane / Tham）：开放眼科 / oculomics 基础模型协议。截至 **2026-07-10**，232 名合作者、78 国；88 份资产（生成模型权重或匿名眼底）来自 39 国。两档贡献：只交微调后的生成权重，或交匿名真图。目标是补拉美 / 非洲 / 中东 / 中亚表征。**CAICC**（10/27）：白内障全路径 scoping，检索至 2025-07-20，纳入 185 项。检测 52 / 特征 50 / 个性化手术规划 27 / 智能手术 28 / 康复 24 / 患教 4。181 项可评验证成熟度：68.0% 停在内测，外验 18.2%，单中心前瞻 3.3%，多中心前瞻 **1.1%**。作者称没找到「经过临床验证的多模态术前手术复杂度模型」。**DAIRET**（意大利 Lodi，10/21 电子出版）：1,051 名糖尿病患者非散瞳眼底，AI「可疑 / 不可疑」对盲法眼科分级。任何糖网灵敏度 59.5%、特异度 81.4%；转诊级（中度及以上，n=25）灵敏度 **100%**（95% CI 86.3–100）、NPV 100%。74%「不可疑」是潜在、未实测的转诊下降。无重度 / 增殖性病例，15 名 AI 阴性未完全核实。
- **单篇小结**：Global RETFound 是资源卡不是系统，接到黄斑裂孔 / 青光眼 OCT 工具槽时可当外验池设计，不要写成已经有全球权重。CAICC 把「白内障 Agent 该补哪一格」写成手术复杂度预测——GUIDE 的 IOL 更新和 AEYE Trial 都还填不了这格。DAIRET 接上周圣保罗收容所试点：门对得上转诊级时 NPV 好看，但 n=25 且没有增殖性，不能写成已经可替现场眼科。

- **日期 / 来源**：2026-10-29；*Nature Cancer*。Mass General Brigham / Dana-Farber / Harvard（Gallifant / Bitterman 等）
- **链接**：https://doi.org/10.1038/s43018-026-01264-6 · https://pubmed.ncbi.nlm.nih.gov/42957896/
- **相关度**：**方法可迁移（本周正刊主对照）**——病历抽取 Agent 的回顾 / 前瞻 / 人在环三阶段，直接对照条目 1
- **摘要**：免疫相关不良事件影响至多 40% 用免疫检查点抑制剂的患者，识别仍靠不一致的人工读病历。作者做成 Agentic LLM，从病历抽 6 类 irAE 的有无、时间、分级、归因和确定性。回顾：当前事件宏平均 F1 **0.92**，多类严重度 0.66；自洽再加 0.14 F1；最佳配置约 **$0.02 / 份**。3 个月前瞻静默部署，二分类 F1 掉到 **0.72–0.79**。临床试验秘书的随机交叉：Agent 辅助少 **2.71 分钟**（*P*<0.001），完全匹配 OR 1.45（1.01–2.08），评分者一致度从 0.22–0.51 提到 **0.82–0.85**。
- **单篇小结**：这是给条目 1 的外推模板——**回顾 0.92 不能当上线数字**。复现青光眼手术史抽取时应固定三列：回顾 F1、静默部署 F1、人在环省时 / 一致度。拟手术槽只有 7.7% 阳性，更接近 irAE 这种稀有事件，不能只报检出准确率。不是眼科。

### 8. LabARIA 检验科多 Agent、放射科 Agentic 综述与 ClinGeX 技能基因组 Agent

- **日期 / 来源**：2026-10-28 / 本窗口索引 / arXiv **2026-10-29**
- **链接**：https://doi.org/10.1038/s44401-026-00163-3（PMID 42957762）· https://doi.org/10.1148/radiol.253226（PMID 42937535）· https://arxiv.org/abs/2610.40556
- **相关度**：方法可迁移（专科工作流编排、工具 + 反馈、技能中心 Agent；都不是眼科）
- **摘要**：**LabARIA**（Weill Cornell，10/28）：人监督的多 Agent 框架，协调检验数据、质控、流程优化和运营智能；定位是「可翻译 agentic AI 的试验场」，本身是框架文不是前瞻终点。**放射综述**（*Radiology*）：单任务 LLM 已能抽信息、写报告，但放射的多系统、多步工作流需要工具和反馈；讨论误差级联、工具调用有效性和 HIS 集成。**ClinGeX**（`2610.40556`，10/29）：105 个可执行技能，按任务检索 + 依赖感知编排做临床基因组解读。223 例时间外推：任务级与专家一致 **71.7%** vs 最强对照 45.7%。
- **单篇小结**：三条分别对应眼科的三件事——青光眼手术史 / 抗 VEGF 报表应按技能包而不是整本指南进提示（接 ClinGeX / 上周 SKILL.md）；OCT 报告槽必须有工具反馈否则会级联（接放射综述）；检验科提醒「先选数据干净、规则清楚的槽练 Agent」。全部不是眼病终点。

### 9. Disparity Laundering、M4Bench 与 OpenGray：多 Agent 不中和偏差，技能才抬推导分

- **日期 / 来源**：arXiv 2026-10-28 / 10-27 / 10-27
- **链接**：https://arxiv.org/abs/2610.38215 · https://arxiv.org/abs/2610.37459 · https://arxiv.org/abs/2610.37081
- **相关度**：方法可迁移（分诊公平性、EHR 推导技能、放疗规划决策基准）
- **摘要**：**Disparity Laundering**（10/28）：5 个模型族 × 4 种聚合拓扑，120 例 MIMIC-IV 急诊，反事实换人口学。**20 个格子没有一格抹掉偏差**——都把各 Agent 独立答案的方向保留下来，给黑人患者更急性的分诊。每个模型都有一种拓扑会放大基线差距，但哪一种因模型而异；后期修补无效。**M4Bench**（10/27）：MIMIC-IV / eICU 上 28 个临床推导任务。Docker 隔离的 Codex（GPT 5.4 Mini / 5.5）加载临床审定技能后，奖励比无技能基线高 **0.136**。**OpenGray**（10/27）：在 OpenKBP-Opt 头颈放疗集上加「已知正确答案」的规划决策题（含两条与剂量目标矛盾、一条可行对照）；评规则脚本到完整 LLM Agent，LLM 侧用了商业 Terra 和本地 Ministral 3 8B。
- **单篇小结**：接到糖网 / 青光眼社区分诊 Agent 时，应先做人口学反事实交换，再决定要不要上多 Agent——**合议会把偏差洗成共识**。M4Bench 则支持「抗 VEGF / CDISC 报表用 SKILL.md」，技能的增益必须写成对照栏。OpenGray 提醒：规划 Agent 不能只报剂量，还要报「该不该提交 / 该不该请示」。

### 10. GPT-6.1 Terra、Gemini 4 Carbon 与 Mistral Large 4 开权：本周是便宜计算机使用，不是新眼科骨干
