### 1. An autonomous multimodal AI agent for evidence-grounded ophthalmic diagnosis（AgentEYE）

- **日期 / 来源**：电子出版 2026-08-05；*Cell Reports Medicine* 2026;7(8):102969；PubMed medline 2026-08-18（PMID 42556343）；Crossref indexed 2026-08-22
- **链接**：https://doi.org/10.1016/j.xcrm.2026.102969 · https://pubmed.ncbi.nlm.nih.gov/42556343/
- **相关度**：**直接相关**（本周主条目；期刊正刊，关键词含 agentic AI / autonomous AI agents）
- **摘要**：多模态眼科诊断需要同时整合眼底照相、B 超与医学证据，但现有系统多为单任务或弱接地。AgentEYE 是一个可审计的多模态 Agent：把眼部影像路由到专用眼底 / B 超工具，检索指南与网页证据，再合成有证据支撑的报告。内部 302 例基准上，诊断正确率与完整度高于纯 LLM，也高于去掉专用影像工具的消融；与「不做检索」的消融接近，说明检索主要服务证据接地与引用可审计，而不是再抬几个点正确率。200 例、三名眼科医师盲评中，相对「LLM 自引用」基线，正确率、完整度、安全性与引用接地均更好。外部分析显示性能随分布变化。作者定位为可追溯的决策支持原型，需前瞻性多中心验证。作者 Zhao / Sun / Kang / Yu / Han / Yao / Agrawal / Ying / Grzybowski / Jin（通讯金凯，浙江大学医学院附属第二医院眼科中心）。
- **单篇小结**：这是本窗口内唯一进入正式期刊的眼科专用 Agent，也是 8/12、8/17 两份报告都漏掉的正刊。架构上对照 EyeAgent（53 工具 / 23 模态）和 `2608.07651`（质控–分类–分割–反思）：AgentEYE 补上了 **B 超工具 + 指南检索 + 引用审计**。评测应拆成「诊断正确 / 报告完整 / 安全 / 引用可核」四栏；外部分布漂移被作者自己点出，内部 302 例不能当成可上线证据。

### 2. Guideline-as-Oracle: Zero-Annotation Training of an Ophthalmic Telephone Triage Agent（v2）

- **日期 / 来源**：v1 2026-08-05 提交；**v2 2026-08-18 更新**；arXiv `cs.CL`
- **链接**：https://arxiv.org/abs/2608.04772v2 · HTML：https://arxiv.org/html/2608.04772v2
- **相关度**：**直接相关**（已报 v1 的版本更新；不改变主数字，补充可审计配方）
- **摘要**：多轮医学 Agent 的监督很难规模化：专家对话标注贵，真实通话又受隐私限制。作者提出 Guideline-as-Oracle（GAO）：把 AAO 指导编译成 **70 行操作规则表**，作为 3,000 条训练对话的**唯一实例级监督**，人工标注只用于评测。规则→对话本身是设计问题，文中整理八种构造策略（引用行定级、单事实边界对、仅元数据修复、措辞多样性、替换、证据门控、训–服对齐、标签修复），并标明各自证据地位（机制 / 空结果 / 混杂 / 仅能打包评估）。对 9B 骨干做全参 SFT 得到 **GAO-Triage**：与 201 例操作参考的一致率 **61.7%→74.1%**（精确 McNemar *p*=0.0046），急症召回 **9.5%→69.0%**；第二随机种子与另一患者模拟器上增益仍在。所测 7 个通用系统没有一个在「一致率 + 急症召回」上同时压过它，且推理不必调用前沿大模型。把标签与对话随机重配会对模型塌成恒常 Routine 预测，说明学到的是指南派生的标签赋值，而不是对话表面形式。标签修复与训练后期安全性退化的消失同时出现。作者反复强调：分数测的是**对自编政策的符合度**，不是独立临床金标准。
- **单篇小结**：这是本窗口里唯一「严格眼科 × 对话 Agent」的增量。v2 没有改写摘要数字，价值在把「指南当 Oracle」从口号写成可审计配方：评测管道自己找出过基准改写泄漏、以及用隐藏病例字段覆盖裁决的启发式；主结论都建立在关掉该启发式的 clean 比较上。对院内电话/在线分诊，可直接借鉴「规则表监督 + 护士角色 SFT + 急症召回优先」，但部署前必须补**独立多医师标注**和真实通话外部分。与上周青光眼工具编排稿形成互补：一边是无影像问询，一边是有工具的看图反思。

### 3. （对照跟踪）An Agentic AI Framework Overcomes Fundamental Limitations of Large Language Models for Glaucoma Detection from Fundus Photography

- **日期 / 来源**：2026-08-07 提交；本周**无 v2**；arXiv `cs.AI`
- **链接**：https://arxiv.org/abs/2608.07651
- **相关度**：直接相关（连续跟踪，非本周新稿）
- **摘要**：LLM 看医学影像有幻觉、准确率上限和跑间不一致。作者做了三步 agentic 流程：LLM 初判 → function calling 调用质控（QAModel、FundaQ-8）、青光眼分类（SwinV2-Tiny）、视盘/杯分割（SegFormer-B0）→ LLM 反思整合。Gemini 2.5 Flash 与 GPT-5.4 mini 在 ORIGA / RIM-ONE-v3（各 n=100）上，相对纯 LLM 准确率提升 **16–47 个百分点**，最佳配置在 RIM-ONE-v3 达到专科医师级 **88%**；纠正 GPT 过诊与 Gemini 不稳，CDR MAE 下降，一致性 κ 可至 ~0.96。
- **单篇小结**：本周无代码仓或期刊版线索。可把本周新出的轻量视盘/杯分割（条目 8）视为可替换工具，而不是另起一套端到端 VLM。

### 4. Toward Multimodal Conversational AI for Age-Related Macular Degeneration（OcularChat）

- **日期 / 来源**：2026-08-18 电子出版；*Ophthalmology Retina*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42612872/ · https://doi.org/10.1016/j.oret.2026.08.010
- **相关度**：眼科多模态对话系统（非工具编排 Agent；最接近「能聊的看图模型」）
- **摘要**：评估 AMD 专用多模态大模型 OcularChat 解读彩色眼底照相的能力。在通用 MLLM 上用 **705,850** 条模拟医患对话配对 **46,167** 张 AREDS 图像微调，再在独立的 AREDS / AREDS2 上测试。AREDS 上，晚期 AMD、色素异常、玻璃膜疣大小的正确率分别为 **95.4% / 84.9% / 67.8%**。视网膜专科医师对回答的评分高于未微调的同一骨干。作者定位为医师监督下的读图、科研标注与教学，强调前瞻性临床验证前不宜部署。
- **单篇小结**：对话微调让「看图 + 解释」成为产品形态，但仍是单模型生成，没有质控/分期/OCT 工具调用或拒答门。玻璃膜疣大小明显弱于「是否晚期 AMD」，正是该把定量工具接进 Agent 的位置。可与 EyeAgent 的工具编排、GAO 的多轮问询对照：OcularChat 补的是**患教/读图话术**，不是分诊或筛查闭环。

### 5. Evaluating large language models in specialized myopia knowledge and clinical reasoning

- **日期 / 来源**：PubMed 索引 2026-08-21（电子出版 2026-08-06）；*Frontiers in Medicine*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42625808/ · https://doi.org/10.3389/fmed.2026.1886498
- **相关度**：眼科 LLM 评测（非 Agent；对照用）
- **摘要**：近视咨询既有专科鉴别，也有防控与科普。比较 GPT-5.3 Instant、DeepSeek-V3.2、Gemini 3.1 Pro Preview、Claude Opus 4.7、Qwen3.6-Plus、Doubao-Seed-2.0-Pro。客观题独立新会话重复 3 次、不加医学增强提示；开放病例由 6 个模型与 8 名低年资医师作答，2 名高年资眼科医师评分。ChatGPT 在标准化判断、病例任务与外部选择题上最高（约 **92.3% / 85.0% / 88.0%**），DeepSeek 次之。病例场景中「核心判断」强、「首选处置」明显下滑。
- **单篇小结**：又一次证明：纯文本/提示工程在「认病」上可以很强，一到「下一步怎么处理」就掉点。这与上周高度近视 vs 高度近视合并青光眼的 MLLM 研究同构——缺的是视野、眼轴、角膜形态等外部证据，不是更长的 CoT。Agent 设计应把处置建议做成**指南/计算器工具**，而不是开放生成。

### 6. Ability of Large Language Models to Answer Patients' Questions and Generate Educational Materials for Uncommon Retinal Conditions

- **日期 / 来源**：2026-08-18；*Journal of VitreoRetinal Diseases*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42620655/ · https://doi.org/10.1177/24741264261469005
- **相关度**：眼科 LLM 患教（非 Agent）
- **摘要**：10 种少见视网膜病、50 条常见患者问题，分别喂给 ChatGPT-4o1、Gemini 2.0 Flash、Copilot。视网膜专科医师 Likert 1–5 评准确/完整，并用可读性指数。FAQ 回答年级水平约 14.6–15.7；准确分约 3.81–4.16。生成患教材料时准确分升至 4.30–4.85。按指定阅读水平改写后，年级下降 3.8–6.9 且准确率不掉。
- **单篇小结**：患教是眼科 Agent 的高频子任务，但本文仍是一次性生成。接到 GAO 式问询或 Guideline-as-Oracle 后，应先核对适应证/红旗症状再通俗化，并强制医师签发。高年级原文说明「默认输出不能直接给患者」。

### 7. Transforming Systematic Reviews: Evaluating a Fine-Tuned Large Language Model for Abstract Screening in Uveitis and Retinal Vasculitis（UveAItis）

- **日期 / 来源**：*Ophthalmology Science* 2026 年 9 月期；PubMed 本窗口出现（电子出版 2026-06-22）
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42620648/ · https://doi.org/10.1016/j.xops.2026.101296
- **相关度**：眼科领域微调 LLM（文献筛查工具，可被 Agent 调用）
- **摘要**：在注册综述（PROSPERO CRD42023489232）中，从 5533 条记录抽 1030 篇，比较葡萄膜炎专家、医学生、UveAItis（微调 GPT-4o）、基线 GPT-4o、Claude Sonnet 3.5。任务是按「是否人体 / 是否原始研究」二分类筛摘要。微调模型显著优于通用 LLM（基线 GPT-4o AUC 0.669）和医学生（AUC 0.585），共识后正确识别 65.4% 专家纳入文献（学生仅 22.3%），「需要协商」输出率 3.4%（专家 16.7%）。作者认为领域微调可达到接近专家的筛查表现。
- **单篇小结**：这是典型的**可注册工具**：输入是题录，输出是纳入/排除。眼科研究型 Agent（本周 BaT、ICD-Deepresearch 一类）缺的往往不是会聊天，而是这种窄任务、可审计的筛查器。注意电子出版早于本窗口，本周是索引可见，引用时核对版本。

### 8. Medrecord-CLIP: enhancing fundus disease diagnosis via EHR-guided vision-language pre-training

- **日期 / 来源**：PubMed 2026-08-23；*Health Information Science and Systems*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42632973/
- **相关度**：眼科多模态基础模型（非 Agent；给 Agent 提供更好的图文表征）
- **摘要**：常规眼底视觉模型绑在刚性类别标签上，忽略病历叙述。作者构建 MedRecordFundus：21,290 张彩色眼底图配对经专家整理、覆盖四类临床维度的 EHR 文本，并提出 MedRecord-CLIP：诊断引导的交叉注意力融合病史，辅以对称 Multi-Positive InfoNCE。在 RFMiD、ODIR、APTOS 2019、IDRiD 上相对 RETFound / FLAIR 等基线，多病种与 IDRiD 分级有显著提升，APTOS 与最强基线持平。
- **单篇小结**：Agent 的「看图工具」不必永远是分类头。把 EHR 叙事写进预训练，更接近门诊真实输入（主诉 + 眼底）。下一步应测：同一骨干在「纯看图 vs 看图+病历」下，工具编排 Agent 的反思是否还改判。

### 9. OptiModNet: A UNet-Transformer Hybrid with Grouped-Query and Channel Attention for Optic Disc and Cup Segmentation

- **日期 / 来源**：2026-08-19；arXiv `cs.CV`
- **链接**：https://arxiv.org/abs/2608.18516 · 代码：https://github.com/SG1947/OptiModNet
- **相关度**：眼科专用 CV 工具（可替换进青光眼 Agent 的分割槽）
- **摘要**：青光眼筛查需要稳定的视盘/杯分割，但 ViT / 扩散模型算力高。OptiModNet 在编解码多阶段插入注意力，并用多层解码监督的 Aggregated Pyramid Loss。在 REFUGE2 上声称相对现有方法提升 >2.5%，仅 **3.73 GFLOPs / 1.93M 参数**。
- **单篇小结**：`2608.07651` 用的是 SegFormer-B0。若复现青光眼 Agent，这是本周最直接的「换一个更便宜的盘沿工具」。先看跨中心与无杯盘标注数据上的 CDR 误差，再决定是否替换。

### 10. Full end-to-end diagnostic workflow automation of 3D OCT via foundation model-driven AI for retinal diseases（FOCUS）

- **日期 / 来源**：2026-08-19 正式发表；*npj Digital Medicine*
- **链接**：https://doi.org/10.1038/s41746-026-03151-x
- **相关度**：眼科 AI 对照（端到端 OCT 流水线，**不是** LLM Agent）
- **摘要**：3D OCT 临床自动化常卡在多阶段流程和「单层、单任务」模型。FOCUS 依次用 EfficientNetV2-S 做质控，再用微调视觉基础模型做异常检测与多病种分类，并以统一自适应聚合把 2D 切片预测合成患者级诊断。训练/测试 3300 人（40,672 层），外部四中心、多设备 1345 人（18,498 层）：质控 F1 99.01%，异常 97.46%，患者级诊断 94.39%；真实世界中心间 F1 90.22–95.24%。人机对比中异常检测与多病种诊断达到或超过专家。作者来自中山眼科中心、南方科技大学等。
- **单篇小结**：FOCUS 证明「质控→异常→分类」这条固定流水线在 OCT 上已经很强，但规划器是写死的。若接到 AgentEYE / EyeAgent，这些模块就是现成工具。反过来：没有 Agent 的流水线缺拒答、缺引用、缺 OCT+眼底+视野仲裁——本周医学 Agent 稿正好补这三块。

### 11. DentAgent: Evidence-Centric Multi-Agent Coordination for Multimodal Dental Reasoning

- **日期 / 来源**：2026-08-19 提交 arXiv
- **链接**：https://arxiv.org/abs/2608.18878
- **相关度**：方法可迁移（专科多模态 + 证据黑板；口腔是眼科的近邻场景）
- **摘要**：口腔评估需要同时吃领域知识、X 线、口内照与 3D 数据；直接让 VLM 生成则证据不可追溯。DentAgent 用 Orchestrator 协调 5 个专科 Agent，各自用领域工具把观察写成结构化证据记录；Evidence Blackboard 作为共享状态，跟踪覆盖、缺口与冲突，再生成回答。
- **单篇小结**：与 AgentEYE 同构——眼底 / OCT / 视野 / 病历 / 指南同样需要一块「证据黑板」，而不是把工具输出悄悄写进长 CoT。青光眼「结构–功能不一致」或近视合并青光眼最适合显式记录冲突。同日还有 **GxP-Agent**（https://arxiv.org/abs/2608.16890）：把监管步骤编成 15 节点 DAG，单次 LLM 生成 ADSL 为 0%，Claude + DAG 三次均 100% 结构匹配。眼科分诊/术前清单是已知依赖的依从性任务，规则表还要变成带校验门的有向图。

### 12. Adaptive Memory and Reflection Multi-Agent System for Medical Question Answering

- **日期 / 来源**：2026-08-19；arXiv；标注录用 IEEE SMC 2026
- **链接**：https://arxiv.org/abs/2608.19029 · 代码：https://github.com/mm-air/AMR-Agent
- **相关度**：方法可迁移（医学多智能体；非眼科）
- **摘要**：针对单 Agent + 静态检索的医学 QA，提出 AMR：专用记忆与反思反馈、按复杂度在独奏/协作/升级工作流间路由，并设共识与伦理监督模块。MedQA / MedMCQA 上优于若干基线；消融显示「分 Agent 记忆 + 反思 + 外部检索」组合最强。
- **单篇小结**：眼科分诊/随访问答常被「简单题用小模型、疑难题升级」困扰。AMR 的复杂度路由可对照 GAO 的急症召回：先判断缺信息还是缺推理，再决定是否拉第二个专科 Agent。

### 13. Multi-Agent AI System for Radiology Report Structuring and Quality Assurance with Independent Radiologist Evaluation

- **日期 / 来源**：2026-08-18；arXiv
- **链接**：https://arxiv.org/abs/2608.18072
- **相关度**：方法可迁移（影像报告多智能体 QA；流程可对到眼底/OCT 报告）
- **摘要**：本地部署多智能体，对 638 份胸腹盆 CT 报告做解剖结构化和质控：发现–印象不一致、性别–解剖冲突、危急值未记录等。标记 14.1% 报告。两名放射科医师评 45 份：69% 双方认为结构化正确，无重要信息丢失或捏造；84% QA 评为优/良。
- **单篇小结**：眼科报告（眼底、OCT、青光眼视野）同样有「所见 vs 印象」分裂和危急值漏报。可先做规则 + 本地 LLM 的双 Agent（结构化 / 对账），不必上云。

### 14. A knowledge-guided agentic framework for mitigating patient-context ambiguity in health queries

- **日期 / 来源**：2026-08-20；arXiv
- **链接**：https://arxiv.org/abs/2608.19875
- **相关度**：方法可迁移（先问清再生成；与电话分诊同构）
- **摘要**：患者提问往往短且缺关键病史。框架夹在患者与下游 LLM 之间：用任务知识图谱生成假说，找出为区分假说必须补的变量，再追问。诊断检索（1034 条掩蔽证据的症状）上，相对直接作答，Top-1 至少 +57.1 个百分点；饮食安全分类（487 条）上也全面提升。
- **单篇小结**：与 GAO「把规则变成该问的下一句」几乎是同一问题的通用版。眼科红眼/闪光/突发视力下降最怕模型在缺发病时间、单双眼、是否术后的情况下直接给处置。值得做成 GAO 规则表的自动追问层。

### 15. EVADE: Evidence-Verified Agentic Diagnosis with Escape

- **日期 / 来源**：2026-08-19；arXiv
- **链接**：https://arxiv.org/abs/2608.18833
- **相关度**：方法可迁移（医学 VLM 的拒答/一致性门；可对眼底 VQA）
- **摘要**：医学 VLM 常过自信。EVADE 不训练：不确定时定位最相关区域、放大再答，仅当全图与放大视图一致才提交，否则弃权。用视图一致性代替「让模型重读自己的文字」。在 VQA-RAD / SLAKE / PathVQA 上，是唯一同时改善校准与选择风险且保持准确率的方法，ECE 相对 zero-shot 最高降约 45%。
- **单篇小结**：青光眼/黄斑病变更吃「看对区域」。可把「盘沿裁剪 vs 全眼底」一致性做成 Agent 的 escape 门：两视图打架就转人工，而不是再写一段更长的解释。作者也承认 7B VLM 往往**定位对了也改不了答案**，增益主要来自弃权。

### 16. BaT: Towards Self-Evolving Medical Research Agent with Stage Rubrics

- **日期 / 来源**：2026-08-17；arXiv
- **链接**：https://arxiv.org/abs/2608.16211
- **相关度**：方法可迁移（医学影像研究型 Agent + 分阶段量规）
- **摘要**：医学影像工作流多阶段、数据敏感、专家轨迹稀缺。BaT（Benchmark-as-Teacher）用 Stage Bank 在策略更新环外合成训练状态，BiCuRL 按固定留出评测选下一阶段课程，用任务量规核验 rollout 并以 GRPO 更新。AutoMedBench-Lite 上 BaT-4B/9B 总体分超过 Qwen Instruct 基线一倍以上；BaT-9B Agent 总体 79.6，超过 Claude Opus 4.6 + Claude Code 的 77.5。
- **单篇小结**：若要做「自动写 OCT/眼底实验」的研究 Agent，分阶段量规比只看最终准确率更有用。也可反哺临床 Agent：质控→分割→分类→报告各设 rubric，而不是只打一个诊断分。

### 17. Foundation Agents Meet Agentic Deep Research: Evidence-Grounded Clinical Code Forecasting（ICD-Deepresearch）

- **日期 / 来源**：2026-08-17；arXiv
- **链接**：https://arxiv.org/abs/2608.17075
- **相关度**：方法可迁移（检索–证据型临床 Agent；非眼科）
- **摘要**：预测下一次就诊将记录哪些 ICD。ICD-Deepresearch 把 EHR 基础模型先验、GPT-5 直接预测、医学检索与 ICD 词典组成 DeepResearch 工作流。MIMIC-III/IV 上患者平均 precision/recall 约 24.6/35.1% 与 25.1/48.3%；医师认为其检索文档有用比例（51%、68%）高于单独 GPT-5 联网或 Medical Deep Research。
- **单篇小结**：眼科纵向病历（青光眼、AMD 注射随访）同样需要「下次可能写什么诊断/操作」。更现实的迁移是：用指南 + 本院编码表约束 Agent 的印象区，而不是开放生成诊断名。

### 18. Claude 平台：computer use / browser use / Skills API / Files API 正式 GA

- **日期 / 来源**：发布说明约 2026-08-19；官方博文 2026-08-20
- **链接**：https://claude.com/blog/computer-use-skills-api-files-api
- **相关度**：方法可迁移（通用 Agent 运行时；computer use 已可纳入 HIPAA BAA）
- **摘要**：Anthropic 将 computer use（`computer_toolset_20260801`，单回合可批处理多步动作）、新建 browser use、Skills API（`/v1/skills`）与 Files API 移出 beta。Skills 用于上传/版本化操作手册，Files 提供过期时间、更高限额与约 1 TB/组织存储。官方称早期客户任务往返次数下降、computer use 可用于 HIPAA 场景；Skills/Files 已上 Microsoft Foundry，computer/browser 工具即将登陆 Vertex AI。
- **单篇小结**：对眼科的意义不是「用 Claude 去点电子病历」，而是 **Skill = 可版本化的 AAO/本院路径**，File = 指南 PDF / 视野打印件。GAO 的 70 行规则表、EyeAgent 的 53 个工具，都可以先做成 Skill 而不是写死在提示词里。浏览器/桌面操作进生产前仍需最小权限与审计，不能默认给真实 PACS 账号。

### 19. MidTool: Mid-training Data Synthesis for Agentic Tool Use

- **日期 / 来源**：2026-08-20；arXiv
- **链接**：https://arxiv.org/abs/2608.20314 · 数据/模型：https://hf.co/collections/MidTool/midtool-release
- **相关度**：方法可迁移（工具使用中期训练；可降低眼科 tool-calling 失败率）
- **摘要**：论证通用工具使用应在 mid-training 而不是全部留给后训练。MidTool 混合网页/PDF/代码与真实 API、MCP skill、文档工作流上的合成监督。对 Qwen3-4B/8B-Base 做 MidTool-Mix 后再 SFT/RL，在 BFCL、τ²-Bench、MCP Universe 上持续优于基线。
- **单篇小结**：眼科 Agent 的失败经常是「选错工具 / 参数编错 / 不会从报告回填」。若复现 `2608.07651`，可把质控–分类–分割的成功/失败轨迹做成中期语料，而不是只在 SFT 里教 JSON。
