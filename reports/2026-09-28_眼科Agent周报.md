### 1. MedRSI: Recursive Self-Improvement for Medical Agents via Clinically Aligned Self-Evolution

- **日期 / 来源**：arXiv 提交 **2026-09-21**；`cs.AI` / 医学 Agent。牛津大学（Junde Wu / Jiayuan Zhu / Minghao Hu / Fenglin Liu）+ Stanford（Jiazhen Pan）
- **链接**：https://arxiv.org/abs/2609.24838 · 代码：https://github.com/ImprintLab/MedRSI
- **相关度**：**直接相关**（本周主条目；工具使用 / 自改进医学 Agent，公开与私有评测都以**青光眼**为主任务之一）
- **摘要**：现有医学 Agent 的能力被部署前的人工工具集锁死。递归自改进（RSI）让 Agent 从失败里发明新能力，但直接搬进医学会把不安全的更新写进后续世代。MedRSI 把诊断经验变成五步循环：诊断 → 按临床后果排序失败 → 反思缺失能力 → 用代码生成 / 工具组合 / 任务模型训练做候选工具 → 只在后续队列上持续有效才注册。推理模型与工作流固定（OpenHands v0.20 + GPT-4o `2024-08-06`），自改进只改稳定工具注册表。公开任务沿 MedAgent-Pro：REFUGE2 眼底青光眼（1,200 张，600/200/200/200）与 MITEA 超声心动图。从「无临床内容的通用 Agent」出发，20 轮后青光眼平衡准确率 **56.2%→94.1%**（95% CI 92.8–95.4；灵敏度 28.4%→92.0%，特异度 84.0%→96.2%，F1 83.2%，AUC 97.2%，严重错误 9.8%→1.5%），超过 MedAgent-Pro（发表 90.4%，作者用同一划分复跑 89.6%，配对置换 *P*=0.004）。私有多模态青光眼：两家三级中心 2018–2024，1,898 眼 / 1,236 人，同日至少具备眼底 / 盘周 RNFL OCT / 可靠 24-2 中的两项（93% 三模态齐全），患病率 38%；测试 486 眼。以完整 MedAgent-Pro 为 *H*<sub>0</sub>，12 轮后平衡准确率 **79.2%→92.1%**（F1 90.2%，AUC 96.4%），超过课题组同预算手训的融合模型 87.8%；结构–功能不一致病例 86.7% vs 晚期融合 71.4%，「盘看起来正常的早期青光眼」灵敏度 88.2% vs 继承眼底工具的 64.9%。20 轮公开任务提出 118 个候选、41 个进实验池、**只有 16 个**注册（青光眼侧含盘裁剪、杯盘分割、vCDR、ISNT 盘沿、PPA、风险预测）；视杯/盘 Dice 0.87 / 0.95，vCDR *r*=0.91。立刻注册会在 30 轮把测试分砸到 76.9%（工具膨胀到 57 个）；「通用 RSI」（均匀优先级 + 立刻注册）落到 72.7%。完整配置 30 轮仍 94.4%。每条轨迹约 212 A100 小时、19 亿推理 token。
- **单篇小结**：这是本仓库第一次出现「青光眼工具不是人写死的，而是 Agent 从失败里长出来的」。位置正好接在 `2608.07651`（人写质控/分类/分割 + 反思）和 MedAgent-Pro（指南计划 + Medical SAM Adapter）之后——那两篇证明工具定上限，这篇证明**注册表治理**定自改进会不会崩。可搬的不是 94.1% 这个绝对分，而是三张表：临床代价优先（不要把预算花在 suspect）、发现快/注册慢（三队列试验 + 注册边际）、以及「不稳定工具一旦进稳定库会污染后续轨迹」。局限必须写清：骨干仍是 GPT-4o（2024-08），公开集是 REFUGE2 而不是 ORIGA/RIM-ONE 外验；私有多模态队列未公开；标签在开发期对改进器可见，测试只在轨迹冻结后算——不是 silent trial，更不是 RCT。接到 AI-TEC / EyeAgent 时，应禁止生产 Agent 在线注册新模型；院内只允许离线沙箱发明、人签发后再进白名单。

- **链接**：https://doi.org/10.1109/JBHI.2026.3736832 · https://pubmed.ncbi.nlm.nih.gov/42771632/
- **相关度**：眼科相邻（基础模型综述；把 **LLM-based agentic systems** 写成第三类，但不是新的评测系统）
- **摘要**：综述公开多模态眼科影像数据（OCT、眼底、裂隙灯）以及自监督、视觉–语言与 **agent-based systems** 的进展。作者把眼科基础模型分成视觉基础模型、视觉–语言模型、以及基于大语言模型的 agentic 系统，讨论架构、学习策略与代表应用，并写到生成式 Agent 的幻觉、数据模态失衡、图文对齐、稳健性与工作流嵌入。结论：眼科 AI 正从任务识别走向「语义接地的临床认知与交互推理」；落地还要标准化多模态资源、可解释与事实一致性、多中心验证。

### 3. Large language models for ophthalmic examination understanding: from information extraction to clinical decision support

- **日期 / 来源**：电子出版 2026-09-11；本窗口 PubMed 可见；*Frontiers in Medicine*
- **链接**：https://doi.org/10.3389/fmed.2026.1937970 · https://pubmed.ncbi.nlm.nih.gov/42798723/
- **相关度**：眼科 LLM Mini Review（非 Agent；给「检查报告进 Agent」提供任务梯度）
- **摘要**：综合 37 篇同行评议：公开 LLM / MLLM 不经眼科特训，处理设备报告、结构化测量、眼底、OCT、视野、角膜与多模态。证据呈稳定任务梯度——结构化抽取与受限计算强于开放看图、多模态诊断或治疗计划。标准化输入、补临床上下文、收紧提示/规则会抬分，但对报告版式、预处理、提示和模型更新敏感。局限是回顾/公开集、小队列、外验少、可能污染、提示与模型访问报告不一致、以及只报技术准确率。作者主张按任务风险配护栏：抽取用结构化输出 + 确定性校验，解释要可追溯与跨设备，决策要独立核验、弃权与医师签发。
- **单篇小结**：这是 9/6 OCTCases「看图题全错」和 9/14 青光眼多模态 LLM「灰区更差」的综述版。接到 MedRSI / AgentEYE 时应把检查理解拆成三槽：OCR/抽数字、看图像素、处置——前两槽可以工具化，第三槽默认弃权。PMID 因本周索引列入；电子出版早于窗口起始日，不另计一条「新的直接相关」。

### 4. Me, my doctor and AI: a qualitative interview study on patients' requirements for trustworthy use of AI-CDSS in ophthalmology

- **日期 / 来源**：2026-09-21；*BMJ Digital Health & AI*
- **链接**：https://doi.org/10.1136/bmjdh-2026-000185 · https://pubmed.ncbi.nlm.nih.gov/42781538/
- **相关度**：眼科相邻（患者对眼科 AI-CDSS 的信任与告知要求；不是诊断 Agent）
- **摘要**：德国 2026 年 1–3 月半结构访谈，23 名眼科患者/照护者（22–84 岁）。患者大体接受眼科用 AI-CDSS，但信任条件落在三域：医师（会不会用、能不能看出错）、系统（性能与解释）、治理（透明与同意）。关键要求是医师必须能识别错误输出；医师是信任中介——部分人把「医生看着办」当成足够披露。作者强调：患者不直接操作系统，却承受医–AI 混合决策，告知与参与必须写进部署。
- **单篇小结**：AI-TEC / EyeAgent 若只报医师采用率，会漏掉患者这侧。可直接借鉴「必须告知在用 AI + 医师能纠错」两句；不要把「患者开放」写成已经可以静默跑分诊。对照上周德文 Ambient Scribe：医生要本地部署，患者要能看见谁在做决定。

### 5. TeleGlaukos: A Clinician-Led Adaptive Telemonitoring Platform for Hybrid Glaucoma Care

- **日期 / 来源**：2026-09-20（上周窗口末日，上周未收录；本周作为边缘工作流补录）；*Bioengineering*
- **链接**：https://doi.org/10.3390/bioengineering13091090 · https://pubmed.ncbi.nlm.nih.gov/42791962/
- **相关度**：眼科工作流（可配置协议引擎 + 症状分支 + 规则警报；**不是** LLM Agent）
- **摘要**：青光眼需要持续监测与依从，门诊之间不可见。TeleGlaukos 把静态症状表变成患者特异工作流：条件问题、症状触发分支、用药提醒、规则警报、双向通信。PWA + Django。临床试点 30 名青光眼患者（2025-05–2026-04）；平台共 95 个账号。记录 737 次参与会话、1,329 事件、30 条双向消息、186 份问卷；结构化监测让 2 人因疑似治疗相关不良反应被提前复诊并改治疗。22 人可用性评分平均 SUS 未在摘要写全部分项。定位为围术期/治疗期混合监测，而不是诊断。
- **单篇小结**：形态上接近「规则引擎 + 人在环」，不是工具编排。对本仓库的用处是：青光眼随访 Agent 若要上线，先写**症状分支和升级规则**，再谈 LLM。因提交日落在 9/20，不计入本周「≥1 篇直接相关」。

### 6. A multi-label deep learning system for simultaneous detection of nine fundus conditions

- **日期 / 来源**：2026-09-25；*Asia-Pacific Journal of Ophthalmology*
- **链接**：https://doi.org/10.1016/j.apjo.2026.100379 · https://pubmed.ncbi.nlm.nih.gov/42790816/
- **相关度**：眼科专用 CV（九病种眼底多标签；可替换进筛查 Agent 的分类槽）
- **摘要**：17 个异构来源 236,242 张眼底，患者级 70/10/20 划分。九个标签：DR、AMD、近视性黄斑变性、青光眼可疑、ERM、血管阻塞、屈光间质混浊、视网膜出血、以及「任何视网膜异常」。多任务 ConvNeXt，阈值在调参集用 Youden 预定。内部（N=47,229）AUROC 0.943–0.989，灵敏度 88.1–97.1%，八个病种 NPV≥98.8%。东亚体检中心外验 4,055 张：AUROC 0.894–0.983，八个病种 NPV≥95.6%（DR 99.3%，VO 99.9%，MMD 99.8%）。
- **单篇小结**：上周 VUNO 阴性筛查把阅片降到 7–17% 但 DR/AMD 灵敏度会掉。本条是「一张图出九个门」的固定算法对照。接到 Agent 时应同时暴露：病种级 NPV、外验人群、以及「青光眼只是可疑、不是视野/OCT 确诊」。不要把 0.98 AUROC 写成已经可替代专科。

### 7. Detecting Glaucoma Across Multi-ethnic Myopic and Non-Myopic Populations Using an Uncertainty-Aware Vision Transformer

- **日期 / 来源**：arXiv 提交 **2026-09-24**；多中心青光眼筛查
- **链接**：https://arxiv.org/abs/2609.29433
- **相关度**：眼科专用 CV（近视/高度近视外验 + 预测不确定度；给工具槽提供「何时弃权」）
- **摘要**：ViT-B/16 + 预测不确定度，56,483 张 CFP（近视 57.1%，高度近视 14.4%），标签用临床/影像/视野统一。16 个外验集跨三洲。内部 AUROC 98.7%（95% CI 98.2–99.1%），灵敏度 94.5%，特异度 97.3%。外验 AUROC 86.4–99.6%。高度近视内部 97.8%；北京眼研究 86.5%，台湾/泰国/韩国医院集 93.3% / 91.8% / 85.5%。探索性高度近视临床评价：只看 CFP 时准确率高于眼科医师与训练评分员（92.0% vs 70.0%，*p*=0.008），与掌握全套临床信息的青光眼专科相当。
- **单篇小结**：`2608.07651` 的分类槽是 SwinV2-Tiny、域是 ORIGA/RIM-ONE。本条说明高度近视才是外验会掉的地方，而且不确定度头可以当弃权信号。接到编排层时，高度近视 + 高不确定度应强制过 OCT/视野或转诊，不要只报内部 98.7%。

### 8. GLAM: Deep learning of longitudinal visual fields predicts glaucoma progression rate and identifies fast progressors

- **日期 / 来源**：arXiv 提交 **2026-09-24**
- **链接**：https://arxiv.org/abs/2609.29256
- **相关度**：眼科专用时序工具（Humphrey 24-2 进展；可替换进 pro 随访 Agent 的功能槽，不是 Agent）
- **摘要**：常规用 MD 对时间做最小二乘，要 6–10 次、数年才得到可靠斜率。GLAM 吃纵向 24-2 总偏差图 + 5 个临床特征，预测 MD / VFI 进展率并给偶然不确定度。华盛顿大学公开 Humphrey 集：4,276 眼（正文另写 28,943 次检查 / 3,871 人）。MD 斜率 MAE 0.139 dB/年（*R*<sup>2</sup>=0.927；相对 ridge 降 73.5%），快进展者 AUC 0.990。作者认为单靠视野深度学习可匹配多模态管线。
- **单篇小结**：MedRSI 私有任务已经把 24-2 当第三模态。本条补的是**纵向斜率**，不是单次野。接到青光眼随访 Agent 时应同时暴露：需要几次野、快进展 AUC、以及「对齐的是 UWHVF 标签、不是本院治疗决策」。摘要里的眼数/人数口径前后不完全一致，引用前对原文表。

### 9. Advancing automated phase recognition in cataract surgery through the SICS-155 challenge

- **日期 / 来源**：2026-09-08 电子出版跨窗口；本窗口 *Medical Image Analysis* 可见
- **链接**：https://doi.org/10.1016/j.media.2026.104313 · https://pubmed.ncbi.nlm.nih.gov/42777601/
- **相关度**：眼科手术视频工具（SICS 阶段识别；给术中/教学 Agent 提供工具槽，不是诊断 Agent）
- **摘要**：MICCAI 2025 SICS-155：Sankara（Bengaluru）155 段手法小切口白内障手术，均长 13:05，19 个阶段。作者按 BIAS 汇报挑战，再融合参赛技术做成术后离线 SOTA（boundary-aware FACT）：SICS-155 准确率 87.98%、edit 90.80%、segmental F1 89.56%；Cataract-101 超声乳化公开集准确率 97.61% / 93.36%（取决于划分）。下一步才是实时质量。
- **单篇小结**：上周 SurgicalRoomAgent 是语音控设备；本条是**看视频认阶段**。眼科日间手术 Agent 应把阶段识别写成只读工具，不要默认给显微镜写权限。电子出版可能早于窗口，仅因本周索引/对照列入。

### 10. Training-free OCT denoising via anatomically guided latent manipulation of a pretrained generative foundation model

- **日期 / 来源**：2026-09-20；本窗口 *Artificial Intelligence in Medicine* 可见
- **链接**：https://doi.org/10.1016/j.artmed.2026.103532 · https://pubmed.ncbi.nlm.nih.gov/42790286/
- **相关度**：眼科专用工具（冻结 VAE 先验的 OCT 去噪；可放在分割/分层前）
- **摘要**：监督去噪要成对干净图，域外会幻影。作者用冻结 VAE：Bessel-K 高斯化 + GMM 分开视网膜与背景，估计噪声潜方向，一次 encode–抑制–decode。六个公开 OCT 集上，相对最强监督对照平均 PSNR +5.6 dB、SSIM +0.32，且不重训。
- **单篇小结**：MedRSI / AgentEYE 的分割上限吃噪声。去噪应写成可选预处理工具，输出必须带「是否改了层边界」的质控，防止规划器把去噪图当成原始检查。

### 11. RetinoMamba-AnatomyQuery: Anatomy-Guided Query Learning for Efficient Vision Impairment Screening from Retinal Fundus Images

- **日期 / 来源**：2026-09-21；*Life*
- **链接**：https://doi.org/10.3390/life16091577 · https://pubmed.ncbi.nlm.nih.gov/42795440/
- **相关度**：眼科筛查 CV（正常/异常二分类；轻量工具卡）
- **摘要**：Vision Mamba 全局表征 + EfficientNet-B3 局部特征 + 解剖–病灶 query。ODIR-2019 与 BRSET 调和后 10,842 名合格患者：准确率 97.93%，召回 97.77%，特异度 98.07%，F1 97.82%；RFMiD 外验准确率 96.21%、F1 95.99%。参数 23.9M、8.3 GFLOPs。

### 12. Agentic AI in Medicine: Challenges for Responsible Development and the Case for Clinical Testing Harnesses

- **日期 / 来源**：2026-09-23；*Annals of Biomedical Engineering*
- **链接**：https://doi.org/10.1007/s10439-026-04381-6 · https://pubmed.ncbi.nlm.nih.gov/42776404/
- **相关度**：**方法可迁移（本周主对照）**——主张用临床测试 harness 评 Agent **轨迹**，而不是单次输出
- **摘要**：临床决策支持的评价方法是围着「给医师看的一个输出」建的。Agentic AI 不适合：脚手架让模型在医师看见之前检索、调工具、根据中间结果行动，风险单元从一次推断变成**一串动作**。四项挑战：多步静默错误传播、只审结论不审过程、换模型/工具后验证失效、范围扩张快于证据。作者主张临床测试 harness：边缘病例场景库、全轨迹可观测、显式升级测试、以及与执业范围挂钩的分阶段证据阈值。医学已有模拟、资质与 M&M，需要的是改编而不是发明。
- **单篇小结**：这是对 MedRSI / AI-TEC / EyeAgent 最可搬的一句——**评的是轨迹，不是最后一句诊断**。青光眼 Agent 的评测清单应加：调了哪些工具、哪一步开始错、升级有没有被触发。同窗口 *J Med Ethics*（PMID 42767824，9/21）从 techno-moral change 写医患关系会被 agentic AI 改写；血液科社论（PMID 42764575，9/21）用一项约 83% 符合肿瘤委员会、幻觉 0.3% 的前瞻 silent trial，把约束从准确率改成可治理性。三者同周，正好是「怎么测 / 改了什么关系 / 谁来签字」。

### 13. RexDrug: Reliable Multi-Drug Combination Extraction Through Reasoning-Enhanced LLMs

- **日期 / 来源**：2026-09-24；*IEEE Journal of Biomedical and Health Informatics*
- **链接**：https://doi.org/10.1109/JBHI.2026.3737505 · https://pubmed.ncbi.nlm.nih.gov/42784491/ · 代码：https://github.com/DUTIR-BioNLP/RexDrug
- **相关度**：方法可迁移（多 Agent 生成推理轨迹 + RL；可对青光眼/抗 VEGF 联合用药抽取）
- **摘要**：现有关系抽取停在二元相互作用，撑不住变长 n 元方案。RexDrug 两阶段：多 Agent 协作自动生成高质量推理轨迹做 SFT，再用为联合用药定制的多维奖励做 RL。DrugComb 上 n 元抽取优于现有 SOTA；DDI13 上二元相互作用可泛化。代码已公开。
- **单篇小结**：9/14 GraphRAG 药疗图是「图遍历 + 出处」；本条是「把 n 元方案从文献里抽出来」。眼科日间注射/滴眼液联合用药可以先做抽取槽，再接到禁忌边。不要让模型「读完整份病历再猜方案」。

### 14. Claude Opus 5.5 与 GPT-6 Sol / Luna：同日旗舰与中低档

- **日期 / 来源**：Anthropic 官方 2026-09-22；OpenAI API / 开发者公告同日约 90 分钟后
- **链接**：https://www.anthropic.com/news/claude-opus-5-5 · https://developers.openai.com/api/docs/models/gpt-6-sol · https://developers.openai.com/api/docs/pricing
- **相关度**：运行时（本周平台层增量；Astra / Fable 5.1 / Agents API 不重复）
- **摘要**：**Opus 5.5** 是 Claude 5.5 家族首发。官方称多数工作接近 Fable 5.1，典型负载比 Opus 5 便宜约 40%；标价输入/输出 $4 / $20 per MTok，**cache read $0.20**（比 Opus 5 低 60%），输出快 30%+。官方表（max effort、生产护栏开）：Terminal-Bench 4.0 **66.4%**（Astra 57.9%，Fable 5.1 55.8%），FrontierCode v1.1 54.4%，CursorBench 4.0 57.8%，HLE with tools 67.7%，Terminal-Bench-Science 0.1 **58.7%**（Astra 仍领先，64.6%），AutomationBench 40.0%（Astra 41.4%）。生物学/网络能力按 Mythos/Fable 档护栏；生命科学须走 Verification Program。Sonnet / Haiku 5.5「未来数周」。同日 OpenAI 放 **GPT-6 Sol / Luna**：官方定位为把 Astra 的对齐与能力做到更快更便宜的档；相对 GPT-5.6 促销价 API **再降 50%**。公开价（短上下文）：Sol $2 / $10，Luna $0.10 / $0.50；长上下文翻倍。Sol 面向复杂编码与 agentic 工作流，1.05M 上下文；Luna 面向高通量抽取/摘要。媒体与社区帖复述：Sol 在 Agents' Last Exam V1 max effort 56.4%（Astra 59.3%），编码欺骗率 Sol 1.3% / Luna 2.8%（对照 GPT-5.6 Sol 10.4%）。独立三方尚未同 harness 重跑 Opus 5.5 vs Astra vs Sol。
- **单篇小结**：眼科科研 Agent（Keane 组 nAMD 分析、MedRSI 式工具发明）缺的是「更便宜的长程 cache + 中档日常」；电话分诊缺的仍是规则表工具，不是再换旗舰。评测须固定「骨干 × effort × 护栏是否介入」。Astra 继续留计算机使用与科学工作流；Sol/Luna 更适合批量抽报告、跑 R；Opus 5.5 更适合长程改分析脚本。一律不得默认给 HIS/PACS 写权限。
