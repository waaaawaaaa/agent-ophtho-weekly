# 【AI技术周报】2026-08-30（眼科×Agent 无新稿，改推前沿动态）

## 本周总结

检索窗口 **2026-08-24～2026-08-30**。在 arXiv、PubMed 与公开会议/期刊索引中，**未见新的「眼科 × Agent / Agentic / multi-agent / tool-using LLM agent」直接相关投稿、版本更新或正式发表**。连续跟踪的青光眼眼底 Agentic 框架（`2608.07651`，8/7）、眼科电话分诊 Agent（`2608.04772v2`，8/18）与 AgentEYE（*Cell Reports Medicine*，上周主条目）本周均无增量。MICCAI 2026 *Agentic AI for Medicine* Workshop 官网仍未公布录用名单；EyeAgent RCT（NCT07401459）仍为 Not yet recruiting。

按既定规则，本周改为 **AI / Agent / 多模态医疗** 简报。结构分四层：

1. **眼科相邻（非 Agent）**：本周期刊侧最密的是「纯 LLM/MLLM 评测」——*Retina* 上四家通用 MLLM 读 800 张眼底图（ChatGPT-4o 正确率 75%，其余 14–18%）；青光眼手术方案生成在复杂病例上安全风险上升；KLEx 屈光手术指南对齐较好但可读性极差。arXiv 侧则是可被 Agent 调用的工具：AMD/DME OCT 病灶分割、含眼底的医学 VLM 校准基准 MVC-Bench、环形血管可解释分类、OCT 反事实编辑的身份保持。
2. **方法可迁移的医学 Agent**：EviDx / CDEG / MediSkill-Evo 把诊断写成「主动取证 + 过程约束」；LUCAID 给出病理 Agent 的前瞻性临床对照（可操作决策一致率 93.0% vs 五位胸病理专家 68.3–81.1%）；STRIVE 把纵向影像报告拆成可核验的多智能体。
3. **治理与委托**：*Irish Journal of Medical Science* 把 Agent 从「预测」改写成「委托」，并指出单一 Agent 在院内会制造**相关失败**（同一错误过程被放大）；*npj Digital Medicine* 评论 Quicker 式指南 Agent 缺可核证据包与校准弃权。
4. **运行时**：Claude in Chrome 正式 GA（8/26），可在浏览器里自动执行动作并由安全分类器预审；Google Co-Scientist 给出真实实验室闭环与 HealthBench 上的推理时架构发现。

启示与前几周同构，但被本周眼科 LLM 评测写死了：**通用 MLLM 看眼底仍然远弱于专用 CV 工具，复杂手术/处置不能交给开放生成**；医学 Agent 本周的进展集中在「证据状态机 + 过程义务 + 人口级监督」，正好补上周 AgentEYE「专用工具定上限、检索定审计」之后缺的**何时停、何时升级、如何防止同一幻觉被复制到全院**。上周已覆盖的 AgentEYE、GAO-Triage v2、Claude Skills/Files GA、Gemini 3.7 Flash 不再重复展开。

### 1. Diagnostic Accuracy of Multimodal Large Language Models in Retinal Fundus Photography

- **日期 / 来源**：2026-08-25；*Retina*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42640646/ · https://doi.org/10.1097/IAE.0000000000004986
- **相关度**：眼科多模态 LLM（非 Agent；本周最接近「通用模型直接看眼底」的对照）
- **摘要**：任务专用 CNN 仍是眼科影像 AI 主流，通用多模态大模型读眼底的诊断能力缺少系统比较。作者从 8 个病种各抽 100 张彩色眼底图（共 800 张），用统一提示分别喂给 ChatGPT-4o、Claude 3.5 Sonnet、Gemini 1.5 与 Grok-2，要求自由文本诊断、1–10 自信分与论证类型。ChatGPT 总体正确率 **75%（603/800）**，远高于 Claude / Grok（各 18%）和 Gemini（14%）。仅 ChatGPT 的论证类型与对错有关联，且自信–正确率呈弱正相关（r=0.19，*p*<0.001）；模型间一致性很低（与 ChatGPT 的 κ 仅 0.11–0.16，其余两两约 0.05）。作者认为 ChatGPT 相对最强，但临床部署前仍需 refinement、验证与流程整合。
- **单篇小结**：这是本周对「纯 VLM 看眼底」最硬的否定对照。75% 看起来不低，但另外三家掉到随机附近，且跨模型几乎不重合——同一张图换骨干就会改判。对照 `2608.07651` / AgentEYE：专用质控–分类–分割工具才是诊断上限，LLM 只适合做路由和报告。自信校准差也直接接到本周 MVC-Bench。

### 2. Evaluation of Large Language Model-Generated Recommendations in Glaucoma Surgical Decision-Making

- **日期 / 来源**：2026-08-29；*Seminars in Ophthalmology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42667272/ · https://doi.org/10.1080/08820538.2026.2725223
- **相关度**：眼科 LLM 处置建议（非 Agent；对照「下一步怎么做」）
- **摘要**：把三级医院真实病历改写成标准化情景，分「原发性」与「复杂」青光眼，要求 ChatGPT、Copilot、Gemini 各给**一个**术式并陈述理由。青光眼专科医师盲评适当性、理由质量、特异性、指南符合、可行性与安全风险（0–100）。总体中位分接近（80.7 / 80.7 / 82.7，*p*=0.367），但复杂度显著伤模型：Gemini 在复杂病例上适当性与理由质量下降，**安全风险显著升高**（*p*=0.009）；ChatGPT 与 Copilot 更稳，但复杂组理由质量仍显著差于原发组。作者结论：简单原发病例可作辅助参考，高风险/复杂手术规划不能当自主决策者。
- **单篇小结**：与 8/17 近视 LLM 评测、8/23 近视专科评测同一失败模式——「认病」过得去，「选术式」就掉安全。Agent 设计应把手术决策做成**指南/适应证计算器 + 红旗门**，而不是开放生成一个术式名。复杂病例上升的安全风险，正好是本周「委托/相关失败」评论要管的对象。

### 3. Assessing Guideline Knowledge Alignment of Large Language Models in Ophthalmology: A Preclinical Benchmarking Study on KLEx Evidence-Based Guidelines

- **日期 / 来源**：电子出版 2026-08-29；*Journal of Ophthalmology*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42668902/ · https://doi.org/10.1155/joph/4163980
- **相关度**：眼科指南对齐评测（非 Agent；给 Guideline-as-Oracle 提供屈光手术对照）
- **摘要**：以国际角膜屈光透镜取出（KLEx）指南的 38 条循证推荐为金标准，默认配置评 GPT-5.5 Instant 与 DeepSeek-V4。两名眼科医师用 5 分 Likert 评安全与医学准确性；再用 ICC 量推荐强度与指南的一致，DISCERN 量结构可靠性，FRE/FKGL 量可读性。Likert 接近（4.96 vs 4.89，*p*=0.134）；114 次独立生成中，与指南推荐强度的 ICC 分别为 **0.884** 与 **0.739**。DISCERN 不显著；FRE 仅 9.93 / 3.74，FKGL 16.07 / 18.95，即输出是专家级难读文本。作者定位为术前临床参考工具，不能替代专科判断。
- **单篇小结**：指南对齐可以很高，同时完全不适合直接给患者。GAO-Triage 把 AAO 规则编成 70 行表再 SFT，比「把整本指南丢进聊天框」更可审计。若做屈光术前问询 Agent，应先对规则表、再强制降年级，并保留医师签发。

### 4. Evaluating large language model clinical reasoning in glaucoma using retrieval-augmented generation

- **日期 / 来源**：电子出版 2026-05-26；*Advances in Ophthalmology Practice and Research* 2026 年 8–9 月期；**本窗口 PubMed 索引**
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42666552/ · https://doi.org/10.1016/j.aopr.2026.05.003
- **相关度**：眼科 RAG（非工具编排 Agent；本周索引可见）
- **摘要**：40 例真实青光眼情景（原发、继发、术后、终末期），比较 GPT / Gemini / Grok 在有无 RAG 下的医学准确性、要点覆盖、逻辑完整性，另做独立安全审计；对照 4 名执业眼科医师书面回答，2 名掩蔽青光眼专科医师打分。配对 RAG 全面优于非 RAG，复合优势对三家骨干均显著（GPT 均差 0.119，Gemini 0.095，Grok 0.110）。评分者一致性有限，作者强调需共识裁决，且安全是单独审计层、不进加权总分。结论支持 RAG 作为**有监督**决策支持，不支持独立临床使用。
- **单篇小结**：电子出版早于本窗口，本周是索引可见。数字方向与 AgentEYE 消融相反：那里检索主要换来引用可审计而不是再抬正确率，这里 RAG 抬了情景推理分。差异可能来自任务——本文是文本病例推理，AgentEYE 是看图诊断。对青光眼 Agent：影像工具定诊断，RAG 定「下一步处置是否写得出处」。

- **链接**：https://pubmed.ncbi.nlm.nih.gov/42640898/ · https://doi.org/10.1371/journal.pdig.0001347
- **相关度**：眼科 AI 文献计量（对照用；标出 Agent 仍未进入主曲线）
- **摘要**：系统检索 2015–2025 年 WoS / Scopus / PubMed 眼科 AI 原创论文 12,911 篇（LLM 辅助标引 + 人工一致性）。年发文 CAGR 39.7%（108→3061）。开发性研究占 88.3%，评价性研究仅 7.4% 且 2019 年后才出现；经典深度学习 71.8%，基础模型研究 0.6% 但 2024–2025 陡增。病种仍以 DR / 青光眼 / AMD 为主（32.9% / 17.5% / 12.6%），角膜、白内障、近视在 2019–2020 后抬头。影像模态 84.1%，眼底与 OCT 2019 后平台期，文本模态 2022 年后继续升。作者认为眼科 AI 正从窄任务看图走向评价、基础模型与多模态，轨迹可外推到一般医学 AI。

### 6. MVC-Bench: Benchmarking Calibration of Medical Vision-Language Models

- **日期 / 来源**：2026-08-27 提交 arXiv；`cs.CV`
- **链接**：https://arxiv.org/abs/2608.27004
- **相关度**：方法可迁移（医学 VLM 校准；评测轴含**眼底**）
- **摘要**：医学 VLM 评测长期只报准确率。MVC-Bench 从三轴评校准：模态/骨干/分布偏移稳健性，校准策略与提示微调有效性，提示模板与随机种子稳定性。覆盖 8 个骨干、眼底 / 病理 / 胸片，域内与域移，比较事后校准、训练期校准、零样本与 6 种提示微调；主指标准确率 + ECE，辅以 MCE / ACE，共 1638+ 次受控实验。作者提出训练期 Multi-Class Margin（MCM）正则，在 12 个域内设置中的 10 个取得最低 ECE，域移下仍有竞争力。
- **单篇小结**：条目 1 里「自信与对错几乎无关」正是 MVC-Bench 要量的东西。眼科 Agent 的 escape 门（上周 EVADE：全图 vs 盘沿裁剪不一致则弃权）需要的是**校准过的不确定度**，不是模型口头说的 1–10 分。复现青光眼工具编排时，应把 ECE / 选择风险写进工具卡，而不是只报 ORIGA 准确率。

### 7. Automated 2D and 3D Segmentation of AMD and DME Lesions in OCT

- **日期 / 来源**：2026-08-27；arXiv `cs.CV`
- **链接**：https://arxiv.org/abs/2608.27095
- **相关度**：眼科专用 CV 工具（可替换进 AMD/DME OCT Agent 的病灶槽）
- **摘要**：多数 OCT 分割只做域内验证。作者系统消融 AMD / DME 的 2D 与 3D 四条流水线，域内 Dice 0.76–0.82，体积与表面校准 r≥0.97；消融表明集成组成是最稳的增益来源，并给出「全容积 + 校准」采纳标准，避免只看切片 Dice。外推到无病灶金标准的临床队列 OLIVES，用生物标志物 AUROC、中心子野厚度相关与纵向一致性做代理指标：预测能跟踪临床标志，但弱于域内。作者定位为病灶负荷跟踪的证据，而非已验证的临床工具。
- **单篇小结**：上周 FOCUS 证明固定 OCT 流水线已经很强。这篇补的是 **AMD/DME 病灶几何 + 外推代理指标**。接到 AgentEYE / EyeAgent 时，应同时暴露 Dice、体积校准和「域外只报代理、不报病灶金标准」三行，防止规划器把分割输出当成已证实的注射指征。

### 8. Interpretable Fundus Image Classification via Ring-Based Retinal Vasculature Features

- **日期 / 来源**：2026-08-25；arXiv `cs.CV`
- **链接**：https://arxiv.org/abs/2608.24723
- **相关度**：眼科可解释 CV（可作青光眼/视网膜 Agent 的结构化证据，而非黑盒分类头）
- **摘要**：许多眼底分类依赖深度潜表示，可解释性差。作者以视盘为中心做环形血管表征，量化几何、颜色、氧合相关外观与血管–背景熵，仅用这些描述子在三个公开数据集上分类。HRF 上自动血管掩膜准确率 **91.1%**，与同设定下的 RETFound 持平。额外分析显示，预训练图像模型对拍摄尺度、眼底在视野中的位置等采集伪影更敏感。
- **单篇小结**：Agent 的「看图工具」不必永远输出一个病种 logits。环形血管描述子可以直接写进证据黑板（上周 DentAgent 的结构），供反思 Agent 引用「哪一环、哪项几何」而不是「模型认为是青光眼」。也提醒：RETFound 类基础模型可能在吃视野位置，质控工具要先裁、再分类。

### 9. When the Edit Changes the Patient: Measuring Identity Preservation in Counterfactual Retinal Images

- **日期 / 来源**：2026-08-24；arXiv `cs.CV`
- **链接**：https://arxiv.org/abs/2608.23024
- **相关度**：眼科生成模型评测（非 Agent；OCT 反事实/患教图的身份门）
- **摘要**：医学反事实生成常直接套用自然图像编辑，假设锚定源图就能保持身份；视网膜 OCT 的生物识别线索很弱，该假设很少被测。作者用裁判分类器、嵌入对齐和盲法阅片，比较源图锚定、结构化提示与成对训练三类文本条件编辑。三者图像质量与编辑成功率接近，但**身份保持差很大**：源图锚定常改掉被摄者，成对训练最好。作者要求以后同时报告身份保持、真实感与编辑成功。
- **单篇小结**：若 Agent 用「生成一张治疗后 OCT」做患教或反事实解释，必须加身份门，否则解释的是另一个人。这对纵向随访（同一患者注射前后）尤其致命。可与 STRIVE 的时间一致性验证对照：一边管报告里的变化方向，一边管像素里还是不是同一个人。

### 10. EviDx: Evidence-Aware Active Diagnosis with Scaffolded LLM Agents

- **日期 / 来源**：2026-08-25；arXiv
- **链接**：https://arxiv.org/abs/2608.24570
- **相关度**：方法可迁移（主动取证诊断 Agent；与电话分诊同构）
- **摘要**：临床诊断是主动取证：收集证据、更新鉴别、决定何时足够。现有医学 LLM 多把诊断写成静态病例→答案。EviDx 用 ℰ-Synthesis 从原始病例构造交互环境，支架组织角色化 Agent、证据工具与演化证据状态，运行时 harness 按不确定度与证据覆盖决定是否终止。三级评测金字塔分别看执行稳健、推理动态与诊断结局。实验显示诊断表现与过程稳定性提升，并暴露骨干相关的能力边界。
- **单篇小结**：这是 GAO「先问清再定级」的通用版，而且把「何时停」写成一等公民。眼科红眼/闪光/突发视力下降最怕模型在缺发病时间、单双眼、是否术后时直接给处置。可把 EviDx 的证据覆盖计数接到 GAO 规则表：必问变量没齐就禁止输出 Emergent/Urgent 以外的处置。

### 11. CDEG: Learning Decision-Critical Evidence for Long-Horizon Diagnostic Agents

- **日期 / 来源**：2026-08-24 提交，2026-08-26 v2；arXiv
- **链接**：https://arxiv.org/abs/2608.22899
- **相关度**：方法可迁移（长程诊断 Agent；学「真正改判的证据」而非整段轨迹）
- **摘要**：长程诊断里，失败往往是关键证据没问到或问到了没用上。复用历史轨迹会把噪声/偶发信息一并灌回。CDEG 对比同一病例的成功与失败轨迹，用反事实干预验证哪些证据真的改诊断，再建成诊断–证据–动作图；推理时按当前证据状态检索，引导补问或重评。多骨干、域内/OOD 上最高相对原版 Agent 准确率 **+11.5%**。
- **单篇小结**：对眼科分诊/随访，不要把整通通话当记忆，只要「改过急症定级的那几条」（如突发单眼视力下降 + 术后 + 闪光）。这比上周 AMR 的「分 Agent 记忆」更可审计：记忆条目必须能做反事实。

### 12. MediSkill-Evo: Process-Constrained Self-Evolution for Evidence-Grounded Clinical Interaction

- **日期 / 来源**：2026-08-24 提交，2026-08-25 v2；arXiv
- **链接**：https://arxiv.org/abs/2608.23397
- **相关度**：方法可迁移（临床交互 Agent 的过程义务与自演化，不微调骨干）
- **摘要**：交互临床 Agent 部分可观测，可靠护理取决于证据接地且安全的过程，而不是只报最终诊断。MediSkill-Evo 不微调骨干，把临床/过程/符号/视觉知识写入四类受校验的知识库，再用 Process-Constrained Preference Harness 把候选动作锚定到证据并优先更安全决策。300 例 MIMIC-IV FullChain、180 例硬隔离过程义务、100 例 NEJM 图像诊断：Qwen FullChain 上诊断准确率相对最强先验 Agent +7.81%，治疗意图覆盖 +70.67%，关键失败 −43.04%；可选 MedSAM 定位时 NEJM 诊断 +2.56%。
- **单篇小结**：眼科电话/在线问询最该学的是「过程义务」：红旗症状必须问、缺影像不能编 OCT 所见、急症通道不能被日常话术覆盖。知识写成带权威与范围的 Skill（上周 Claude Skills GA），比把经验写进权重更适合院内版本管理。

### 13. LUCAID: Agentic Multimodal AI for Lung Cancer Precision Pathology

- **日期 / 来源**：2026-08-24；arXiv
- **链接**：https://arxiv.org/abs/2608.23803
- **相关度**：方法可迁移（专科多模态 Agent + **前瞻性临床对照**；病理是眼科的近邻）
- **摘要**：肺癌组织诊断要整合形态、免疫组化与分子，现有 AI 多为单任务且缺前瞻验证。LUCAID 用一个整合 Agent 耦合 9 个模块，覆盖质控、肿瘤检测/分割、组织学分型、微环境、细胞密度、预测标志物（PD-L1 / MET / TROP-2）到结构化报告，并允许交互查询。模块相对大规模专家标注 F1 0.82–0.95；前瞻性临床验证中，对可操作决策与专家组裁定金标准的一致率 **93.0%**，五位有经验胸病理医师为 68.3–81.1%。
- **单篇小结**：这是本周医学 Agent 里证据等级最高的一篇——有前瞻、有专家组金标准、比的是可操作决策而不是切片 Dice。眼科对标清单：AgentEYE 仍是回顾 302 例 + 200 例盲评；EyeAgent RCT 尚未入组。LUCAID 的「模块 F1 与终局决策分栏」可直接搬到眼底/OCT Agent 的注册文件。

### 14. STRIVE: Multi-Agent Structured Temporal Reasoning with Integrated Verification for Longitudinal Radiology Report Generation

- **日期 / 来源**：2026-08-25；arXiv
- **链接**：https://arxiv.org/abs/2608.24237
- **相关度**：方法可迁移（纵向影像报告多智能体；可对到青光眼/注射随访 OCT）
- **摘要**：纵向放射报告要写当前所见和相对前片的变化。现有方法把诊断、属性、时间比较和语言生成揉进隐表示，进展状态还被当成独立标签。STRIVE 拆成诊断 / 属性 / 时间变化三个 Agent，产出显式中间证据；时间 Agent 用 Progression-Aware GRPO，方向反转罚分最高。一致性门在生成前对账，Validation Agent 再查报告是否被聚合证据支持。Longitudinal-MIMIC 上临床效力最佳，时间变化一致率（LCC）相对最强基线翻倍以上。
- **单篇小结**：青光眼 RNFL / 视野、AMD 注射前后 OCT 都是「方向反了比漏写更危险」。不要把前后两张图丢进同一个 VLM，而要：专用测量工具出数字 → 时间 Agent 只判进展方向 → 报告 Agent 只能引用已对账的数字。

### 15. AI agents in clinical medicine: delegation, supervision, and the problem of correlated failure

- **日期 / 来源**：2026-08-29；*Irish Journal of Medical Science*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42667591/ · https://doi.org/10.1007/s11845-026-04584-9
- **相关度**：方法可迁移 / 治理（把 Agent 从预测改写成委托）
- **摘要**：既往临床 AI 只给出输出、由医师行动；Agentic 系统自己把任务做完。其他行业已在铺开，医学仍多是试点，正好可以先立法再追认。作者主张核心问题从「预测准不准」变成「这件事能不能托付」，并借用毕业后医学教育的委托框架：分级自主、任务级范围、具名监督。对应关系在一点上断裂：监督同事预设错误独立、个别发生；**同一 Agent 在全院部署会复制同一个错误过程**。因此不能只靠病例级复盘，而要做质量改进式的人群级监测。
- **单篇小结**：眼科筛查一旦把青光眼 Agent 接到普查流水线，过诊偏置（`2608.07651` 里 GPT 单独看图时特异度可到 0–5%）会在一天内复制到整个人群。评测必须同时报病例级准确率和**人群级阳性率漂移**。同日 *Lancet Digital Health* 评论「Autonomous agentic AI systems in health care: friend or foe?」（PMID 42665468）可作社论对照，无结构化摘要。

### 16. Ensuring trustworthy AI assisted guideline development for clinical practice

- **日期 / 来源**：2026-08-27；*npj Digital Medicine*
- **链接**：https://pubmed.ncbi.nlm.nih.gov/42661056/ · https://doi.org/10.1038/s41746-026-03098-z
- **相关度**：方法可迁移（指南 Agent 的可信护栏；直接对照 GAO / 眼科指南更新）
- **摘要**：评述 Li 等的 Quicker：按 GRADE 工作流起草临床推荐（问题分解→检索→筛选→证据评价→写推荐），单审者系统测试中单条推荐 20–40 分钟。评论指出评价缺口，建议：可核验、标明范围的设计感知证据包；校准过的不确定弃权；针对性人工校验与模块化质量门；以及防污染、防过度依赖的治理。强调可信不等于临床信任。
- **单篇小结**：眼科指南（AAO PPP、青光眼、屈光）更新慢，Quicker 这类系统会被拿来「先出一版」。护栏清单可直接接到 GAO：规则表必须带来源行号；模型说「符合指南」时要能点开那一行；不确定就停在 Routine/转诊，而不是写成推荐强度。

### 17. Claude in Chrome 正式 GA；Cowork 内置独立浏览器

- **日期 / 来源**：官方博文 2026-08-26
- **链接**：https://claude.com/blog/claude-in-chrome-generally-available
- **相关度**：方法可迁移（通用 Agent 运行时；浏览器动作 + 提示注入防护）
- **摘要**：Claude in Chrome 对所有付费套餐正式 GA，可在浏览器中**自动执行**阅读、点击、跳转、填表，动作用户已登录会话；每步由安全分类器对照原始请求预审，不匹配则拦截。企业可限制域名。官方称在带 probe + 分类器的当前评测上，Sonnet 5 / Opus 5 攻击成功率为 0，Fable 5 为 0.3% 且均为低严重度。同日 Cowork 增加侧栏独立浏览器，不必借用用户日常 Chrome 会话。仍不支持其他 Chromium 与移动端；本地文件需桌面端。
- **单篇小结**：对眼科的意义不是「让 Claude 去点 PACS」，而是：**Skill + 域名白名单**可以先用来拉取公开指南 PDF / 厂商门户对账，且动作预审比上周 computer use GA 更接近可审计日志。生产环境仍须最小权限，不能默认给真实电子病历 cookie。提示注入没有被「GA」消灭，只是分类器把成功率压下去。

### 18. Accelerating Scientific Research with Gemini in the Real-World（Co-Scientist）

- **日期 / 来源**：2026-08-27；arXiv
- **链接**：https://arxiv.org/abs/2608.26701
- **相关度**：方法可迁移（科研多智能体闭环；含 HealthBench 上的临床向架构发现）
- **摘要**：把 Gemini 多智能体 Co-Scientist 从纸面假说推进到执行接地：材料上对接半自动 CVD，设计 MXene 前体路径并一次生长单层 MoS2 / MoSe2 / WS2；生物学上从稀疏成像预测工程大肠杆菌群体表型并与未发表湿实验吻合；计算机科学上自主发现推理时缩放架构，在 HealthBench Hard / Professional 上超过 6 个前沿模型，盲法医师评价降低潜在临床伤害。30 名领域专家、450 份双盲审稿显示可靠性模块降低幻觉与剽窃。
- **单篇小结**：对本仓库更有用的是「推理时架构被 Agent 搜出来，且用临床基准 + 医师伤害分卡住」。若做眼科研究 Agent（上周 BaT），应同样要求：代码能跑、外部分数、以及医师伤害审计，而不是只交一篇生成稿。实验室闭环本身不可直接外推到临床决策。

### 19. （对照跟踪）上周仍有效的眼科×Agent 硬核稿

- **日期 / 来源**：2026-08-05 / 08-07 / 08-18；期刊电子出版 08-05、本窗口**无新版本**
- **链接**：https://arxiv.org/abs/2608.04772 · https://arxiv.org/abs/2608.07651 · https://doi.org/10.1016/j.xcrm.2026.102969
- **相关度**：直接相关（连续跟踪，非本周新稿）
- **摘要**：GAO-Triage（`2608.04772v2`）用 AAO 规则表零对话标注训练眼科电话分诊 Agent（一致率 61.7%→74.1%，急症召回 9.5%→69.0%）。青光眼眼底 Agentic 框架（`2608.07651`）用 LLM 初判 + 质控/分类/分割 + 反思，相对纯 LLM 提升 16–47 个百分点。AgentEYE（*Cell Reports Medicine*）路由眼底/B 超工具并检索指南写可审计报告，上周已作为正刊主条目写入 8/23 周报。
- **单篇小结**：三篇本周均无代码仓、v3 或期刊勘误线索。本周新出的 OCT 病灶分割、环形血管描述子、MVC-Bench 校准，应视为可替换工具/评测卡，而不是另起一套端到端 VLM。
